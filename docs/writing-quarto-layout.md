# writing-quarto 的目录分层

技能正文只有九步。每一步一个文件，案例和渲染约定各有自己的目录；本文件只记这套分层与改法，写作规则本身不在这里。

## 目录

```text
skills/writing-quarto/
├── SKILL.md       # 入口：九步与完成判据
├── examples/  #/ 案例：每步的正反例
├── quarto/    #/ 渲染：Book 结构、元素与排错
├── scripts/   #/ 检查：内容核对脚本
└── steps/     #/ 步骤：九步的规则正文
```

## 四层各放什么

**steps/** 放规则正文，一个文件一步，文件名按 `NN-名字.md` 编号。读者沿 `SKILL.md` 的九步走进来，读当前这一步的一个文件就够。每个 step 内部固定四段：产出、通用情况、情况、正反例。写法是判断标准和判定信号；正反例句不抄进来，只写指向 `examples/` 的引用。

**examples/** 放正反例，文件名与 step 同号，一个主题一个文件。案例只在判不准时打开：每步的「正反例」节写清该开哪个文件、看哪一节。案例可以贴不佳原文和改写，规则条文不在这里复制。

**quarto/** 放 Book 结构与渲染层约定：`basics.md` 管项目结构与 front matter，`authoring.md` 管元素写法，`mermaid.md` 与 `coords.md` 管图，`terminal.md` 管命令与输出，`render.md` 管 HTML 输出、链接与排错，`refactor.md` 管全仓重构。排图、查渲染错误或做全仓重构才打开。

**scripts/** 放可机器判定的检查，正文只写调用方式与何时运行。规则能用脚本判定的不再抄进 step。

`SKILL.md` 只留入口：适用场景、两种走法、九步各一句、完成判据。不贴目录树，不复制任何一步的条文。

## 新增或移动一条规则

先判断它属于哪一步，再落到那个 step 的「通用情况」；只有一种情形才成立时落到「情况」。同一个判定在别的 step 里已经有条文，就引用它，不复制。规则要例子才讲得清时，在 step 的「正反例」节加一行引用，例子写进 `examples/` 同号文件。

只在渲染层成立的内容放 `quarto/`，写作层不回引。

## 自检

`npm run check` 跑 `scripts/checking-skill-links.mjs`：九步、案例、渲染文件与脚本齐全，每一步 H1 编号与 `SKILL.md` 的清单对齐，反引号里的路径能解析，`` `steps/…md`「节」 `` 的节名真实存在，旧目录与 `kb_id` 不再出现，README 与 docs 里的树满足标记列规则。目录树的写法只在 `steps/03-blocks.md`「情况：目录树」一处成文，列表项格式只在 `steps/07-layout.md`，别处提到时指过去。
