# 中文案例：段落组织对照

段落组织与同义复述的正反对照。
## 自然段多中心未拆

以 示例章无标题引言改稿前为对照。一段同时承担承接上一章、交付物清单、源文件位置与摘录声明四件事，第二句还用顿号串四个交付物。章引言的形态契约（`conventions/writing/chapter-structure/skeleton.md`）已改为「单段 ± 列表」：多中心时并段或改列表，禁止拆成两个散文段（拆段触发表见`conventions/writing/paragraph-shape/rules.md` 的知识文件「段落规则」）：

```text
不佳（一段四职责，顿号串四个交付物；拆成三个散文段同样违规）：
[对应工程目录](…)已经指出项目动态库的头文件位置。这一章只处理状态面板：数据项如何定位、状态如何保存、下标如何换算，以及无效访问如何拒绝。本章的代码写在头文件 state.h 和源文件 state.cpp 里。本章摘录源码服务于讲解，片段不保证与源文件逐字一致，也不等于文件内顺序。

改写（单段：承接 + 本章交付 + 源文件位置嵌在段末句；摘录声明整句删除）：
[对应工程目录](…)已经指出项目动态库的头文件位置。这一章实现可以检查坐标的状态面板读写，接口与实现分别在头文件 state.h 和源文件 state.cpp 里。
```

判定信号：一段内出现「承接 + 清单 + 位置 + 声明」四项中的两项以上；章引言用顿号串三个以上交付物；章引言出现两个散文自然段（首个 `##` 前两个非列表段落块）；「本章摘录源码服务于讲解」「片段不保证与源文件逐字一致」「不等于文件内顺序」等摘录免责句出现在读者正文。`verifying-content.py` 对免责句硬拦，`verifying-content.py` 对两个散文段引言判失败。


## 段内同义堆叠

以 示例章「用数组存放九个数据项」的块后段改稿前为对照。中心句之后连续两句都在换说法解释同一个事实（长度在编译期确定），没有引入新机制，属于段内同义堆叠；相邻的同义合并规则管跨段落，这里管同一段内部（规则见`conventions/writing/paragraph-shape/semantic-split.md` 的知识文件「段内同义堆叠禁令」）：

```text
不佳（中心句后两句换说法复述「数量不变」，第三句又突然换主题）：
数组长度写成 kCellCount：数据项有多少个，编译期就确定下来。这个数量从开局到终局不变，是示例项目规则的一部分，长度确定的 std::array 正好装下全部九个数据项。保存之后，访问每个数据项还需要把行列坐标换算成数组下标。

改写（每句一个推进：长度 → 类型；换算主题留给下一段首句承接。该改写只解决同义堆叠，分句骨架仍不合格——先决定后补依据、「由 X 完成」提前交接，对照见 `sentence-frame.md` 的「句内骨架：先依据后选择」）：
`cells_` 的长度取常量 `kCellCount`。状态面板一共九个格子，这个数量是示例项目规则的一部分，从开局到终局不变，编译期就能确定。

长度写进类型后，`std::array` 正好装下全部九个数据项。读写某个格子时，还要把行列坐标换成数组下标；换算由紧接着的 `ToFlatIndex` 完成。
```

判定信号：段内两句主语不同、谓语同义，删掉任一句主线仍闭合；中心句后连续多句解释同一个词；句间只靠「也就是说／换句话说／即」类复述连接。改写形态是「中心一句 + 至多一句机制 + 可选一句桥接」。豁免：公式「定义 — 原理 — 代入」递进；简洁边界要求动作、对象、顺序三要素不被砍成电报句；「九个数据项」这类全书固定表述按需出现不算复述；自测答案可对照题面复述一次。


## 相邻段落同义合并

以 示例章理解最小程序源码节为对照。相邻两段各自换一种说法讲同一事实（程序对外可见的结果 / 自动化检查针对的结果，都是「输出含约定文本 + 退出码 0」），合并为一段：

```text
不佳（双段两说，第二段只是换主语复述）：
这段程序被下游读取的结果只有两处：标准输出中的 Hello, World!，以及 main 返回的 0。

构建规则里的自动化检查针对这两处：输出须含约定文本，进程须以退出码 0 结束；两处同时满足才算通过。

改写（一段点名成功条件；目录节不引入冒烟测试，机制由本章已有的自动化检查表述承载）：
这段程序的成功条件只有两条：标准输出须含约定文本 Hello, World!，进程须以退出码 0 结束；自动化检查要求两条同时满足。
```

判定信号：两段删掉任意一段、主线仍闭合；第二段的主语换人（程序 → 检查），谓语与对象不变。合并后其余位置不再以第三种说法复述。


## 同一决策合并成段

换源原因、版本差异、配置路径差异属于同一决策，合并成一段；把同一对象拆成「目录如下。命令都在这里执行。」两个短句会制造停顿，直接写成一个动作句：`下面的目录是本章示例的文件清单，所有命令都在该工程根目录执行。`


## 散文伪标签冒号与多核混段

以 示例章数组存储节的块后段为对照。同一句里叠了两层问题：冒号前是「话题标签」，读感像词条；前半讲长度、后半讲容器，两个中心挤进一段（规则与拆核四步见`conventions/writing/paragraph-shape/semantic-split.md` 的知识文件「散文伪标签冒号禁令」「拆核四步」）：

```text
不佳（散文里「话题标签：解释」词条式冒号；长度与容器两个中心混在一段）：
数组长度写成 kCellCount：数据项有多少个，编译期就确定下来。这个数量从开局到终局不变，是示例项目规则的一部分，长度确定的 std::array 正好装下全部九个数据项。

改写（先长度后容器，递进用衔接承接；词条式冒号改成完整主谓句。该改写只解决词条式冒号和多核混段，分句骨架仍不合格，对照见 `sentence-frame.md` 的「句内骨架：先依据后选择」）：
`cells_` 的长度取常量 `kCellCount`。状态面板一共九个格子，这个数量是示例项目规则的一部分，从开局到终局不变，编译期就能确定。

长度写进类型后，`std::array` 正好装下全部九个数据项。
```

合法冒号只有两种场合：完整句引出紧随的列表、围栏或图（「约定如下：」）；列表项引导词之后（如 `- **坐标**：一对行列写成 (row, col)。`）。列表项、表格单元格、代码注释与终端字面量（`流程结果：甲方获胜`）不按散文判。

判定信号：散文句首或句中出现「短话题或行内代码 + 全角冒号」且冒号后不是列表/围栏/图；同一段并行推进两个互不依赖的中心；段末突然引入下一段才展开的对象且无承接词。`verifying-content.py` 对两类信号记 WARN，人工按拆核四步改写。


## 定段落：类型接线段整段删除

块后的类型接线句怎么判：块后没有新信息就整段删除。条文见`conventions/writing/sentence-craft/sentence-frame.md` 的知识文件「一次对话」。这段在定段落判为不合格：块后没有新信息，整段删除，不走拉链的三条改写。对照保留 `Move` 的导语与围栏注释，轮到谁由后文 `Game::Place` 一节承担。

**定段落（示例章 `Move` 块后，类型接线与轮到谁叠进一段）：**

```text
不佳（前两个逗号分句各自是「成员叫法 + 使用 + 某一章的类型」，后句换讲轮次；「全部信息」又被下一句的「两个不同的问题」否定）：
`Move` 的位置直接使用上一章的 `Position`，用户字段使用本节的 `Player`，一个结构体装下一次操作的全部信息。先手和后手交替操作，一次操作由当时轮到的用户提交。

改写（整段删除，不另写替身句：导语已写「一次操作要带上目标位置和操作的用户」，围栏注释已写 position 是操作的行列坐标、player 是执行操作的用户；交替操作留在 `Game::Place` 一节）：
（删除）
```

判定信号：读者复述不出这段要记住什么；删掉整段后导语与围栏仍闭合；段内另一件内容在后文小节已有专讲。
