# 第 6 步：定用词

产出：统一术语、主动语态和语气的句子。
这一步不改刚排好的句序。改完露出第二个意思，退回第 4 步重新分段。

## 通用情况

### 目标语气

中文技术工程文档的语气：陈述、可核对、主动语态。句子的三要素判法见 `steps/05-sentences.md`「简洁边界」；允许自然衔接词，不堆砌「必须 / 应当 / 予以」。

### 读者正文禁用问答式讲解

读者正文（`content/**`、README）不把类型、函数或图写成“它回答什么问题”“只回答”“回答四类问题”“回答整局走到哪一步”。这类句子把读者正文写成作者自检提纲，删掉后读者仍能拿到同样的结果。改写为返回值、判断结果或直接陈述：

- 不佳：`Board` 保存九个棋盘格子。它回答四类问题：坐标是否越界、棋盘是否已满、是否连成三个以及赢家是谁。
- 改写：`Board` 保存九个棋盘格子，写入前检查坐标；满盘、三连和赢家都从这些格子得出。
- 不佳：`GetResult` 读取 `result_`，它回答整局走到哪一步。
- 改写：`GetResult` 返回 `GameResult`，开局是 `kInProgress`，分出胜负或平局后给出对应结果。

自测固定导语“试着自己把回答完整说出来”中的“回答”指读者自己的答复，允许保留；技能步骤里的“读者要能说出什么”是自检说明，不要求改写成读者句。其余示例必须给读者能直接读到的句子，不写“读者要能说出……”。

### 绝对范围词要少用

读者正文默认不写「只 / 仅 / 唯一 / 一律 / 永远 / 一定 / 必然 / 全部 / 完全」这类把范围一次说死的词。删掉后句义不变就删；需要限定范围时，写出范围本身：尺寸、条件、文件名或入口。

- 不佳：`Board` 只保存九个棋盘格子，入口只把三个标准流交给 `RunMatch`。
- 改写：`Board` 保存九个棋盘格子，入口把三个标准流交给 `RunMatch`。
- 不佳：测试只覆盖落子成功，其余分支没有保护。
- 改写：测试覆盖落子成功；错人落子、越界和终局还没有测试。

「只读」「只写」是读写性质的固定术语，保留；`const` 成员函数首次称「只读」时，写明它不改动对象。安全、协议或验收条件确实需要排他时，写成可核对的条件（「`PlaceCell` 在目标格子非空时返回 `false`」），不靠「只」承担论证。

### 表示、保存、记录，不用「承载」

读者正文不把类型或字段写成「承载」某个值。「承载」是抽象能力或文档职责的说法，套到 `struct`、`enum`、字段上会让读者分不清它表示什么、运行时保存什么。

按对象选动词：

- 类型表达概念：`CellPosition` **表示**一对行列，`CellType` **表示**格子里的取值。
- 对象保存数据：`Board` 的 `cells_` **保存**九个 `CellType`。
- 文件或协议留下记录：快照 **记录**落子次数、当前玩家和结果。
- 名称与值对应：`kX` **对应** X 标记。

- 不佳：坐标由 `CellPosition` 承载，取值由 `CellType` 承载。
- 改写：`CellPosition` 表示一对行列，`CellType` 表示格子里的取值。
- 不佳：这份配置承载三个字段。
- 改写：这份配置保存三个字段。

### 读者正文禁无信息提问与自造关系词

读者正文不向读者发问。没有任务指向的提问（「总览图为什么不列成员？」「这条边表示什么？」）只是把作者自检提纲搬进正文，删掉后读者仍能拿到同样信息；需要读者判断的内容改写为陈述句，或放进自测。

关系用通行词：组成、调用、依赖、只读依赖、继承。不要给关系另造简称（「组成边」「依赖边」），也不要把「组成关系」写成一个新名词再解释。

- 不佳：总览图为什么不列成员？
- 改写：（删除；图注已说明总览的范围。）
- 不佳：`Game` 与 `Board` 之间的组成边表示什么？
- 改写：`Game` 持有一个 `Board` 作为组成部分。

判定信号：正文句以「为什么 / 为何 / 表示什么」收尾并带问号；出现「×边」式自造关系词；把图的取舍、成员多少写成读者需要回答的问题。

### 两轴禁例与允许写法

| 轴 | 禁止 | 允许 |
| --- | --- | --- |
| 口语讲义腔 | 动手前、咱们、搞定、别慌；开场「先弄清三件事」式讲义口 | 进入实现前先确认…；确认 / 理解 / 查看 |
| 注释状态对 | 「空着」「放着」；用「尚未 / 已」配一对状态 | 一句让人看出是没有操作，还是操作是 X 或 O（行尾定稿见注释规范的定稿表） |
| 刻板公文腔 | 必须显式、永远、应让…；堆砌禁词后的电报省略 | 写成可观察条件或后果；完整陈述句 |
| 规划元叙述 | 本章规划、落点是、类型名只是设计方向、尚未对应可运行目录 | 直接写本章要解决的问题与目录路径；实现状态用「实现并通过验收前按设计页阅读」一句收束 |
| 压缩隐喻与过短句 | 契约链、状态外壳、地基、执行纪律、无先行词的闭环、消费、CLI 打印式省略主语 | 字面可核对：写具体对象（公共定义、状态码）、可观察前置条件（规则接口稳定）、完整流程（从开局输入到正常退出的一次）与完整主谓句（终端程序打印状态面板） |
| 人称 | 正文寒暄式第二人称开场 | 正文以工程对象为主语；「你」仅用于本章回顾与自测指令 |

### 句段改写步骤

段落或句子不合格时，退回它所属的步骤改完再回来，本步不重做段落与句子：

1. 段落主题与拆段：退回第 4 步（`steps/04-paragraphs.md`「段落规则」）。
2. 中心句与一句一事：退回第 4 步（同上）。
3. 拆句、写全三要素与分句语序：退回第 5 步（`steps/05-sentences.md`「句子规则」「句内骨架」）。
4. 相邻同义合并与过渡位置：退回第 4 步（`steps/04-paragraphs.md`「段间：过渡句只在话题切换处」）。
5. 操作节取舍：退回第 3 步（`steps/03-blocks.md`「小节标题与正文对齐」）。

本步只改词与术语：先按「目标语气」的两轴判断该删还是该换，再回原句动字，不动句子骨架。

### 判定信号

- 口语信号：出现对读者的招呼（动手前、先弄清、咱们）或寒暄式开场。
- 公文信号：删去「必须 / 应当 / 予以 / 永远」后句义不变，说明这些词只承担语气；改为写出不满足时的后果。
- 元叙述信号：句子主语是「本章 / 本页 / 写作计划」，内容讲的是章节安排而非工程对象。实现状态说明全页至多出现一次。
- 破损句信号：句子缺动作、对象或顺序，读者补不全；写全三要素的判法见 `steps/05-sentences.md`「简洁边界」。

### 不同文件的语气

同一套维度在不同载体上的强制范围不同；豁免不是放行语法错误，是放行语气形态：

| 载体 | 强制范围 | 豁免 |
| --- | --- | --- |
| 读者散文（qmd、README） | 三层级全部 | 无 |
| agent 文档（.agents/**） | 句子级语法硬伤 | 压缩语气豁免见本步「不同文件的语气」；表格项、标题短语不按完整句判 |

### 七个质量维度

每个维度给可操作判定信号，命中即改写：

1. **中心明确**：判定见 `steps/04-paragraphs.md`「段落规则」（对照见 `examples/03-block-after.md`「单段混并列对象」）。
2. **简洁**：把候选词句删掉，信息不变即删——无信息修饰（「非常」「其实」「完全」「简单来说」）、同义反复、重复交代的同一事实。
3. **连贯**：段间衔接的判法见 `steps/04-paragraphs.md`「段间：过渡句只在话题切换处」；句序违背时序或因果即调整；连接词表达的关系与上下文不符即改。句间衔接遵守 given-new 与设计句骨架，判定见 `steps/05-sentences.md`。
4. **可读性**：单句 20/40 字与拆句见 `steps/05-sentences.md`「句子规则」；复合句拆成简单句或并列句；三项以上并列写成列表，不写伪连贯长句；换算豁免见 `steps/07-layout.md`「列表选择」。同档并句的长度见 `steps/05-sentences.md`「同档并句」。
5. **不拗口**：命中即重写——三重定语链；一句里连续三个「的」；名词化堆叠（「进行 X 的实现」「对 X 作出更新」）；双介词嵌套（「在…中通过…对…」）。
6. **指代明确**：「这 N 个」「它们」「其」的先行词必须唯一且紧邻；承前省略的判法见 `steps/05-sentences.md`「六个成分」。
7. **不冗余**：同一事实只讲一次与固定表述豁免的判定见 `steps/04-paragraphs.md`「段内同义堆叠禁令」（对照见 `examples/04-paragraph-cases.md`「相邻段落同义合并」）；同一对象同页统一称呼。

### 定用词：术语要稳

- 动词选用与主动语态见「目标语气」；「由 X 完成」在这一步改成主动句，改完露出第二个核就退回定段落。
- 「同一概念只使用一个称呼」的判定见「七个质量维度」；英文标识保持大小写。
- 「游戏」指作品或玩法整体，「对局」指具体一场：定义「井字棋是…游戏」用「游戏」，规则、落子与结果语境用「对局」；同一页不把两者当同义词换用（对照见 `examples/06-wording-cases.md`「游戏与对局」）。
- 项目名在同一页首次写全（如「井字棋棋盘」），后文改用对象名（「棋盘」「动态库」「对局」）；不逐段重复项目名，也不在同一页反复解释已经说过的事。
- 无信息修饰的删除判定见「七个质量维度」；禁用词以 `scripts/verifying-content.py` 词表为准。
- 压缩动词写全：`重建`、`重编`、`重跑` 这类两字词，读者可能读成「重新创建」；写「重新生成」「重新编译」「重新运行」，同一页后续也不回退到压缩词。
- 连续出现三个「的」时的改写判定见「七个质量维度」第 5 条。
- 正文提及枚举类型与成员函数时写源码完整标识符（`Result`、`Game::ApplyMove`），不设「概念简称」层；架构层名首次出现用一句可观察行为定义；讲读写路径第一句写屏幕上或调用处发生什么。下一句点名类型与函数。再下一句写边界（对照见 `examples/01-language-scope.md`「零基础可懂的读写路径与层名定义」）。
- 枚举成员的含义写在源码行尾注释里，正文不复述成释义列表或释义段；正文只写谁调用、如何验收、与邻章关系（叙事范围见 `steps/01-task.md`「叙事范围（硬边界）」）。
- C++ 概念点名按「定用词：术语要稳」的词表；读者侧禁用行见 `scripts/verifying-content.py`；语气判定与口语腔、公文腔的正向标准见「两轴禁例与允许写法」。

## 情况

### 情况：改完露出第二个意思

换词后一句话读出两件事，说明段落里混了两个对象。退回第 4 步拆段，不在第 6 步换词补救。

### 情况：术语只在项目里定

书名、读者和术语定稿写法在书的 `.agents/skills/quarto-book-project/` 里。没有项目技能就沿用本书第一次出现时的写法，不自己造同义词。

### 情况：空泛套话与编辑残留

- **空泛套话**只在不指向具体对象时才算病：「深入探讨」「至关重要」「无缝」「赋能」「全方位」删掉后读者取走的信息不变就删；确实在点名一个对象时保留并写出那个对象（「无缝接入现有构建」指不新增构建命令，就写「不新增构建命令」）。
- **同义循环换词**：同一段里「实现」「落地」「完成」轮换指同一动作，读者会以为换了东西；统一成一个词。
- **客服腔**：「如果您有任何疑问，欢迎随时联系」只留操作与结果。
- **编辑过程残留**：「下面我们来看」「综上所述」「本节将」把写作动作写进正文，删；「本节」只在确需导航时留一次。
- **工程术语不在此列**：反馈里的「闭环」、构建里的「增量」指得到具体机制就保留，别当套话删。

判定信号与对照见 `examples/06-wording-cases.md`「空泛套话与编辑残留」。
