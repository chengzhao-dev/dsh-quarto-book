# 第 2 步：定结构

产出：章内页面骨架和二级标题清单。

边界：这一步只定删留和标题，不改句子；全章重构也先停在这里。页面宽度归 `designing-theme`，图与代码的桥接归第 3 步，段落节奏归第 4 步。

## 通用情况

绝大多数章按下面的六段块序列展开；类章、能力章与着陆页的差异见「情况」。本步的规则默认按这一通用形状判断。

### 章节骨架

六段块序列是骨架的默认顺序。

### 六段块序列

```text
无标题引言 → 按独立任务划分的任务级 ## → ## 常见错误 → ## 自测问题 → ## 本章回顾
```

- 任务级 `##` 按独立读者任务和可验证结果划分；通常 2–4 个，是上限不是配额。固定收尾不计入任务数；着陆页不套用本骨架。
- 两处豁免只在确实无可写内容时成立：首章「常见错误」可只留最可能的 2–3 项；工程目录章没有可独立复现的失败症状时，可整节缺省。
- 读者沿正文依次确认：来对了地方、完成一个可验证动作、理解关键关系、确认获得的能力。各段服务一个认知结果，顺序由「读者先要知道什么」决定。
- 章际衔接：第 N 章的引言、任务节与自测只用第 1..N-1 章已建立的名字与概念；本章新术语在首次真正使用处就近落术语卡或行内括号。接不上前章已建立名字的概念，下沉回首次使用它的章，不在本章临时补课。

### 无标题引言

第一个 `##` 之前是连贯读者文，回答三问：

- 从哪来：承接上一章已成立的结果；引用其他章一律用章节标题链接，不用「第 N 章」。
- 这一章做什么：本章要解决的问题与读者将获得的能力，正面陈述；范围能并则并，不写否定式后章预告。
- 代码在哪（可选）：有主源文件时，用同段末句自然语言点名并挂全章 blob 链接，不另起「代码写在…里」。

形态：首选恰好 1 个自然段（2–4 句）；必要时 1 段 + 1 个列表，列表只放并列范围/对象，前置引导句写在同一段末。禁止两个散文段并立、单句孤儿段、结尾导航段。不放 Callout，不写后续章节内容，不用「后面的 X」引入后文才建立的结构件。

内容：60–140 个可见字符（链接只算锚文本，空白不计），超过先删下一块已经摆出来的内容，不足补「本章要解决什么」。项目可在 `checks.json` 用 `"lead_chars": [60, 140]` 覆盖。陈述范围与页面一样大：部分页只说这一部分，只有书首页可以写「这本书」。第一句写读者要做成的事，不用「本章将…」「下面介绍…」开场。

链接预算：引言只挂承接上一章的那 1 个章节链接和本章主源文件的 blob 链接；其余章节链接下沉到正文真正用到它的句子。同一段不堆多个章节链接——每个链接都是读者离开当前页的一次机会。

摘录免责句不写进读者正文，同源保证交给 `verifying-content.py`。

### 任务序列

- 每节一个可验证结果：任务结束时存在读者能自己复述的检查动作；只有「读完了解释」的内容并入相邻任务。
- 节内顺序：概念 → 最小示例 → 操作 → 验证 → 边界；先让读者看到行为，再解释规则。单次操作按「做什么 → 执行什么 → 看到什么 → 简短说明」推进。
- 任务节以该章标题里的对象为准，不把每章都写成「目录、设计、构建、测试」。
- 交付清单或边界说明不单独设 `##`，并入引言或相邻总览；连续值类型并成一个结果。
- 任务节内按「类型 → 简单函数 → 更难的函数」排列，最难的组装放在最后，满足先定义后调用：读者要读懂的行内标识符，其行为必须已在上文或紧邻声明中出现；未定义名字的调用链、节首概览与编号步骤整段删除。
- `##` 导语只用白话，不点后文才定义的函数名；有 `###` 时导语承接上文。

### 有 class 的章的任务节

有 `class` 定义的章，任务级 `##` 按下面次序排；没有下一种内容就停，不为凑数加节：

1. 类型：本章用到的值类型（枚举与结构体），一节一个可验证结果，可下分三级标题。
2. 成员变量：单独一节；读取成员的函数用三级标题。只判断下标区间的检查也用三级标题放在这一节，不单独占二级标题。类说明、构造函数与数据成员拼进同一个围栏。每个函数的声明和实现留在同一个 `###`；标题点名本节对象，不用「只读接口」这类总称。
3. 最重要的函数：这个类最重要的一个函数及配套函数。
4. 其余重要函数：还有一组就再加一节，没有就停。

没有 `class` 的章不套这个次序，按「先类型，再使用这些类型的函数」重排。

### 常见错误

服务失败后回来的读者。每个症状一个 `###`，标题后第一句写触发条件和可观察现象。

- 误用型：一段成文写原因与正确做法；两者各需完整交代时，用症状句导语加「出错的原因／正确的做法」引导词列表。
- 排查型：按定位 → 修复 → 验证三步展开。
- 入门章只保留最可能遇到的 2–3 项，不是完整 FAQ。

细则是 `quarto/terminal.md`「常见错误条目形态与三步诊断流」。

### 自测问题

服务刚跑通主线、需要确认理解的读者。每章 0–7 道；没有可观察结果就不设题。

- 题目问本章已写明的一件可观察结果（会怎样、是哪一个、从几开始）；只有正文写了原因且情景完整时才用「为什么」。
- 题干用本章已用过的词说全，只看题干就能作答；每个细节都要改变答案，答案不受细节影响时不单点某情形。
- 题干只描述一个自洽局面，不把矛盾事实写进同句。
- 一道题只问一件可观察结果，不把两个观察捆进同一题。要考拒绝，用正文已用过的规则问可观察结果，不为出题制造正文没走过的局面。
- 固定导语：「不要展开答案，试着自己把回答完整说出来，写完之后展开对照；说不出来的部分，回到对应小节对照正文。」
- 答案写在 `::: {.answer}` 内，由 `filters/answering-disclosure.lua` 渲染为默认收起的 `<details>`；首句直接回答，一到两句，不补题面之外的对比或延伸，只用本章讲过的概念。
- 答案里的文件、路径与标识符用行内代码，不挂链接；所属目录已在答案前文确立时，路径可省顶层前缀。

### 本章回顾

1–2 句段落，不用列表。

- 「你已经能 <能力>」对应本章任务节交出的结果，可复用任务节关键词；不写正文没有的抽象总称。
- 「下一章 <预告>」不写链接，直述一句；预告不引入下一章才建立的术语。
- 每个说法都要能在正文找到出处，禁止空泛能力句或只写预告；任务节变化时同步改写。

## 一章一个关键

每一章只有一个关键，标题、各级标题、导语和自然段都是它的部分或核对。关键分两类：

- 类章：头文件的主要类型是拥有数据的类。YAML `title` 用类的读者名（2–6 个汉字，不写英文类名）；章首第一句同时写出类名。二级标题是类的一部分：要用的类型、成员变量、最重要的函数、其余函数。成员函数可做三级标题，不能做章标题。没有数据成员的类同样可以是类章：不写成员节，其余按「要用的类型 → 类本身 → 对外做的事」排列。
- 能力章：没有这样的类，关键是这一章交给读者的那一件事；函数、文件和步骤都是它的部分。源文件只有一个函数且这个函数就是交付物时，关键可以是这个函数（`main` 属于这一种）。

固定收尾「常见错误」「自测问题」「本章回顾」不改名，不升成关键。

### 术语与验证策略

- 标题、导语与任务节只用读者在前文已认识的名字；本章新术语在首次真正使用处就近定义，不在标题里抢先出现。
- 每个任务节交付一个可观察结果；章末「本章回顾」只复述这些结果，不引入新承诺。项目有章节表时，关键、`title` 与二级标题同轮同步。

### 源文件与编译顺序

章的关键与头文件里声明的物理顺序冲突时，以编译要求为准：被用到的类型先声明，被依赖的类型留在使用它的类前面。叙述主次由章首与横幅承担，不由声明顺序承担。

## 标题

### 标题分层

| 层级 | 长度 | 形式 |
| --- | --- | --- |
| YAML `title` | 2–6 个汉字 | 侧栏里要找的对象：概念、数据、结果用名词；整页交付就是一个动作时才用「动词 + 宾语」 |
| `##` | 2–10 个汉字 | 这一阶段交出的对象，或读者必须动手的短任务：「限定语 + 对象」或「动词 + 具体宾语」 |
| `###` | 2–10 个汉字 | 该阶段里的一个实体或一步具体动作；「常见错误」下的症状标题可到 12 个汉字 |

- `##` 承担大任务，要让读者看出它承担本章 title 的哪部分；`###` 承担可独立执行、观察或验证的子任务；正文最多到 H3，不写 `####`。
- 只有解释或一两句结论的内容不升级为标题；`##` 含多个连续子流程或篇幅触达预算时，拆 `###`，不整块下压。
- 一个 `##` 下设 `###` 时至少两个：同级只有一个时，删去标题归回正文，或补出真正独立的同级小节。
- 标题只用读者此刻已认识的词或字面自明的词，不用正文之后才解释的术语。
- 单个类型、单个枚举或单个函数的小节不独占任务级 `##`，与相邻概念并成一组再下分 `###`。
- 标题与内容匹配：标题动词承诺的动作必须是正文实际让读者完成的动作；只要求观察的用「观察、查看、核对」，不用「走完、完成」。任务级标题不与页面 title 共用核心动词；`##` 的宾语要涵盖其下 `###` 的宾语。
- 层级不跳级；下级标题不重复上级标题的名字；标题与导语不写拗口动宾，不用实现细节当主叙事。

### 标题字数

YAML `title` 2–6 个汉字；`##` 与 `###` 2–10 个汉字，「常见错误」下的症状标题可到 12 个。按可见汉字计，英文、数字和标点不计入；part 落地页的 title 例外。

### 句式

- 二级、三级标题只用两组词：要么「限定语 + 对象」（数据项坐标、操作后的结果），要么「动词 + 具体宾语」（检查是否三连、放入一枚元素）。同一个 `##` 下的 `###` 只用其中一种。
- 任务级 `##` 在同一章内用同一种句式；类章与流程章统一收成名词短语，动作交给正文。
- 标题若是集合的数量（`八条线`、`三种类型`），先看条目能否各自成为实体；能就拆成实体标题，不能就改成承载它们的对象。标题不替读者数个数。
- 标题不用人称、劝诱和口语动词（「自己走一局」「跟我做」），不把读者写进标题。
- 标题不以时间或过程从句起头（「输入之后的回应」还原成「程序回应」），时间关系留给导语。
- 标题不用视图隐喻和英文类名：`程序全图` 改 `程序结构`，`Ai 落子` 改 `电脑落子`。
- 标题禁元叙述与空心题：不写「本节说明…」「本章规划…」，不写读不出动作对象的短语。
- 标题与导航不使用行内代码；文件名承担路径职责，中文 title 承担理解职责，两者不必逐字翻译。
- 过程节不承载回顾职责：`### 本章实现边界` 一类标题不设，边界话并入 `## 本章回顾`。
- 例外：part 落地页的 title 即 part 名，不受 2–6 汉字硬限；章节与落地页一律不写 `description`。

### 形式规则

- 不加冒号、破折号、括号补充说明；并列结构可用顿号或逗号。
- 不堆「教程」「详解」「学习」「验证：」等泛化或解释性后缀。
- 不用「看懂、读懂、弄清」类口语领会词，不预设读者的领悟结果。
- 不用「并」串联两个动作，不用把字句；两个动作各有任务节承载时择主撰写对象。
- 指示（这一步、这次）、过程动词（记下、收进、用到）、方式（用数组、先…再…）与数量词（三种、四个）不进标题，下放导语或正文。

### 定语「的」

标题里的「的」按定语与中心语的关系取舍，不默认加也不默认省：

- 加「的」：定语与中心语是两个各自成立的名词性概念，直连会长串名词堆叠或切分歧义。
- 省「的」：两者合成一个单一名称或紧密概念，加「的」反而把名称拆散。
- 判定法：拆开各说一遍，两个都是完整概念就用「的」相连；合起来才是一个名称就不用。加「的」后超字数时先改写对象词，不靠删「的」压字数。

### 命名同步

改 title 不改文件名，除非主题边界或页面职责变化；改后跑 `quarto_render_check` 看右侧目录与导航。页面 title 变化时，part 落地页的卡片标题与一句话描述同步改为新承诺。项目技能有章节表时，同轮同步表的 `title` 与 `##` 顺序；表与正文不一致按章题脱节处理。

## 纵向承诺链

定结构时逐条对照，不新开第 10 步。每条的要求都是「下一层必须兑现上一层对象」：

1. part 落地页那句引言的范围等于该部分全部章的 title 集合；根首页卡片不把项目收成其中几章。
2. 章引言里「这一章做什么」的宾语等于 title 的对象；引言行名的源文件必须是本章摘录实际来自的文件。
3. 每个任务级 `##` 的中心名词是章 title 对象的一部分；类章按「类型、成员、最重要函数、其余函数」排。
4. 每个 `###` 的中心名词能被父级 `##` 的宾语盖住，或是这一结果里的一步；恰好 2 个 `###` 时导语一句点一个，3–4 个时只写共同结果。
5. `###` 导语的宾语等于该 `###` 的对象；其下每段段首保持这个对象，换对象就换 `###` 或挪句。
6. `##` 下没有 `###` 是允许的，条件是这一节只有一个函数或一个结果；禁止补孤立 `###`。
7. 「本章回顾」里「下一章」的名字等于 `_quarto.yml` 中下一章的 title，不写链接；回顾的能力用本章 title 的对象；最后一章不写「下一章」。
8. 类章任务节顺序按上文；任务章的 `###` 顺序与构建脚本步骤顺序一致；目录章的「有几个目录」与目录树项数一致。
9. 章题一致：引言第一句、各 `##` 中心名词、回顾能力句并排看，三处对象必须与 title 相同；不同说明正文写成了另一章，先改 title 或重排任务节。

## 分层上限

### 计数口径

估算 token = 中日韩字符数 × 1.5 + 其他字符数 ÷ 4；只用于预算比较，不声称等于真实 token 数。计入正文、标题、列表、表格、Callout 与链接锚文本；不计 YAML、链接目标、代码围栏、mermaid 与可执行单元全文。任何链接只计锚文本。

### 上限表

| 层级 | 上限 |
| --- | --- |
| 整章（frontmatter 外，只含计入部分） | 5000 token |
| 无标题引言 | 400 token |
| 每个 `##` 正文（不含代码/图） | 400–1200 token；一章只有一个任务级 `##` 时 200–1200 |
| 任务级 `###` 正文 | 有代码/表/图时下限 40，没有时下限 120；上限 640 |
| 「常见错误」症状 `###` | 60–240 token，不套任务级下限 |
| 任务级 `##` 数量 | 通常不超过 4 个 |
| 每个 `##` 下 `###` 数量 | 2–7 个 |
| 普通代码块 | 20 行 |
| `{mermaid}` / `{python}` | 40 / 30 行 |
| 单个正文段落 | 70–220 token；写作舒适带 90–180。豁免下限：章引言、节导语、紧邻块的单句前导、回顾、自测固定导语、Callout 内段落 |
| `##` 节导语 | 120 token 且 ≤2 句 |
| `###` 节导语 | 80 token 且 ≤1 句 |
| 单个 `>` 引用块 | 80 token |
| 一章 Callout | 超过 8 个失败；常用 1–3 个 |

数字依据：技术写作社区实践是单节 3–5 分钟阅读（1500–3000 字）、单个功能模块 800–1200 字；按 CJK×1.5 换算，整章 5000 token 约合 3300 汉字的正文当量，是「一节一件事、一章四节左右」的自然边界。

## 执行与例外

- `verifying-content.py` 第 3 查按上表逐文件、逐节、逐代码块、逐段核对，超限即失败；调限额只改该脚本常量与本表，两处同步。
- 根 `index.qmd` 与 part 落地页（`body-classes: index-page`）只核对整章总量与代码块限额，不套标题与骨架限制。
- 接近上限不是目标：预算是上限，内容仍按第 4 步的凑字数禁令精简。
- 标题归并：两个标题讲同一件事就并成一个，下层句子跟着走，不重写。
- 全章重构：第 1–2 步只定删留和标题；发现某段要重写，记下来留给第 5–7 步。
- 判不准时打开 `examples/02-structure-shape.md`。

## 情况

- 类章按「类型 → 成员变量 → 最重要函数 → 其余函数」排任务节；没有 `class` 的章按「类型 → 使用这些类型的函数」排。
- 只有一项交付、没有可独立复现失败症状的工程章，可省「常见错误」，其余固定收尾保留。
- 着陆页与根首页不套六段骨架，只核对整章预算、标题层级与卡片承诺。
- 已有的 `.feature-grid` 内 `.landing-card` 不得删除，也不得改成普通列表；卡片数量和链接与项目章节表一致，缺了按章节表补回。
- 全章重构或跨章搬迁时，先按「章节骨架」定删留，再进入标题与句子步骤。

## 正反例

正例：章题「棋盘」→ 引言点明 3×3 棋盘 → 任务节「类型与坐标」「成员与接口」「写入与清空」「终局判定」→ 固定收尾；每个 `##` 都是「棋盘」的一部分。

反例一：章题「棋盘」，任务节却按「打开文件、修改、编译、运行」排——把读者动作当结构，偏离本章关键。反例二：标题写成「进行棋盘的初始化操作」——空动词加关系词把对象挤到末尾，读者在目录里扫不到「棋盘」。
