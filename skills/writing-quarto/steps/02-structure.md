# 第 2 步：定结构

产出：章内页面骨架和二级标题清单。
这一步只定删留和标题，不改句子；全章重构也先停在这一步。

## 通用情况

### 页面骨架

正文按下面顺序组织：

```text
无标题引言 → 任务序列（2-4 个 ##）→ ## 常见错误 → ## 自测问题 → ## 本章回顾
```

- 无标题引言写成连贯读者文（形态契约见 `steps/02-structure.md`）：首选单个自然段（承接上一章的结果，用章节标题链接；正面陈述本章要解决的问题；可选在段末用一句话点名主源文件并挂链接），必要时「一段 + 列表」；禁止两个散文自然段并立、单句孤儿段和结尾导航段，摘录免责句永不进入读者正文，不放 Callout。
- `##` 承担一个可验证阶段，数量按独立任务和依赖关系决定；2–4 个是常见预算而非标题配额，`###` 只用于有独立动作或结果的子任务。`##` 下有多于一段的主线内容时必须拆成合理的 `###`，禁止「长导语 + 大段代码 + 过短 `###`」的失衡结构。
- 章目标与回顾分工：引言或紧随引言的目标节只陈述本章可交付、可见的产物，不提前堆「属于哪章、哪章再讲」的回顾式边界；「本章做到哪、后续章接什么」只写在 `## 本章回顾`，过程中的 `### 本章实现边界` 一类过程节标题一律不设。
- 每个任务按「做什么 → 执行什么 → 看到什么 → 简短说明」推进。
- 常见错误按症状分 `###`，标题后第一句写触发条件与可观察现象，随后给原因与正确做法；误用型条目一段成文，原因与做法需要分开完整交代时用症状句导语加原因/做法引导词列表，排查型故障展开「定位 → 修复 → 验证」三步，形态分野见 `quarto/terminal.md`。入门章节只保留最可能遇到的 2-3 项。中间实现章的常见错误承接开发过程中真实出现过的报错记录。
- 自测问题用带 `.answer` 的有序问题检查本章已经写明的一件可观察结果；题面只描述自洽局面、一道题只问一件可观察结果，其余规则（含拒绝题的正例写法）见 `steps/02-structure.md`「六段块序列」；只有本章写了原因、而且情景已经说全时，才用「为什么」问句。每章按本章可验证的结果决定题数，没有这种结果时不添加，写法见 `quarto/authoring.md`。答案首句直接针对问题所问的对象作答，补充细节放在首句之后，不先岔到相邻对象（对照见 `examples/05-sentence-reference.md`）。
- 本章回顾确认读者获得的能力并说明下一章可使用的状态；句数、句式与承接正文的要求以 `steps/02-structure.md` 为准，不重复页面目录。

页面骨架的块级顺序与引言构成以 `steps/02-structure.md` 为准。篇幅以该文件的 token 预算为准，由 `scripts/verifying-content.py` 强制。

### 收尾

最后说明下一章可以继续使用什么状态。需要领域依据时查 `SKILL.md`，再读对应文件；不在本文件复制知识正文。

### 六段块序列

```text
无标题引言 → 按独立任务划分的任务级 ## → ## 常见错误 → ## 自测问题 → ## 本章回顾
```

正文首章和末章也套这个序列，全书各章的页面骨架都是它：任务级 `##` 按独立读者任务和可验证结果划分；2–4 个只是常见预算，不是必须凑足的配额。固定收尾节不计入任务数量，着陆页不套用任务级标题上限。上限用于防止页面失控，不要求把独立任务机械降为 `###`。**两处骨架豁免（用户决定）**：① 首章可以没有「常见错误」节，入门章只保留最可能遇到的 2–3 项；② 示例章（工程目录）没有可独立复现的失败症状，允许整节缺省，不必为凑骨架硬写一条。两者都只在确实无可写内容时成立，不是默认省略。

读者在正文里依次确认来对了地方、完成可验证的动作、理解关键关系并确认获得的能力。各段服务一个认知结果，顺序由「读者先要知道什么才能看懂下一步」决定。

**章际衔接（定结构检查项）**：第 N 章的引言、任务节与自测题只用第 1..N-1 章已建立的名字与概念；本章新术语在首次真正使用处就近落术语卡或行内括号；术语卡的升级判据见 `writing-quarto` 技能 `quarto/authoring.md`「Callout 升级判据」，写法见 `steps/03-blocks.md`。某概念接不上前章已建立的名字时，把它下沉回首次使用它的章建立，不在本章临时补课。

- **无标题引言**：第一个 `##` 之前，写成**连贯读者文**回答读者三问——从哪来（承接上一章已成立的结果）、这一章做什么（本章要解决的问题与读者将获得的能力，正面陈述；范围能并则并，不写否定式后章预告）、代码在哪（可选：若本章有主源文件，用**同段末句**自然语言点名并挂全章 blob 链接，不另起「代码写在…里」独立段）。第一句写出谁在什么情况下做本章这件事，类章同时写出类名；类型怎么实现放到后面的句子。不另开背景节。**形态硬限（用户决定）**：首选**恰好 1 个自然段**（通常 2–4 句）；必要时允许 **1 个自然段 + 1 个列表**（列表前引导句写在同一段末，或段落后紧跟列表；列表不算第二散文段）；**禁止**出现两个散文自然段并立，更禁止 ≥3 段、单句孤儿段、结尾导航段。列表仅用于并列范围/对象，任务细节下沉正文 `##`，不用顿号串交付物冒充散文。**摘录免责句永不写进读者正文**：「本章摘录源码服务于讲解」「片段不保证与源文件逐字一致」「不等于文件内顺序」类作者旁白一律删除（旧「示例位置句开口子」已废止），同源保证交给 `verifying-content.py`；摘录免责只保留在 技能的权威文件与检查脚本里。不放 Callout，不写后续章节内容，不用「后面的 X」式前向指称引入后续章节才建立的结构件（如「实现放在后面的编号目录里」）。引言容纳多个独立概念时**并段或改列表**，禁止拆成两个散文段；拆分判据见 `steps/04-paragraphs.md`「拆分判据」。内容量硬限：token 预算见本文件「分层上限」；范围边界能并入承接段时不成列表。承接中引用其他章节一律用章节标题链接，不用「第 N 章」；本章回顾的下一章预告不写链接，直述预告一句（页面导航已有前进按钮），两者均见 `steps/06-wording.md`。任务概览默认并入承接句，正文小节就是任务的展开；预览列表仅当任务没有对应正文小节时使用（示例章四项工作列表已按此删除）。原 front matter `description` 的定位信息并入引言承接句，信息只保留引言一处、不同义两存；章节 qmd 不写 `description`（字段出处见 basics.md）。着陆页 `index` 按 landing 规则组织，不硬套本契约。
- **任务序列**：每节一个可验证结果。判定标准是任务结束时存在一个读者能自己复述的检查动作；只有「读完了解释」的内容并入相邻任务。概念 → 最小示例 → 操作 → 验证 → 边界，先让读者看到行为再解释规则。各章的任务节以该章标题里的对象为准，不把每一章都写成「目录、设计、构建、测试」四节。设计范围以这一章能在 `src/` 里核对的源文件收束。内容量硬限：任务级 `##` 通常不超过 4 个；`##` 与 `###` 开头的承接句数见本文件「分层上限」，写完直接进入代码、命令或列表；超出即为凑字数信号，禁令见 `steps/04-paragraphs.md`「凑字数禁令」。有 `###` 子节时，二级标题（`##`）的引言须承接上文；恰好 2 个子节时一句点一个，3 个或 4 个时不再逐个点名，点名交给三级标题的句式见本文件「标题分层」，点名用读者已认识的词，不点后文才定义的类型名；一句之内禁止把两个子节对象配成「由 X 定位，并保存 Y」「分别交给」式的两组对应（对照见 `examples/05-sentence-frame.md`「拉链句」）。交付清单或纯边界说明不单独设 `##`，并入引言或相邻工程总览节；同一头文件中连续的值类型优先按一个可验证结果归并到同一任务节。任务节内的讲述顺序按「类型 → 简单函数 → 更难的函数」排列，最难的组装放在最后，并满足先定义后调用：读者要跟着读懂的行内代码标识符，其行为必须已经出现过——上一章、上文，或同一小节里紧挨着的声明和一句行为——上一章已建立的名字视为已知；未定义名字的调用链、节首概览与编号步骤整段删除。`##` 导语只用白话，不点后文才定义的函数名。章内顺序的章内顺序的依据见 `SKILL.md`「九步」的定结构一条，本文件不复述。
- **常见错误**：服务失败后回来的读者。每个症状一个 `###`，标题后第一句写触发条件和可观察现象。误用型条目一段成文写原因与正确做法；原因与做法各需一句完整交代时（如原因牵涉私有段的设计动机），用症状句导语加「出错的原因／正确的做法」引导词列表，列表可作为节导语的合法收尾，导语预算只约束症状句；排查型故障展开定位 → 修复 → 验证三步。形态分野与细则是 `writing-quarto` 技能 `quarto/terminal.md`「常见错误条目形态与三步诊断流」。入门章节只保留最可能遇到的 2-3 项，不是完整 FAQ。
- **自测问题**：服务刚跑通主线、需要确认理解的读者。每章 0-7 道题，题目问本章已经写明的一件可观察结果（会怎样、是哪一个、从几开始），没有这种结果就不设题；只有本章写了原因、而且情景已经说全时，才用「为什么」。题面用本章已经用过的词说全，不用本章未定义的概念，不问「为什么不做成另一种」；题干是合上书的一问，只看本题题干、不看答案与上一题；题干代词的判法见 `steps/05-sentences.md`「代词不能代替未写出的对象」，允许「什么」——它在要一个名字或一句文字，不是指上文没出现的东西；题面里每个细节都要改变答案，答案不受细节影响时不单点某一种情形。题面只描述一个自洽局面，每个事实都要能同时成立，禁止把互相矛盾的局面写成题干（同一句里先说轮到甲方、又说这一步的用户是 O，读者听到的是程序自相矛盾，不是一次非法调用）——「轮到谁」和「这一步的用户」若是同一个对象，只写一次。要考拒绝，用正文已经用过的那条规则问可观察结果（正例：「空状态面板开局，轮到甲方。没轮到的一方来操作时，状态面板会改变吗？」，答案首句「不会。操作的用户不是当前用户，`Place` 返回 `kRejected`，状态面板和轮次都保持原样。」）；不为了出题制造正文没走过的矛盾局面。一道题只问一件可观察结果，不把两个观察捆进同一题（如「状态面板是空的吗」与「轮到谁」并列），拆开或删去一个。固定导语「不要展开答案，试着自己把回答完整说出来，写完之后展开对照；说不出来的部分，回到对应小节对照正文。」；答案写在 `::: {.answer}` 围栏 div 内，由 `scripts/answering-disclosure.lua` 渲染为默认收起的原生 `<details>`；答案只使用本章已讲过的概念。题目同样必须能由本章正文回答：答案依据须是正文已写明的内容，正文没讲的概念不设题；若问题值得问，先在正文补上依据再设题。答案先答所问：首句直接回答题面，一到两句，不补题面之外的对比、延伸或重复题面（对照与归属由正文承载）。问答中的文件、路径与标识符指称统一用行内代码，不挂链接（`verifying-content.py` 对自测节链接记 WARN）；所属目录在答案前文已确立时，路径可省去重复的顶层前缀（如先写 `example/`，后文写 `include/state.h`）。
- **本章回顾**：服务已经成功的读者。1-2 句段落（不是 bullet 列表）：「你已经能 <能力>」中的能力必须对应本章任务节交出的结果，可复用任务节关键词，不写正文没有的抽象总称（如「按输入、输出和终局」）；「下一章 <预告>」不写链接，直述预告一句（页面导航已有前进按钮），预告不引入下一章才建立的术语。回顾的每个说法都要能在正文找到出处，禁止空泛能力句或只写预告；正文任务节变化时同步改写回顾。

### 有 class 的章的任务节

任务级正文里有 `class` 定义的章（示例项目是「状态面板」的 `Board` 与「流程」的 `Game`），任务级 `##` 按下面的次序排列，没有下一种内容就停，不为凑数加节：

1. **类型**：先讲这一章要用到的值类型（枚举与结构体），一节一个可验证结果，可下分三级标题。
2. **成员变量**：成员变量单独一节。读取这些成员的函数用三级标题。不读取成员、只判断坐标是否落在下标区间内的检查，也用三级标题放在这一节，不单独占一个二级标题。类说明、构造函数与数据成员拼进**同一个围栏**，禁止拆成类头一个、成员另一个围栏；存放方式写在第二节正文里，不单独做标题。
3. **最重要的函数**：这个类最重要的那一个函数，以及它的配套函数。
4. **其余重要函数**：除此以外还有的重要函数，有一组才再加第四节、第五节，没有就停。

没有 `class` 的章不套这个次序，按「先类型、再使用这些类型的函数」重排。每个二级标题下三级标题的个数见本文件。超过上限时合并同前缀的函数，或把最难的组装并入相邻节。

### 术语与验证策略

- 术语 callout 就近放置的写法见 `steps/03-blocks.md`；一个同位短语就能说清的（如 CTest（CMake 自带的测试运行工具））可保留行内括号。面向新人的正文不堆砌入门前置名词（walking skeleton 这类术语直接删除）。
- 页面写出的验证结论必须与证据强度匹配：命令能定位、版本能输出、程序能编译运行是不同层级，不能用弱观察替代强证明。
- 涉及阶段目录结构的章节：先给目录树，再按树顺序逐项说明（链接格式见 `quarto/render.md`）。
- 全书统一术语与替换规则见 `steps/06-wording.md`。

### 一章一个关键

每一章只有一个关键，标题、二级标题、三级标题、导语和自然段都是这个关键的部分或对它的核对。关键分两类：

- 类章：头文件的主要类型是拥有数据的类。YAML `title` 用这个类的读者名，2 到 6 个汉字，不写英文类名，不把成员函数写成章标题。章首第一句按本文件「无标题引言」写出，类章同时写出类名。二级标题是类的一部分：类要用的类型、类里的成员变量、类最重要的函数、其余重要函数。成员函数可以做三级标题，不能做章标题。没有数据成员的类同样可以是类章：不写成员节，其余仍按要用的类型、类本身、类对外做的事排列。
- 能力章：这一章没有这样的类。关键是这一章交给读者的那一件事。函数、文件和步骤是这件事的部分。源文件只有一个函数、而且这个函数就是交付物时，关键可以是这个函数。`main` 属于这一种。

固定收尾 `常见错误`、`自测问题`、`本章回顾` 不改名，不升成关键。

### 源文件与编译顺序

章的关键与头文件里声明的物理顺序冲突时，以编译要求为准：语言要求被用到的类型先声明，被依赖的类型留在使用它的类前面。头文件不把类挪到它依赖的类型之上。叙述上的主次由章首和横幅承担，不由声明的物理顺序承担。

### 标题分层

- `##` 承担大任务，且要让读者看出它承担本章 title 中的哪部分：标题应描述本页当前交付的读者结果；布局页不使用「配置并运行」作为标题，除非该页确实让读者完成并验证这些动作。
- `###` 承担 `##` 内部可独立执行、观察或验证的子任务（源码阅读、产物检查、具体故障症状）；一个 `##` 内含多个连续子流程时用 `###` 分步。
- 只有解释或一两句结论的内容不升级为标题；正文最多保留到 H3，不写 `####`。
- 每个任务级 `##` 的可验证结果判定见本文件「六段块序列」；标题写成宽泛主题时读者无法判断做到什么程度才算完。
- `##` 出现多个连续子流程、或篇幅触达 token 预算（见本文件「分层上限」）时，强制拆分为 `###` 子小节，不整块下压。
- 标题只用读者此刻已认识的词或字面自明的词，不使用正文之后才解释的术语。
- 任务级 `##` 承担一个概念组或一项可独立交付的任务：单个类型、单个枚举或单个函数的小节不独占任务级 `##`，与相邻概念并成一组再按 `###` 分步（示例章反例：`定义坐标范围`、`保存格子状态` 曾各自独立成 `##`，粒度低于任务级；现行二级标题只记在本文件的对照里）。
- 任务级 `##` 只保留读者能单独做完的一件事。只负责解释下一块代码、命令或图的，降为 `###`；短到没有独立观察步骤的，连 `###` 也不留，并进相邻正文。固定收尾「常见错误」「自测问题」「本章回顾」不合并、不降级，常见错误下面的症状继续用 `###`。
- 一个任务级 `##` 下设 `###` 时至少两个：依据阮一峰 [《中文技术文档写作风格指南》](https://github.com/ruanyf/document-style-guide) 的标题原则，二级标题是文章的主要部分，三级标题是它下面的步骤，同级标题避免只出现一个；只有 `###` 时删去其标题归回 `##` 正文，或补出真正独立的同级小节。
- `##` 导语的句数与 token 上限见本文件「分层上限」，只写这一节交出的结果，不放代码围栏；恰好 2 个 `###` 时一句点一个，3 到 7 个时不再逐个点名，点名交给三级标题（与「个数见本文件」收尾，取代旧「按顺序点名各子节对象」的概览句式）。连续值类型的任务节归并见本文件「任务序列」；一个三级标题可以只讲一个枚举、一个结构体或一个函数。紧挨着的两个值类型可以放在同一个三级标题里，各成一个短模块，示例章「操作与成败」是正例。
- 标题与内容匹配：标题动词承诺的动作必须是本节正文实际让读者完成的动作——正文只要求观察的行为用「观察、查看、核对」类动词，不用「走完、完成」类只在真实操作节成立的动词；任务级标题不与页面 title 共用核心动词（如页面 title 用「明确」后，任务节不再以「明确」开头），页面 title 已承诺的动作由正文兑现，标题换用更具体的动词；二级标题的宾语要涵盖其下三级标题的宾语，读者从标题序列能看出各节分工，不写比正文更宽或更窄的承诺。改写对照见本文件「反例与改写」。
- 层级结构遵循阮一峰 [《中文技术文档写作风格指南》](https://github.com/ruanyf/document-style-guide) 标题章：不跳级（一级标题下不直接出现三级标题）、避免孤立编号（同级标题只有一个时省略）、下级标题不重复上级标题的名字。
- 标题与导语不写拗口动宾，不用实现细节当主叙事：「得出胜负与平局」这类把两个结果硬拼成一个动宾的标题改写成交付对象（如「终局判定」）；「三连算法」是实现细节，可一句带过，不作章节 title 或 `##` 标题的主叙事（示例章反例：原 `## 得出胜负与平局` 已更名为「终局判定」，正文改说「操作后判定流程是否结束」）。

### 标题字数

标题二选一与层级约定的通用 how 见 `writing-quarto` 技能 `quarto/basics.md`；本节保留本书标题三层数字与反例。目录、侧栏和页内 TOC 需要的是对象名，不是把导语缩进标题；四家文档只取这一层：learncpp 课内小节用概念名，C++ Primer 节名是对象，cppreference 节名只留实体、不留过程，中文技术文档标题收成两组词：「限定语 + 对象」，或「动词 + 具体宾语」。

| 层级 | 长度 | 形式 |
| --- | --- | --- |
| YAML `title` | 2-6 个汉字 | 读者在侧栏里要找的对象：概念、数据、结果用名词（流程规则、数据存储、局面快照）；只有这一页的交付就是读者要执行的一个动作时，才用「动词 + 一个宾语」 |
| `##` 二级标题 | 2-10 个汉字 | 这一阶段交出的对象，或读者必须动手的一个短任务：要么「限定语 + 对象」（流程数据、数据项坐标），要么「动词 + 具体宾语」（执行脚本、输入坐标） |
| `###` 三级标题 | 2-10 个汉字 | 该阶段里的一个实体或一步具体动作，组词同二级（数据项坐标、检查是否三连）；「常见错误」下的症状标题可到 12 个汉字，以便认出故障（找不到动态库） |

- **同级同句式**：二级、三级标题只用两组词——要么「限定语 + 对象」（数据项坐标、操作后的结果），要么「动词 + 具体宾语」（检查是否三连、放入一枚元素）；同一个二级标题下的三级标题只用其中一种。不收成「格子定义」「三连」这类看不出对象的短词。
- **能单独看懂才省略**：下级不重复上级里已经说清的词；省略后在侧栏里看不懂的，保留区分词（「类型」单独不够，「流程类型」可以）。
- 汉字计数只计汉字，英文和标点不计；JSON 这类读者已认识的词可以留在症状标题里，但不靠英文把标题撑长。

### 形式规则

- 一律**不加冒号、破折号、括号补充说明**；并列结构可用顿号或逗号连接（如「区分声明、初始化与赋值」）。
- 不堆「教程」「详解」「学习」「验证：」等泛化或解释性后缀；标题让读者预先知道这一页/节要完成什么，而不是只知道宽泛主题。
- 标题不用「看懂、读懂、弄清」类口语领会词，也不预设读者的领悟结果；标题写读者要在目录里找的对象，陈述本页交付的内容（用户决定：`看懂一次完整流程` 改 `流程规则`；自动化由 `writing-quarto` 技能 `scripts/verifying-content.py` 词表承担）。
- 标题禁元叙述与抽象空心题：不写「本节说明…」「本章规划…」类讲章节安排的标题，也不写读不出动作对象的空心名词短语（「确认依赖方向」类），一律改成「动作 + 对象」或读者已认识的对象。
- title 留下读者在侧栏里要找的对象：概念、数据、结果用名词；只有这一页的交付就是读者要执行的一个动作时，才用「动词 + 一个宾语」。修饰性定语留给正文，否则「示例项目」「工程」等限定在 title 与二三级标题里连续重复（用户决定：各章 title 收尾为对象名，如流程规则、工程目录、数据存储、一次操作、构建与运行、操作策略、局面快照）。
- title 不用「并」串联两个动作、不用把字句；两个动作各有任务节承载时择主撰写对象，动作细节留给导语和任务节。
- 标题与导航不使用行内代码（`CMakeLists.txt` 这类名字不进标题；标题写「构建规则」「一键脚本」等表达）。
- 标题只用读者此刻已认识的词或字面自明的词，不使用正文之后才解释的术语（统称禁用清单见 `steps/06-wording.md`）。
- 二级、三级标题用两组词：要么「限定语 + 对象」（数据项坐标、操作后的结果），要么「动词 + 具体宾语」（检查是否三连、放入一枚元素）；同一个二级标题下的三级标题只用其中一种，数字见「标题字数」。指示（这一步、这次）、过程动词（记下、收进、用到）、方式（用数组、先…再…）、把字句与数量词（三种、四个、九个）不进标题，下放到导语或正文。组词是否带限定语由改标题时逐条对照，不新增正则。导语仍按现规则：恰好两个三级时一句点一个，三个或四个时不逐个点名。
- 三级标题可以保留本章对象的完整名称（如「数据项坐标」），不拆成「行与列」「空格与标记」。
- 固定收尾节名固定复用，见本文件。
- 过程节不承载回顾职责：`### 本章实现边界` 一类「本章做到哪、哪章再讲」的标题一律不设，边界话并入 `## 本章回顾`；开篇的目标节只陈述本章可交付产物（如 `确认本章产物`），标题与回顾分工见本文件「页面骨架」。
- 英文文件名承担稳定路径职责，多词形态见本文件；中文 title 承担理解职责，两者不必逐字翻译。
- 例外：part 落地页（`_quarto.yml` 中 part 引用的 index.qmd）title 即 part 名（如「示例项目」），不受 2-6 汉字硬限；副题信息只放落地页引言，章节与落地页 qmd 一律不写 `description`（front matter 出处见 basics.md），后续其他 part 同样处理。

### 定语「的」的取舍

标题（YAML `title` 与 `##`、`###` 同规）里的定语「的」按定语与中心语的关系取舍，不默认加、也不默认省：

- **加「的」**：定语与中心语是两个各自成立的名词性概念，直连会长串名词堆叠或产生切分歧义（如「明确流程约定」：示例项目 与 流程约定 各自成词，去掉「的」后定语加中心语直连成七字名词串；「识别流程的进行与结束」的「的」标出领属边界）。
- **省「的」**：定语与中心语合成一个单一名称或紧密概念，加「的」反而把名称拆散（如「认识示例工程布局」：示例工程 是一个整体名称）。
- 判定法：把定语与中心语拆开各说一遍，两个都是完整概念就用「的」相连；合起来才是一个名称就不用。加「的」后标题超出标题字数时先改写对象词，不靠删「的」压字数。

### 纵向承诺链

写章第 2 步（定结构）逐条对照，不新开第 10 步。检查顺序固定为下面 8 条；每条的要求都是「下一层必须兑现上一层对象」：

1. part 落地页那一句引言的范围等于该部分全部章的 YAML `title` 集合。根首页卡片不把示例项目收成其中几章。
2. 章引言里「这一章做什么」那一句的宾语等于 YAML `title` 的对象。引言点名的源文件必须是本章摘录实际来自的文件。
3. 每个任务级 `##` 的中心名词是章 title 对象的一部分。有 `class` 的章按「类型、成员变量、最重要的函数、其余重要函数」的次序排任务节，形状见本文件「有 class 的章的任务节」，没有下一种内容就停在当前一种。
4. 每个 `###` 的中心名词能被父级 `##` 的宾语盖住，或是这一结果里的一步。恰好 2 个 `###` 时，`##` 导语一句点一个；3 个或 4 个时导语只写共同结果，不逐个点名。
5. `###` 那一句导语的宾语等于该 `###` 的对象。其下每个自然段的段首句保持这个对象；换对象就换 `###`，或把句子挪到已经拥有该对象的 `###`。导语点名标题里的对象，不用「这三种类型」代替还没写出的取值名。
6. `##` 下没有 `###` 是允许的，条件是这一节只有一个函数或一个结果。禁止为了「有下级」补出一个孤立 `###`。
7. 「本章回顾」里「下一章」后面的名字等于 `_quarto.yml` 中下一章的 YAML `title`，不写链接。回顾里的能力用本章 title 的对象。最后一章不写「下一章」。任务节不解释下一章才建立的术语。
8. 有 `class` 的章的任务节顺序，见本文件「有 class 的章的任务节」。任务章的 `###` 顺序与 `src/run-build.sh` 的步骤顺序一致。目录章里「有几个目录」的句子与该节目录树的项数一致，口径见本文件。

### 命名检查

改 title 不改文件名，除非主题边界或页面职责变化；改动后 `quarto render` 检查右侧目录与书内导航显示。页面 title 变化时，part 落地页的卡片标题与一句话描述同步改为新 title 的承诺，一句话仍概括该章交付，不沿用旧措辞。

### 计数口径

估算 token = 中日韩字符数 × 1.5 + 其他字符数 ÷ 4。公式对主流分词器（GLM、Claude、GPT）取保守上界，只用于预算比较，不声称等于真实 token 数。

- **计入**：正文、标题、列表、表格、Callout 与链接锚文本。
- **不计入**：YAML frontmatter、链接目标、代码围栏（`{.cpp}`、`{.text}`、bash 等）全文、`{mermaid}` 图表全文、`{python}` 可执行单元全文。逐字代码与图表是机器寻址或视觉对象，读者扫读时整体跳过；token 预算度量的是读者逐句读过的正文当量。
- 代码与图表不计 token 不等于免检：它们仍受分层的行数上限与注释连续行检查约束（见「分层上限」）。
- **任何链接只计读者看见的锚文本，不计目标**（计数口径收紧）：`[锚]` 与 `(目标)` 组成的行内链接、`[锚][ref]` 引用式链接只计锚（锚内可含行内代码）；`<https://…>` 与裸 URL 计 0。GitHub 绝对链接的 URL 是机器寻址字符串，相对链接目标是页面地址，计入都会挤占正文预算；`verifying-content.py` 在计数前把整段链接替换为锚文本，再进入统计。
- 字符数按 Unicode 字符计：汉字、全角标点各算 1 个字符，归入中日韩一侧。
- 节导语口径：标题之后、首个代码块/列表/表格/引用/盒子（div）之前的连续正文；空行只分段，不结束导语。导语内链接只计锚文本。
- 引用块口径：连续 `>` 行合并为一块计数，链接只计锚文本；Callout 盒子（`:::`）不是引用块，按其自身层级计入所属分节。

### 分层上限

| 层级 | 上限 |
| --- | --- |
| 整章（frontmatter 外全部内容，只含计入部分） | 5000 token |
| 无标题引言（首个 `##` 之前） | 400 token |
| 每个 `##` 正文（不含代码和图表） | 400–1200 token；一章只有一个任务级 `##` 时该节 200–1200（下限只约束任务级，固定收尾不设下限）。区间按现有章节的正文当量定，低于下限合并或降级，不补空话 |
| 任务级 `###` 正文（不含代码和图表） | 有代码、表或图时下限 40 token，没有这些块时下限 120 token；上限 640 token |
| 「常见错误」的症状 `###`（不含代码和图表） | 60–240 token，不套任务级 `###` 的 120 下限 |
| 「自测问题」与「本章回顾」 | 不设新的上下限，本章回顾保持短 |
| 任务级 `##` 数量 | 通常不超过 4 个；按独立任务划分的原则见本文件「六段块序列」 |
| 每个 `##` 下 `###` 数量 | 2 到 7 个；只有 1 个时并入 `##` 正文或补同级 |
| 普通代码块（围栏内内容行） | 20 行 |
| `{mermaid}` 图表块 | 40 行 |
| `{python}` 可执行单元（坐标图等） | 30 行 |
| 单个正文段落（代码块、表格、列表与标题之外的连续文本段） | 70–220 token；下限拦过短段（70 token ≈ 45 汉字当量），上限保持上限，写作舒适带 90–180。豁免下限：章引言段、`##`/`###` 节导语、紧邻代码/列表/表/图/盒子的单句块前导语、本章回顾、自测固定导语、Callout 盒子内段落；豁免类仍受 220 上限约束。低于下限的补法见 `steps/05-sentences.md`「导语衔接」 |
| `##` 节导语（标题后、首个代码块/列表/表格/引用/盒子前） | 120 token 且 ≤2 句，不放代码围栏；设 `###` 的任务级 `##` 导语不另设下限，导语点名的句式见本文件「标题分层」 |
| `###` 节导语（同口径，到首个盒子/代码块/列表前） | 80 token 且 ≤1 句 |
| 单个 `>` 引用块（连续引用行合并计） | 80 token |
| 代码片段内注释 | 写法与限额见 `steps/03-blocks.md`「代码块 filename 标注」 |
| 一章 Callout | 不设下限；超过 8 个失败。写作时常例是 1 到 3 个 |

`{python}` 可执行单元应只含助手调用，绘图逻辑在共享助手库（见 `quarto/coords.md`）；超出 30 行说明把绘图逻辑内联进了正文，属于结构违规。

数字依据：没有规定章节字数的权威国标（GB/T 7713《科技报告编写规则》只管结构格式）；技术写作社区实践是单节对应 3-5 分钟阅读（约 1500-3000 字）、单个功能模块 800-1200 字，超限优先拆分。按 CJK×1.5 换算，整章 5000 token 约合 3300 汉字的正文当量，是「一节一件事、一章四节左右」的自然边界。

### 执行方式

- `verifying-content.py` 第 3 查按上表逐文件、逐节、逐代码块、逐正文段落核对，超限即整体失败；限额调整只改该脚本的常量与本表，两处必须同步。
- 根目录 `index.qmd` 与 `content/<game>/index.qmd`（YAML 含 `body-classes: index-page`）是着陆页：短引言与卡片网格不是章节引言，只核对整章总量与代码块限额；着陆页不套用标题与骨架限制，见本文件「六段块序列」。
- 任务级 `##` 数量、固定收尾不计入、`###` 的使用条件与首章「常见错误」豁免的结构判断，见本文件「六段块序列」；数量口径以上表为准。
- 结构性规则（引言构成、`###` 数量）同时受 `steps/02-structure.md`「六段块序列」约束；本表提供量化兜底。
- 接近上限不是目标：预算是上限，内容仍按凑字数禁令与密度规则精简（见 `steps/04-paragraphs.md`「凑字数禁令」）。

### 页面宽度与垂直节奏

页面“紧凑”通常有两个来源：正文列太窄导致无谓换行，或块之间缺少承接留白。优先小幅放宽 Quarto HTML grid 的 `body-width`，再用共享 CSS 调整正文块间距；不要只放大字体，也不要用局部规则给每个块重复加 margin。正文列仍需保留 `max-width: 100%`，代码和宽表在窄屏上继续滚动或换行。

当前仓库采用 840px 的正文内容列和约 1.55rem 的普通块间距，代码块连续出现时保留更大的间隔。代码块与正文同宽：不再对代码做二次限宽（`--code-max-width` 已删除），宽屏两侧留白属主流文档站（VitePress 1440 壳/688 正文）正常行为，不按显示器拉满正文。872px/840px 的取值依据（100 列代码不折行）见 `../designing-theme/knowledge/reading-surface.md`。评估重点是：每个任务是否有清晰的动作与结果、连续盒子之间是否有解释段、移动端是否出现横向溢出。这里不设置依赖浏览器截图的硬阈值，最终以 `quarto render` 后的 HTML 结构和实际阅读抽查为准。

Quarto 通过 HTML grid 控制正文、侧栏和目录列，代码块的 `filename`、换行和复制行为由代码块配置及 CSS 共同控制；页面宽度与代码标题过长是两个独立问题。

### 一图一事与同主题相邻

图是读者视觉负荷最高的盒子：一张图同时表达两条关系时，读者要同时在脑子里维护两个对照，图前正文与图后结论也各要写两遍才能闭环。因此一张图只核对一条已讲清的关系，需要两条就拆图或拆节；一图一事与主题错位拆 `###` 的边界见 `steps/03-blocks.md`「代码与图的桥接」。代码与图相邻的前提是同一对象：图讲 B 而前后代码讲 A、C 时，读者被迫在三个对象间跳转，这正是「代码 A → 短句拐弯 → 图讲 B → 再贴代码 C」式堆叠的成因。主题错位时先用一句正文收束本对象，再另起 `###`。图中的每个框和箭头都应能在图前正文找到出处；图引入正文没有的概念时，读者只能靠猜。写法见 `writing-quarto` 技能 `quarto/authoring.md`「代码与图的桥接」。

### 主线必须先闭合

读者在教程中需要不断确认"我现在做什么"和"我是否做对了"。如果命令、输出、参数解释和下一步背景交错出现，读者必须频繁切换目标，无法判断哪一块是必经步骤。先给唯一动作和可见结果，再补解释，能把首次成功压缩成一条可回放的路径。

主线闭合要求一节只有一个要闭合的目标：标题、第一句、动作和验收输出指向同一个结果，中途出现第二个独立动作时，读者就无法判断当前在等哪一个。任务粒度本身的判定标准属于页面结构，见本文件。

标题对齐同时排除离题辩白：操作小节里与标题无关的工程取舍长论（「为何不跳过某步 / 幂等 / 配置漂移」类）让读者在动作中途读辩白，主线被打断；执行规则见 `steps/03-blocks.md`「小节标题与正文对齐」。

当多个 `###` 共享同一阶段、环境或产物时，可以用父级 `##` 统摄，但父级只负责分组，不能把两个各自可验收的任务压成一个模糊标题。父标题要写清当前阶段或范围，子标题继续使用可执行、可观察的任务名。

### 长段拆分的判断依据

长段的问题不在于占据多少行，而在于它要求读者同时记住多个职责。主线动作、成功判据和可跳过说明压在同一段时，只读必要内容的读者必须重新寻找下一步，逐字阅读的读者又无法判断哪些细节可以跳过。按职责拆成短段，能让首次执行和回看细节两条路径自然分开。

普通 Callout 不能成为细节垃圾桶。把可以跳过的内容集中进提示框后，读者仍要判断这段是否影响当前任务，而且视觉上独立的盒子容易像必经步骤。只有删除后不影响首次成功和验收的信息才适合下沉，并且一个最小模块最多一个 Callout，一章的个数见本文件；术语解释型 Callout 是就近放置的例外，写法与限制见 `steps/03-blocks.md`。稳定界面判据与它的解释同框时，另见下节约束。

合并与拆分都按信息职责判断，不按固定字数。同一状态内部的账号创建和正常现象可以合并。成功判据与后续执行范围进入下一个状态时另起一段，即使它们仍属于同一次首次启动流程。

## 情况

### 情况：类章或能力章

类章按「是什么、怎么用、边界在哪」排任务节；能力章按「做完什么、怎么做、怎么验」排。同一本书里两种章各自固定次序，不混排。

### 情况：标题归并

两个标题讲同一件事就并成一个，下层的句子跟着走，不重写。承诺链断开时先并标题，再动句子。

### 情况：全章重构

第 1–2 步只定删留和标题。发现某段要重写，记下来留给第 5–7 步，不在这里改。
