# 第 5 步：定句子

产出：一句一动作的句子。
这一步只调句内结构和句间衔接，不改第 4 步定下的段序。

## 通用情况

### 代词不能代替未写出的对象

「这个／这些／这一步」类代词只在**同句或同一节的上一句已经列出对象名**时合法；对象名只出现在后面的 `###`、只出现在代码围栏、或只出现在另一道自测题里，都算没有先行词。判定以整篇 qmd 为范围，按标题切开后再看代词前面有没有对象名，一句摘出来不能判。段内回指不在此列：上一句已写出「数量」，下一句写「这个数量」仍然合法（given-new 的复用分支）。

- **自测题干**是合上书的一问，只看本题题干：禁止「这个、那个、这些、那些、哪个、哪些、哪一句、哪一层、哪一行、哪一块」，先写出被问的对象，再用「是多少、会不会、A 还是 B」来问；「什么」允许——它在要一个名字或一句文字，不是指上文没出现的东西。答案折叠里的回指不扫。
- **节首句**不得用代词把后文才展开的内容提前捆成一包：节首以「这些／这个／这一步」作话题、同句又没有列出对象名，即失败。「这一章」「下一章」「这一节」指书的单位，是固定说法，不在此禁令内。
- **已经逐个写出名字之后的回指**仍然合法：如前文小节已写出 `Player`、`Move`、`PlaceResult`、`Result`，后文「这些类型由 `Game` 的四个数据成员使用」保留。

条文与自动检查见 `writing-quarto` 技能 `scripts/verifying-content.py` 的整篇题干/节首检查；步骤挂点：定结构改自测题，定句子改节首与句内代词；对照见本文件「代词不能代替未写出的对象」。换算句里的「下标」不算已经写出的对象；点名规则见 `steps/07-layout.md`「列表选择」换算条。

### 一次对话

面向读者的一次说话只推进一件内容：可以是一句，也可以是紧挨着的两句，但必须沿用同一套说法。对话不是新的切分单位，也不是标题层级：判定挂在定段落和定句子上——定段落先问这段有几件内容、决定删或拆，定句子才改措辞。脚本不统计对话数；自动失败只有下面四条判定里的三类高精度信号（见 `steps/03-blocks.md`「机械检查」）。

- **一件内容**是读者能单独复述的一件事，例如「这次有没有写进状态面板」。两件内容用顿号或逗号放进同一句，再补「是两个不同的问题」「用两个枚举分开回答」，就是把两次说话写成一次；读者读到围栏前，要回头拿开头的问题去猜后面的编号各指哪个。
- **围栏前的成员列表允许与随后成员注释用词接近；围栏后不再复述**：成员取值列表和成员行尾注释说的是同一批对象，用词相近不是改口；列表之后的数据成员围栏里已写明的信息，块后不再复述。
- **写不出本段中心，或这句与导语、围栏注释同义，就删本段**，不另写替身句。要换对象必须另起段，而且该对象得是本节正在讲的，不能提前交给后文才展开的成员或函数（如 示例章的 `current_owner_` 与 `Game::ApplyMove`）。
- **后文还讲这件事时，沿用开头的说法和类型名**，不改口成「接着看」「第一个枚举」「第二个枚举」。序数可以指真实位置（示例章「第一个格子」），不能用来给前面并列过的类型、成员、入口、步骤重新编号；格子、行、列和「第二次写入」这类真实次序豁免。改写是每件内容紧挨它自己的围栏，说法从开头保持到围栏。
- **数量词和「这些」必须对着紧接着的名单或围栏**：写「四个入口」「覆盖四类」，下一块就要列出四个名字或四类场景；对不上就改成点名对象（示例章写「读写用 `IsInRange`、`GetCellKind`、`PlaceCell` 和 `IsFull`，`Board()` 只建出空状态面板」，不再说「只留四个入口」）。
- **一句里的全称（全部、所有、唯一）读完下一句仍然成立**；被下一句否定就改范围或删除。**类型接线**（两个逗号分句各自是「成员叫法 + 使用 + 某一章的类型」）若两项都已出现在紧邻导语和围栏里，整段删除，不走「拉链句」的推迟、拆句、一项一行。

条文与自动检查见 `writing-quarto` 技能 `scripts/verifying-content.py` 的句子模块切分；步骤挂点：定段落删段或拆段，定句子改措辞；对照见 `examples/04-paragraph-cases.md`「定段落：类型接线段整段删除」、`examples/05-sentence-frame.md`「定句子：两次说话拆成一次对话」与 `examples/05-sentence-reference.md`「定句子：数量词对着下一块点名」。

### 句内骨架

写作步骤的定句子步骤。本条管**设计说明**（为什么这样存、这样判定、这样分工）——一段解释代码决策的正文；步骤句、列表项、自测导语不套这条。它不与邻条重复：拆核四步管多核怎么拆段（见 `steps/04-paragraphs.md`「拆核四步（多核混段的拆段方法）」），过简断裂管分句之间的衔接（见本文件「过简断裂禁令」），本条管**分句各自担任什么角色、按什么次序排列**：

- 每个分句只担任一种角色：可观察事实、不变约束、因此作出的选择。次序固定为**事实 → 约束 → 因此选择**；选择句不得出现在依据之前——先写「长度取常量」再补「九个格子」，读者要把因果倒过来读。
- 光有回指不够。后一分句若不是同一谓语的延续，必须写出「因此 / 所以」；删掉关系词后读者仍要自己补因果，判为不合格。可观察事实（「状态面板一共九个格子」）可以在前，读者据此才知道选择成立。
- 「是示例项目规则的一部分」这类只贴类别、不改变下一步的分句删除：它不回答「所以代码怎么办」。
- 「因此选择」必须是读者下一步要执行的动作。只约束作者的选择（不另造类型、测试少记一个名字、注释该怎么组织）整句删掉，不改写成另一句解释；正文不展开与本章对象无关的标准库机制，也不写「不写甲，而是乙」。
- 一句里用逗号甩出的独立判断，最多留「事实，约束」或「约束，所以选择」一对；第三个判断另起句或删除。单句仍守本文件「句子规则」的 40 字与一动作上限。
- 递进同一核不拆段复述：长度和装下它的数组是同一个核，同段用「因此」接住，不另起一段再说一遍「正好装下」。
- 后续小节专讲的对象，本段不写「由 X 完成」：换算如果由下一小节专讲，本段不提前交接（「换算由下一小节完成」）；块内注释或下节首句已经说出的职责，整句删除。
- 与「对象先行」的对齐方式见 `steps/04-paragraphs.md`「句序与段落形态」。

判定信号：设计说明句里选择先于依据；逗号甩出第三个独立判断；分句只贴类别不改变下一步；删掉关系词后因果要读者自补；段末提前交接后续小节的对象；「因此选择」只约束作者、读者没有下一步动作。改写对照见 `examples/05-sentence-frame.md`「句内骨架：先依据后选择」与「技能腔：解释作者的选择」。类型接线句与被下一句否定的全称按本文件「一次对话」判删留，不按本节改写句内次序。

### 拉链句

一句话里把两组对象两两配对（左组对右组），删掉任一配对，剩下的配对仍能单独成立，原句就是拉链句：读者要按顺序把左组一一配到右组，且两个配对共用同一个判据（如「数据项在哪、上面是什么，分别交给 `Position` 和 `CellKind`」——删掉任一配对，另一配对照样成立）。它不是一个中心，也不是步骤链；现有的「一句一动作」「不提前交接」拦不住它，因为它把两件事合法地写进了同一句。旧「分号双主语」豁免（两个行内代码主语用分号并列，如「`Position` 定位一个数据项；`CellKind` 保存格子的类型」）已废除：这类分号句通常就是拉链句，按本节改写。

三条改写，按顺序选，停在第一条适用的：

1. **推迟**。`##` 有 `###` 时仍按顺序点名子节，但至多两句、一句只点一个对象，只用读者已经看见的白话，不点后文才定义的类型名。类型名留在该 `###` 的块前导语里，紧挨声明。
2. **拆句**。两个都能单独成立的观察分成两句。后句用「因此 / 所以 / 接着」接住前句对象。禁用「分别交给 / 各说一层 / 分别是」。
3. **一项一行**。同一对象的三项及以上取值或属性，放进列表或表格，一项一行。列表项内部也不再用「分别是 A、B 和 C」再拉一次链。

与相邻规则的分工（避免改到不该改的句子）：

- 后一步用到前一步的结果时，写成前后两句陈述，不用「先 / 再 / 最后」连接。
- **同物两处可留一句**：主语只有一个，只是指出声明文件和实现文件；句中再塞第二个任务（接受、拒绝、判定终局）时，第二个任务拆掉。位置句的谓语用「放进」，不用「记住」「保存」「选出」。
- **回顾不按拉链改写**：回顾的条数与形态见 `steps/02-structure.md`「六段块序列」。
- **块后复述不按拉链改写**：块后复述禁令见 `steps/03-blocks.md`「内容块前后的闭环」（对照见 `examples/03-block-after.md`「块后复述注释」）。

判定信号：同一句里用「分别交给」「各说一层」「分别是」连接两组对象；或一句内两组配对删掉任一仍成立。改写对照见 `examples/05-sentence-frame.md`「拉链句」；「分别交给」「各说一层」由 `verifying-content.py` 对读者正文硬拦。类型接线句是本节的例外出口：两项都已在紧邻导语和围栏出现时整段删除，不走推迟、拆句、一项一行（见本文件「一次对话」）。

### 六个成分

读者正文围栏外的句子以六个成分为主轴：主语、谓语、宾语、定语、状语、补语。普通句子用不到六个。默认是主语加谓语。谓语支配一个对象时加宾语。定语只修饰主语或宾语里的名词，一层。状语只放在谓语前，一层。补语只放在谓语后说明结果，一层。

一句先标成默认主轴，或标成下表的一种场景。表外的连谓句、兼语句、双宾句、主谓谓语句、名词谓语句、倒装句，拆成默认主轴的两句；同档并句的连谓不拆，异档连谓仍拆。

- 动作支配一个对象：动词谓语句，主语加谓语加宾语。
- 说明状态、没有对象：形容词谓语句，主语加谓语，无宾语。
- 判断类别：是字句。
- 处置读者已经知道的对象，并且写出结果：把字句。对象是新信息时不用。
- 受事是这句话的话题，施事不重要或已在上句：被字句，或受事作主语的动词谓语句。
- 处所里存在、出现或消失某物：存现句，处所作主语。
- 下一句仍是上一句的话题：零形回指，主语不写出。话题已经换了，必须写出主语。

下一句的主语复用上一句的宾语或话题。一句仍只做一个动作，仍不超过 40 字；同档并句一个逗号，整句不超过 40 个汉字。

依据：黄伯荣、廖序东《现代汉语》把主谓句分成动词谓语句、形容词谓语句、名词谓语句、主谓谓语句，常用句式另有把字句、被字句、连谓句、兼语句、双宾句、存现句；朱德熙《语法讲义》把主语看成已知话题；陈平把零形回指定义为上文已出现的事物可以不写出那个词。

### 主语选执行者或话题对象

章首引言、节导语与段首句的主语，取本章或本节要交代的对象，或执行动作的一方：程序、井字棋、对局、棋盘、玩家、`Board`。主语不取这些对象产生的下游产物——回应、输入、输出、画面、结果、数据。

- 主语落成产物时，动作的发出者被挤进定语，读者读到句末才知道谁在做事。例如「终端画面里的回应确定一局井字棋要做什么」，主语是「回应」，「确定」的却是程序。
- 改法：执行者或本章对象先作主语，产物退回宾语。上例改为「程序每一轮都显示当前棋盘，并提示轮到谁落子」。
- 判定信号：圈出主语，问它会不会自己做这个动作。不会，就是主次颠倒；把主语换成执行者或本章对象。
- 产物是本节主题时可以作主语，例如快照字段、终端输出的格式；此时不把执行者降格为「由 X 完成」式被动（见 `steps/06-wording.md`「目标语气」）。
- 依据：Google 开发者文档风格指南与 Microsoft 风格指南都要求尽量用主动语态，让执行动作的一方作主语；朱德熙《语法讲义》把主语看作已知话题，章首的话题是本章对象。改写对照见 `examples/05-sentence-reference.md`「主语不落到下游产物」。

### 过简断裂禁令

逗号、句号把一句话切开后，下一分句必须满足 **given-new** 之一，否则为过简断裂：

- 复用上一分句的对象：代词、同名，或「其中」式回指；「这个／这些」只回指同句或上一句已经写出的名词（见本文件「代词不能代替未写出的对象」）；
- 写出关系：因此、这样、然后、用来、以便等承接词。

禁止新主语＋新事实且与上一分句无回指——每截单看都合法、段却不成篇，读者要自己补「因为／所以／其中」。与「罗列短句成段」的分工：那条打**句号清单**（多个各自成句的短句堆成段，见 `steps/04-paragraphs.md`「罗列短句成段禁令」），本条打**逗号切断**和**过简两句各丢一个事实**（如「对象 → 文件位置 → 入口个数 → 私有存储」逐截并列）。时序句「进入目录，执行入口」合法：后一分句接住前一分句的动作。

判定信号：逗号或句号后的分句引入新的主语或新的行内代码标识，且无回指词、无承接词。改写时按本文件「概念负荷」收敛主概念，用给定信息衔接次要展开；对照见 `examples/05-sentence-brevity.md`「过简断裂段」。

### 导语衔接

导语第二句用衔接词接住上一句的对象，不用「这一节」起头；链接已经写出章节名时，不再加「的画面」。

- 管 `content/**/*.qmd` 里 `##` / `###` 标题下、第一个围栏或子标题之前的导语。不管章首无标题引言里的「这一章」，不管 `.agents` 规则正文。
- 「这一章」「下一章」仍只用于章首承接和章末回顾。
- 导语里出现「这一节」或「本节」即不合格。第二句用「因此」「这样」或重复上一句已经写出的名词来接住，不用「先…再…」。
- 链接文字已经是章节名时，链接外面再写「的画面」即不合格。`01-rules.qmd` 的标题「终局时的画面」保留，它是那一节自己的对象。
- 「这个／这些／这一步」仍只按本文件「代词不能代替未写出的对象」判定。

### 概念负荷

- 主题仍一段一个（「一段一对象」见 `steps/04-paragraphs.md`「段落规则」）；该主题下最多 **1–3 个主要概念**——读者读完必须能复述的独立对象或判断。
- 允许若干**次要概念**只服务主概念：出处、约束、可见性、与上一句的关系；次要概念不得另起主语当新主概念。
- **主次判定**：删掉该信息后，段首中心句是否仍成立？成立 → 次要或应删；不成立 → 主要。文件位置、`public:` 段名、入口个数默认是次要；「`Game` 编排一次」「状态面板收在对象内部」若本段要讲接口与存储分工，则「接口／内部存储」算两个主概念，须用给定信息衔接，不得并列甩出。
- 超过 3 个主概念：拆下一段，或改「一句中心 + 列表」；禁止用逗号、句号把第 4 个主概念塞进同一段。
- 普通自然段的 token 带与豁免见 `steps/02-structure.md`「分层上限」；低于下限时补的是衔接与必要次要概念，不是凑字数句（「凑字数禁令」见 `steps/04-paragraphs.md`，与本条同时成立）。

### 句子规则

- 单句一般不超过 20 字，40 字以上不可接受；一个句子出现三个以上动作或多个括号时拆句。
- 解释拒绝、终局或分支时，主句先写可观察结果，条件跟在后面或另起一句：先写「操作被拒绝，局面保持不变」，再写为什么；不把原因堆在句首让读者读完才知道结果。正文不重复 if/return 的分支细节，见本文件「情况：围栏里的代码」。
- 正文不使用破折号夹心解释：解释用冒号引出，或拆成两句；冒号的合法场合收窄见 `steps/04-paragraphs.md`「散文伪标签冒号禁令」。
- 用主动语态、肯定语气和陈述句；不用感叹句和双重否定。语气判定与口语腔、公文腔的正向标准见 `steps/06-wording.md`。
- 不写否定式预告：「程序不提供电脑对手」「这一章不实现 X」式否定句一律不写；正文只正面陈述当前程序做什么，后续章节才会出现的能力保持沉默，即使当下为真也不写，否则后文补上该能力时句子失效。范围声明同受此限：章引言只写本章要交出的对象，不点名后续章节的流程（如「不在这里配置、编译、测试或运行」）——即使是否定形式，也把后章内容提前搬进读者视野，超出本章范围。下一章预告同属后章内容，只写在章末本章回顾，引言保持沉默。
- 读者正文（`content/**/*.qmd`、根 `README.md`、`index.qmd` 的围栏外正文）不用「先…再…」「先…然后…」「先…最后…」串动作或阅读顺序。每一步写成独立陈述，主语是对象或读者要做的事。代码块导语直接点名对象做什么。`.agents` 的操作步骤、引号和围栏里的反例不套这条。
- 读者正文点名类时直接写反引号里的类名，例如 `Game`、`Board`、`Ai`。类名前面不加「类」。

### 简洁边界

简洁的上界是不丢失理解所需的信息。为省字而砍掉动作、对象或顺序的电报式省略句一律禁止：

- 禁例：「先自己回答，再展开核对。」——读者不知道怎么算回答、核对什么。改为完整指令：「不要展开答案，试着自己把回答完整说出来，写完之后展开对照。说不出来的部分，回到对应小节对照正文。」
- 指令与提示句写全三要素：动作（做什么）、对象（对什么做）、顺序（先做什么后做什么）。
- 并列的量名各自带上被计量的对象：「行数、列数」不能配一个光秃的「总数」。对象必须留在引入该名字的短语里；围栏代码注释和隔着代码块的后文都不算补上（示例章 `kRows` 的导语因此写成「数据项总数」）。
- 拿不准一句是否过省时写成完整句；多出的字数由篇幅预算吸收（见 `steps/02-structure.md`「分层上限」），不由读者的理解力吸收。

### 结构助词「的」

本条管 `content/**/*.qmd`、根 `index.qmd`、根 `README.md`，以及 C++、CMake、shell、Python、TOML、YAML 注释里的结构助词「的」。不管「是……的」「有的」「目的」。

- 定语是动词、主谓或介词短语时留下这个「的」。例：已经写入的状态面板；还没有元素的数据项；检查状态面板是否已满的功能。
- 固定搭配整词修饰：搭配已经固化为一个术语或一个叫法时整词使用，不再拆出「的」。例：二进制文件、源代码、数据成员。
- 中心语是类型、大小、数量、位置时一层修饰就够：这个「的」只在术语与中心语之间出现一次，不再叠加。例：数据项的类型（中心语是类型）；文件的大小（中心语是大小）。
- 同一个名词短语里有两个「的」时，先把内层术语粘合，只在两个术语的分界留一个。粘合后仍有两个，就改写成动词句。
- 定语和中心语都是名词，粘合后仍是一个叫法时，去掉「的」。例：状态面板的行数写成状态面板行数；状态面板的列数写成状态面板列数；数据项的状态写成数据项状态；示例项目的状态面板写成示例项目状态面板。
- 术语表已经定名的，类型概述跟术语走。例：`Position` 的类型概述写「数据项坐标。」
- 省掉之后领属不成立，或变成另一个意思时，留一个「的」。
- 口诀：两层不加的，三层要加的；固定搭配不加的，动词定语要加的；读起来会停顿，就加的。
- 正文里的命令与配置按同一组规则；源码注释的措辞由项目 C++ 流程负责，本技能不在这里定。

### 函数概述跟围栏

函数围栏前的概述句，其动词与对象必须与围栏里的函数名和参数一致：围栏里是 `ApplyMove`，概述句就用「应用」和「一步操作」，不改写成同义词（如「落子」）。位置写成「定义在 `文件` 里」，不用「声明在」。源码注释怎么写由项目 C++ 流程负责，本技能只对齐正文与围栏。

散文一句不换对象；判定全文见本文件。
反例：「已落 X：先手在这一格落下 X。」——右侧换成「先手」和落下动作。
正例：「先手：使用 X 元素。」

### 关系写成能核对的运算

一句里的量必须写成相等、乘除加减、上下界，或哪个成员记下哪个数。盖住这四种的「确定、体现、界定、表达」不合格。时间义「已经确定」合格，如「编译期就能确定」。领域换算注释的「由 A 得到 B」和 `To*` 的「将 A 转换为 B」不在这节改，注释场景见 `steps/03-blocks.md`。一句仍只做一个动作，仍是是字句或动词谓语句。标识符的加减乘除写在同一对反引号里，运算符用源码符号。`kRows - 1` 合格，`kRows` 减 1 不合格。

命中即改的信号在 `writing-quarto` 技能 `steps/08-reread.md` 信号表「定用词」行；正反对照见 `examples/06-wording-cases.md`。

### 同档并句

相邻、同一对象、同一档、被句号切开的两句可并成一句，异档不并进一句。三档次序固定：

- 职责：对象记下或交出什么。一个谓语。
- 机制：同一对象上、同一件事的条件与动作。连谓只允许这一档，一个逗号。状语必须是时间或条件（写入前），不能是文件位置。
- 位置：声明文件和实现文件。主语仍是这个对象，谓语只能是「放进」。这是「同物两处可留一句」的写法，不把职责再塞进来；上一章链接只当库名的定语，不另起主语。

示例章章首正例：`Board` 记住状态面板上已经落下的元素。保存九个数据项，写入前检查坐标。把声明放在项目动态库的头文件 `state.h`，把实现放在源文件 `state.cpp`。话题没换，下一句不写「它」作主语；中间已经换成别的对象，位置句写回原来的类型名。否决句是「在头文件和源文件里记住已经落下的元素」：「在头文件和源文件里」修饰了「记住」，记住的是元素，不是头文件。改写对照见 `examples/05-sentence-reference.md`「处所状语配错谓语」。

### 一句不换对象

一句里能不能同时写已落 X 和先手：不能。一句只写一个对象，冒号右侧不得换成另一个对象，也不得用近义词把左侧再说一遍。

反例：「已落 X：先手在这一格落下 X。」——冒号右侧换成「先手」和落下动作，不再说左侧的格子状态。改写见术语表「数据项类型」的三句；正例三句不在这里贴，见同节。

一句里的对象仍只有一个；六个成分的槽位见本文件。

### 句子级病类清单

逐句判为不合格，命中即按括号内方式修；正反对照见 `examples/05-sentence-reference.md`「主语跳变与并列搭配不当」及各专名案例：

1. **搭配不当**：缩句成「主＋谓」「主＋是＋宾」核对，主谓、动宾、主宾任一不搭即换词或换句式（主宾搭配典型：目录是程序、章保存格子）。
2. **主语跳变**：并列或后续分句逐一还原主语，与首句施事不同即补名词或拆句（「操作后显示 X」主语继承到没有字母的格子）。
3. **并列成分不一致**：并列各项句法形式与施事必须同构，首项介词统领全列（「一行、一列或一条对角线上」→「在一行……上」）。
4. **顿号层级嵌套**：外层并列用逗号、内层用顿号；「以及」前用逗号（GB/T 15834—2011）。
5. **指代不明**：先行词不唯一或不在最近，换专名。
6. **紧缩并称释义**：把用途压成「一读一写」式并称、或省主语从句（「报告是否下满」），名字与动作的对应要读者自补，改写为显式映射（判定信号见「逐条释义代替动机」）。
7. **欧化措辞**：「进行／作出＋名词」改回动词；滥「的」滥「被」压缩；名词化主语段内一致时（如「读取直接抛出」的操作名）可留，否则补施事。
8. **破折号夹心与分号堆叠**：破折号夹解释的句子级判法见本文件；冒号后用分号续第二个解释即拆（对照见「破折号夹心句」「冒号后堆叠分号解释」）。改冒号时只允许两种合法场合（完整句引出列表/围栏/图；列表项引导词后），散文词条式冒号的判定见 `steps/04-paragraphs.md`「散文伪标签冒号禁令」。

### 定句子：句子要短

设计说明的分句角色链（事实 → 约束 → 因此选择）见本文件「句内骨架」；句序与段落形态判定见 `steps/04-paragraphs.md`「句序与段落形态」。

- 先按本文件「六个成分」给每句分类，再改字；改完回到定段落，核对中心句和一段一对象。
- 单句长度与拆句的判定见本文件「句子规则」。
- 多中心句按中心拆成两句，判定见本文件「句内骨架」。
- 拉链句判定口诀与三条改写见本文件「拉链句」；步骤链、同物两处不按拉链改写，对照见 `examples/05-sentence-frame.md`「拉链句」。
- 结构助词「的」的去留判定与口诀见本文件「结构助词「的」」；两个名词粘成一个叫法仍带「的」，或三个以上名词、动词定语省了「的」，就按这条改。
- 相邻句子的因果、时序关系要写在句面上，判定见本文件「句内骨架」。
- 写完数量词和「这些」，对着下一块点名的判定见本文件「一次对话」，对照见 `examples/05-sentence-reference.md`「定句子：数量词对着下一块点名」。
- 换算按 `steps/07-layout.md`「列表选择」换算条写成同一段短句；对照见 `examples/07-layout-list.md`「公式与换算讲解段」。
- 元叙述开场与对象先行的判定见 `steps/04-paragraphs.md`「句序与段落形态」，对照见 `examples/01-language-scope.md`「元叙述开场与对象先行」。
- 假对比（「这不仅是 X，更是 Y」）、起跑式铺垫（「在开始之前」「首先我们来看」）与句尾意义拔高的判定和删法见本文件「情况：假对比、起跑式铺垫与意义拔高」，对照见 `examples/05-sentence-frame.md`「假对比、起跑式铺垫与意义拔高」。

## 情况

### 情况：围栏里的代码

代码注释属于源文件，本技能不改写、不评判。正文只查一件事：块后是否把围栏里已经写明的注释又讲了一遍。复述就删，判定见 `steps/03-blocks.md`「内容块前后的闭环」。

### 情况：引文与术语原文

引用外部规范或 API 原文时不改字，句长和语序让位给原文，只在引文前后补一句读者要取走的意思。

### 情况：假对比、起跑式铺垫与意义拔高

这三类都只删不补，删完读者要取走的信息不变：

- **假对比**：「这不仅是把常量挪进头文件，更是一次边界的重新划分」的后半句没有给出前半句之外的信息，只抬高语气。删「不仅是……更是……」，两层事实各写一句；前后两半都有信息时才保留对比（「这不是新增开关，而是把已有开关的默认值改掉」）。
- **起跑式铺垫**：「在开始之前」「首先我们来看」「让我们先了解」只宣布要开始。删掉，直接从对象和动作写起。
- **意义拔高**：「看似只挪了一行，却为后面的扩展打下了基础」把一次操作说成意义。读者要取走的是操作改变的结果；有结果写结果，没有就删。

三条都不顺手补依据：不新增事实、数字、命令、性能结论与引文，不把留有余地的说法改成确定说法，也不改写作者观点。对照见 `examples/05-sentence-frame.md`「假对比、起跑式铺垫与意义拔高」。
