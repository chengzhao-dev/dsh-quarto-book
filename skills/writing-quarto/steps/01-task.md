# 第 1 步：定任务

产出：一句读者做完能完成的事，加上这一章要覆盖的任务清单。
这一步不动标题层级，也不改句子。

## 通用情况

### 读者

读者有编程基础，可能第一次接触本书使用的语言、构建工具或自动化测试。每页只解决一个任务。正文按书的实际技术栈写，不预设某一种语言或操作系统；需要环境差异时在页面里就地交代。

### 叙事范围（硬边界）

本书定位是可用工程的用法与验收；编程语言机制的系统讲解不属于正文。`content/**` 正文因此只写五类内容：领域语义、分层与依赖、接口契约、构建与测试验收、可验证动作。

- **禁止**用正文讲解编程语言机制（枚举、结构体、命名空间、`inline`、`constexpr`、翻译单元、ODR 等），也禁止风格指南逐条教学（命名大小写、前缀、include guard 对比等）。
- 枚举取值列表的位置见 `steps/03-blocks.md`「三级标题最小模块」。
- **禁止**在工程章（非设计章）展开数值选型旁白：不写「用有符号整型承载…」「某字段为什么选定宽有符号整型…」，也不为选型链到外部语言笔记。`int` 可出现在代码摘录中，旁白不解释「为什么有符号」。
- **禁止课堂类比**：工程坐标系、API 与数据结构只用程序事实与可观察行为表述，不写「数学课」「平面直角坐标系」等跨学科课堂对照（如「与数学课的直角坐标系正好相反」）。作者构思时可借类比想问题，落盘到 qmd 前必须换成工程对象与可观察行为；图注已交代原点与轴向的，正文不复述对照。
- **禁止突兀跨仓依据句**：不写「写法依据见 / 依据见 / 机制见 / 选型见 / 承诺见 / 用法见 / 陷阱见」+ 外部语言笔记。工程约定由本书拥有；外部教材不是工程写法的依据机关。
- **跨仓外链默认零条**。工程叙事须自洽。仅当本小节工程点已讲完、且确有系统学语法需求时，可在小节末**单独成句**尾置可选深潜，口吻为「若要系统阅读…，见对应章节（GitHub 绝对 URL）。」同一章此类深潜宜 ≤2，能删则删。仅设计章可保留一次分册级链接。本书固定采用外部章节的构建约定时，用「本书固定采用…」陈述，仍放工程点之后，禁用「写法依据见」。
- **允许**代码块逐字展示源码（关键字照抄真实代码）；旁白回答工程问题：这段公共定义解决什么问题、谁读取或调用它、如何验证。
- **禁止接口清单压缩段**：不得把私有成员、公开成员名单、`const`、`[[nodiscard]]` 等接口属性压进同一段旁白；定稿形态为场景（动作 → 点名 → 边界）→ 代码 → 块后只补注释未覆盖的工程信息；语言属性不进旁白讲义（对照见 `examples/05-sentence-reference.md`「接口清单压缩段」）。
- 判定口诀：句子的主语应是工程对象（模块、接口、数据、文件），不是语言构造（`enum class`、翻译单元）。反例与改写对照见 `examples/01-language-scope.md` 与 `examples/04-paragraph-cases.md`。

### 内容优先级

章节出现取舍时，按下面的顺序判断，不用较低层级的格式或样式要求覆盖较高层级的教学目标：

1. 读者任务与章节边界
2. 信息顺序和渐进披露
3. 页面块与段落布局
4. 技术正确性和可验证性
5. 标题、列表、Callout 和代码块等表达形式
6. 句子精简、术语和标点
7. 视觉样式与装饰

新增内容先确定它在既有页面块序列中的位置，再写入相邻小节。修改后回读完整小节及前后切口，确认动作、结果和下一步仍然相邻。只有步骤存在先后依赖时使用有序列表；同级选项使用无序列表；连续因果解释保留为短段落。

目录树先核对磁盘，再只保留当前任务需要的文件；注释、排列顺序与树后读法句统一见 `steps/03-blocks.md`「情况：目录树」。GitHub blob 链接嵌进同节导语句子里，不单独成行贴在代码围栏上方。线性构建流程用标题和文字说明，不用 Mermaid 代替。

### 术语门槛

- 保留编译、链接、目标、状态、回合等标准术语；首次出现时用一句话解释或就近术语卡，再进入命令。
- 不解释对当前操作没有影响的内部格式。只保留判断成功所需的输出。
- 面向新人的正文不堆砌入门前置名词；标题只用读者此刻已认识的词。

### 定任务：先让新人完成任务

- 开篇场景的写法见`steps/02-structure.md`「无标题引言」。
- 每页一条成功路径与后置内容的判定见`steps/06-wording.md`；主线闭合见`steps/02-structure.md`。
- 标准术语的首次解释与术语卡落点见`steps/02-structure.md`（写法见 `quarto/authoring.md`）；缩写先写全称。
- 不假设读者知道工具名、命令参数、目录布局或错误输出代表的含义。
- 目录式堆砌禁令与清单下沉判据见`steps/02-structure.md`。
- 标题与引言的单事承诺、承诺用词与 title 变更同步见`steps/02-structure.md`。
- 语言课禁令、否定式预告、不写「下一节」都在这一步判：它们决定本章能不能出现某句，不是措辞问题（细则见`steps/05-sentences.md`「句子规则」、本文件「叙事范围」）。

## 情况

### 情况：语言课

讲语言特性时，任务写成「读者能读懂一段真实代码」，不写成语法清单。叙事范围跟着读者的语言门槛收窄。对照 `examples/01-language-scope.md`。

### 情况：否定式预告

开头写「本章不讲 X」把注意力引到不存在的路径上。删掉这类句子，把边界写进叙事范围的正向句子。

### 情况：「下一节」整句

「下一节介绍……」只重复目录。整句删除，不换成别种导航句。

### 情况：没有项目技能

书里没有 `.agents/skills/quarto-book-project/` 时跳过书名、读者和章节表，不猜也不补。任务只从当前文件和 `_quarto.yml` 读到的内容定。
