# 第 7 步：定版式

产出：标点、中英混排、列表和加粗的版式。
这一步只改呈现形式，不改句子表达的内容。

## 通用情况

### 列表选择

目录列表后能用段落补一个遗漏的目录吗：不能，并列成员一次列全。列表选择规则：

- **无序列表**：并列概念、范围边界、要点枚举——各项之间没有先后或因果；代码块后的逐条讲解格式见`steps/04-paragraphs.md`「段落规则」。
- **有序列表**：有先后顺序的步骤或链路——执行顺序本身就是信息（如配置 → 编译 → 测试 → 运行）。
- 列表项结构平行：起首用同类的词（都是名词短语，或都是动词短语），长度相近。
- **列表字数带**：同一列表各项保持视觉齐长，避免扫读节奏断裂。计量：引导词汉字数、冒号后汉字数（行内代码按标识符计）。失衡判定：冒号后最长 ≥ 最短 × 2，或引导词相差 ≥ 4。改写顺序：删长项多余中心 → 拆多中心 → 过短项按简洁边界补全 → 停止。豁免：出错原因/正确做法；有序步骤；着陆页卡片。列表齐长服从句段主规则，假拆禁令见`steps/04-paragraphs.md`。
- 列表项起首用加粗引导词标记中心语，读者扫读时先看到分类再决定是否细读；关键词取同类词（如「显示状态面板」「读入坐标」），并按对象的发生顺序排列，读者扫读即得顺序与内容。
- 行为或规则枚举项用「**动词短语引导词**：完整句」格式：引导词命名本项的中心动作（如「**显示状态面板**」「**判定流程结果**」），冒号后保留完整中文句，写全动作、对象与结果。引导词是扫读索引，不替代句子信息，不为省字把冒号后压成电报短句（对照见`examples/03-layout-list.md`）。
- 解释并列名称的引导词列表放在首次使用这些名称的代码块或目录树之前：读者先经列表认识每个名称，再看结构展示；禁止把解释压到块后，读者会带着未解释的名称读块。名称本身用读者可核对的具体形态（如「项目动态库」），不用模糊统称（术语依据见`steps/06-wording.md`）。
- 并列成员一次列全：目录、组件等并列对象（含 `build/` 这类构建生成的目录）并入同一个引导词列表，先列全再展示目录树等结构；列表之后不用段落补列遗漏的成员（对照见`examples/04-paragraph-opening.md`「角色总述段」）。
- 目录树的列对齐（目录 `#/`、文件 `#` 右移 4 列、同一棵树只一档注释）见`steps/03-blocks.md`「情况：目录树」；本文件只管列表、标点与加粗，不另写一份树规则。
- 三项以上、或每项内含解释的信息优先成列表；只有两项且能写进一句的保留正文；只有一项时不设列表，写进正文（节内无代码块或列表承接时，整节收成一句）。
- **构造后的成员并列成列表**：同一句或同一段用顿号、逗号并列三个及以上数据成员、而且各项状态不同时，改成引导词列表；列表放在数据成员围栏**之前**，引导句不数个数、不把类名连写两次，也不写「成员写在该类里」——只把「构造之后的取值」引出来（如「`Game()` 默认构造之后，状态面板、当前用户、流程结果和操作记录是下面这样：」）。每一项恰好两句：第一句写成员是什么，第二句只写开局取值；第二句可以是「开局是空状态面板」这类状态句。枚举取值列表的位置见`steps/03-blocks.md`「三级标题最小模块」，本文件不重写；枚举成员的含义仍留在源码行尾注释，这里列的是构造之后每个数据成员的状态，不是把枚举成员再解释一遍。依据：C++ Primer 把名字和初值分开讲，阮一峰一句一事。
- **成员围栏前不列类型**：禁止「`board_` 用 `Board`，`current_player_` 用 `Player`」这种把类型再列一遍的句子——类型已经在围栏里。列表前的导语只点名要展开的维度，不把列表项里的取值先写一遍。
- **`private:` 不作正文话题**：围栏里可以保留源码的 ` private:`，因为片段必须和头文件逐字一致；「存放在 `private:` 下」「都在 `private:` 下」一类把访问说明符当话题的句子删掉，换成该 `##` 标题里的对象。
- **列表后直接进围栏**：成员取值列表的每一项先写这个成员是什么，再写开局状态；状态是枚举值时写出含义，不单写 `Player::kFirst` 或 `Result::kInProgress`。列表之后直接进数据成员围栏，围栏后不再放取值列表或同义复述段；成员的先后顺序、关联的结果类型等话题留到使用它们的函数小节再讲，不在成员节预告。围栏前的成员列表与随后成员注释的用词接近、围栏后不复述，见`steps/05-sentences.md`。
- **换算条（行列到下标的换算怎么写）**：
  - **点名**：第一次就写出是哪一种数。`cells_` 的数组下标、行号 `row`、列号 `col` 各用自己的名字。禁止「一个下标」「这个下标」「这次代入」互相指代。
  - **次序**：放在代码围栏和图之间的**同一段**，一句一个动作，后句接住前句的得数。第 0 行写出具体下标；下一句写第 `row` 行的起点；再一句写 `col` 从 0 加在这个起点上；然后一句只给出 `(1, 2)` 的三个数；最后一句只写算式和得数。禁止把跳过整行、列偏移、代入数字和得数写进同一句。
  - **不用列表**：后句用前句得数的乘加不是并列要点。列表仍只用于没有先后的并列，或配置、编译这种各自能做完的步骤。禁止「公式项：一句职责」。
  - **块位**：定义就是围栏里与源码相同的 `return` 行。`###` 导语仍是一句，点名函数和 `cells_` 的数组下标，并点明实现文件。原理段不重复 `static_cast`。图前一句点名得数是哪一个数组下标，不把图里已标的区间再念一遍。正文不另排 `$$` 或行内数学模式。

### 加粗使用

- 加粗只用于列表项或段首的引导词（中心语前置），标记结构，不强调情绪。
- 同一页加粗不成片：一段正文内至多一两处加粗，连续多句加粗等于没有重点。
- 标题不加粗（层级已由 `##`/`###` 表达）；行内代码与加粗不叠加在同一对象上。

### 标点与中英混排

- 中文用全角标点；并列英文用顿号；中文与英文/数字之间留半角空格。
- 破折号夹解释的句子级判法见`steps/05-sentences.md`（冒号合法场合见`steps/04-paragraphs.md`「散文伪标签冒号禁令」）。
- `true` / `false` / `nullptr` 等 C++ 关键字用行内代码原样书写，不写中文译名。

### 外部规范对照

- 阮一峰《中文技术文档的写作规范》：句长、中英混排空格、标点全角；标题不跳级、同级不孤立。
- Google developer documentation style guide：一段一意、先给最重要信息；任务级标题用动词。
- 华为《中文技术文档写作风格指南》：标题层级与句式；段落长度条文统一指向`steps/04-paragraphs.md`。
- GB/T 15834—2011《标点符号用法》：顿号层级与标点用法。
- 阿里 f2e-spec writing：中英混排与标点。

### 定版式：格式要降噪

- 行内代码与平台名词的版式判定见`steps/02-structure.md`。
- 可复制命令使用指定语言的代码围栏；命令与输出分开的判定见`steps/02-structure.md`。
- 标题与导航不用行内代码的判定见`steps/02-structure.md`；中英文之间的空格见`steps/06-wording.md`。
- 列表用于并列或顺序关系，选择判定见`steps/07-layout.md`「列表选择」。表格只用于需要对多个属性进行比较的内容：同一主题的属性合并成一张表，不按小节拆成多张薄表；只有一两列信息或右侧大量留白时改用句子或列表。列表是版式选择，不是新的一段说明。
- Callout 只承载可跳过提示的判定见`steps/03-blocks.md`。

具体元素写法见 `quarto/authoring.md`，终端步骤见 `quarto/terminal.md`。

## 情况

### 情况：并列或顺序用列表，比较用表格

并列项、有先后的步骤写成列表；多个对象按同一组属性对照写成表格。列表不是新的一段说明，表格格子里不再写「名词：一句」。

### 情况：加粗只标取舍

加粗标记读者要记住的那一条，一段最多一处。整段加粗等于没有重点。
