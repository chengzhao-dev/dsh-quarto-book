# 第 4 步：定段落

产出：一段一个对象的段落序列，段间衔接落在话题切换处。
这一步不改分句次序，句序留给第 5 步。

## 通用情况

### 段落规则

一段最多容纳一个主题。其余规则：

- 每段只有一个主题或中心句；中心句放在段首，后面的句子都服务于它。段内句子改完后，段首仍是中心句，一段仍只有一个对象；句子的六个成分见 `steps/05-sentences.md`「六个成分」。
- 一段一对象：同一段不夹杂两个并列对象，对象切换必须新起段；配套列表只服务本段对象，不得跨对象拼装列表项（对照见 `examples/03-block-after.md`「单段混并列对象」）。
- 段落不超过 7 行，最佳 4 行以内；超过即拆或改列表。
- 多个独立概念禁止塞进同一段：承接、目标、范围边界、阅读顺序、术语解释各归各段。
- 段落之间用一个空行分隔，段首不缩进。
- 代码块后的逐条讲解用无序列表：每项格式为「行内代码标识符 + 全角冒号 + 一句职责」（如 `` `enable_testing()`：开启 CTest。``），描述从简，全页标记方式一致；列表前保留一句引言交代工程语境，列表后需要时补一句收束或尾置 Callout。有先后顺序的排查步骤仍用有序列表；块前导语直接点名对象做什么，不用「先…再…最后…」，元计数禁令见 `steps/03-blocks.md`。
- 删段还是拆段，先按 `steps/05-sentences.md`「一次对话」数这段有几件内容再定删或拆；判定全文见该文件「一次对话」。

#### 拆段触发表

段落拆分不只按行数硬切，命中下表任一信号即拆段或改形态（列表 / 代码 / 图）：

| 信号 | 动作 |
| --- | --- |
| 段内出现第二个互不依赖的对象或主题 | 新起段；新段首句接住上段对象（衔接见本文件「段间：过渡句只在话题切换处」） |
| 段内出现「话题标签：解释」词条式冒号，或两个以上互不依赖的中心并列推进 | 按「拆核四步（多核混段的拆段方法）」判关系：递进同段衔接推进，并列拆段；词条式冒号改完整主谓句（见「散文伪标签冒号禁令」） |
| 一段同时承担「承接上一章」+「本章交付物清单」+「源文件位置」+「摘录声明」 | 章引言不拆段，形态硬限与摘录声明删除见 `steps/02-structure.md`；其他段落按职责拆段，交付物多项且需扫读 → 列表（目录式堆砌对照见 `examples/02-structure-shape.md`） |
| 超过约 4 行舒适带、或逼近 7 行 / 篇幅 token 上限 | 先找逻辑边界拆，禁止为凑行数在句中腰斩 |
| 连续 ≥3 段纯散文且无列表/代码/图 | 改写见本文件「句序与段落形态」 |
| 满篇单句段、句间无衔接 | 合并为连贯多句段，或改成列表 |
| 逗号、句号后分句换新主语、新事实，无回指、无承接词 | 过简断裂改写见 `steps/05-sentences.md`「过简断裂禁令」 |
| 一段出现第 4 个互不依赖的主概念 | 拆段或改列表见 `steps/05-sentences.md`「概念负荷」 |
| 一句多中心、分号串两事、>40 字多动作 | 先拆句，再判是否还需拆段；同档并句不按超长句拆，异档不并进一句，判定见 `steps/05-sentences.md`「同档并句」 |

假拆禁令：不为「段数好看」把同一中心拆成两段同义反复（相邻同义合并见本文件「段间：过渡句只在话题切换处」）；不为对齐列表而去拆段或填第二中心；章引言多中心的形态契约见 `steps/02-structure.md`「六段块序列」。

### 罗列短句成段禁令

- 禁止把多个各自成句、互不衔接的罗列式短句机械堆进同一段：每句单看成立不等于段落成立，句号串联的清单式段落让读者在句间自行补关系。
- 确认一个中心主题后，围绕段首中心句用衔接关系（…时、一旦、则、因此）把相关动作组织成连贯的完整句；单句长度与拆句触发仍守 `steps/05-sentences.md`「句子规则」，不为连贯写超长句。同档并句不按超长句拆，异档不并进一句，判定见 `steps/05-sentences.md`「同档并句」。
- 真正并列、需要扫读的项改用列表（详见 `steps/07-layout.md`「列表选择」）。
- 判定信号：段内句子逐句可删、互不引用；句间没有承接、因果或时序词；逐句像要点罗列。改写对照见 `examples/05-sentence-brevity.md`「罗列短句成段」。

### 凑字数禁令

信息密度以读者判断所需为准，不以篇幅为准。篇幅超限时先删下面这些句式，再考虑拆页；以下句式在 `content/**` 正文一律禁止：

- 统计性凑句：「文件只有 X 行」「真正执行的只有 X 行」「一共只有 X 个」这类数字统计。数字本身影响读者判断时（规模超出预期、需要据此决定读法）才允许出现，纯描述规模一律删除。
- 导航复述段：含「先看…再看…」的句子按 `steps/05-sentences.md`「句子规则」整句删除，不单指「接下来先看」；与 `##` 标题结构重复的段落同样删除，读者从标题自身即可获得导航。
- 同义反复：同一事实在承接句、代码块 filename、树内注释、列表项中重复出现时只保留一处。相邻段落同义合并见本文件「段间：过渡句只在话题切换处」。代码围栏的块后复述由 `steps/03-blocks.md`「内容块前后的闭环」管辖（对照见 `examples/03-block-after.md`「块后复述注释」）。同一禁令再延伸到公开接口旁白：禁止「接口清单压缩段」——把私有成员、公开成员名单、`const`、`[[nodiscard]]` 等压进同一段；定稿为场景 → 代码 → 块后只补注释未写的工程信息（对照见 `examples/04-paragraph-opening.md`「接口清单压缩段」）。
- 判断标准：一句删掉后主线闭环不受影响、且答不出「删掉它读者会做错什么」，默认删除。

### 拆分判据

读到一句话同时回答两个问题时必须拆分，典型信号：

- 一段里出现两次以上括号补充；
- 读者无法用一句话复述这段在说什么；
- 段落同时含「结论 + 原因 + 反例 + 后续动作」中三项以上，拆成按职责分的短段。

### 多问一答拆分

自测答案要怎么折叠，先看这一问该不该拆：自测答案或正文若同时回答两个以上独立问题，按「引言 → 按问拆段或引导词列表 → 收束」组织，禁止把多个问题压进一段：

- **引言**：一句点明对象之间的关系（如「配置和构建是两件不同的事」）。
- **展开**：每个问题一段，或用加粗引导词列表（`**配置**：…` / `**构建**：…`）；两项且能写进一句的仍可保留正文。
- **收束**：一句写出操作后果或因果（如「改了 CMakeLists.txt 要重跑配置」）。
- 典型禁例：把「谁做配置、谁做构建、何时重配」压进同一段；改写对照见 `examples/04-paragraph-opening.md`。

### 段内同义堆叠禁令

一个自然段围绕中心句推进时，同一机制至多给一句展开；再补一句换说法复述同一机制即为段内同义堆叠，主次不清，命中即删辅句或合并。判定信号：

- 段内两句主语不同、谓语同义（如「长度用常量固定」与「长度由常量在编译期确定」），删掉任一句主线仍闭合；
- 中心句之后连续多句都在解释同一个词，没有引入新机制、新对象或新边界；
- 句间只靠「也就是说／换句话说／即」类复述连接，没有因果或递进。

改写形态：中心一句 + 至多一句机制 + 可选一句桥接（引出下一段对象）；需要更多细节时下沉列表、代码块或后续小节，不在段内堆叠。

豁免与边界：

- **换算短句豁免**：换算写成同一段短句各答一个动作，是递进不是堆叠（见 `steps/07-layout.md`「列表选择」换算条）。
- **简洁边界反向保护**：删辅句不得造成电报省略；动作、对象、顺序三要素仍写全（见 `steps/05-sentences.md`「简洁边界」）。
- **跨章固定表述不复述判重**：「九个数据项」这类全书统一表述在各章按需出现，不受「同一事实只讲一次」限制。
- **自测答案豁免**：答案可对照题面复述一次再展开。

与「同义反复」（凑字数禁令）的分工：同义反复管跨位置重复（承接句、filename、列表项同讲一个事实）；本条管同一段内的同义展开；命中任一即删。

### 散文伪标签冒号禁令

散文自然段禁止「短名词话题 / 行内代码话题 + 全角冒号 + 解释」的词条式冒号（如 `` `Foo`：……``、`数组长度写成 X：……`）；这是列表项 `` `id`：职责 `` 的形态落进散文，版式像词条、读感怪异。命中改写成完整主谓句，或改真列表项。

冒号只保留两种合法场合：完整句引出紧随其后的列表、代码围栏或图（如「约定如下：」「定义在 state.h 里：」）；列表项引导词之后。其余散文冒号一律按词条式冒号处理。

判定信号：句首或句中出现「≤12 汉字话题或行内代码 + 全角冒号」，且该冒号没有引出列表/围栏/图。

豁免（不得误杀）：列表项（含 `` `enable_testing()`：开启 CTest。``）；列举/代码/图导语（下一块是列表、围栏或图）；终端与协议字面量（如 `流程结果：甲方获胜`）；表格单元格与代码注释。

与「破折号夹心改冒号引出」（见 `steps/05-sentences.md`「句子规则」）的关系是**收窄**：破折号解释改冒号时，只允许改成上述两种合法场合，不允许改成散文词条式冒号。

### 拆核四步（多核混段的拆段方法）

同一自然段并行推进两个以上互不依赖的中心即为多核混段，读者分不清本段在讲什么。写作或改写涉及捆绑概念（如「长度 / 容器 / 坐标换算」）时，强制走四步：

1. **拆核**：列出本段必须交代的独立核（例：长度常量的含义；使用该长度的容器；行列到下标的换算）。
2. **判关系**：核是「属性 → 承载」递进还是并列。递进可同段用衔接推进（如长度定型 → 容器选用该长度，先长度后容器）；并列必须拆段。
3. **一句一核推进**：每句主语明确（长度 / 数组 / 换算），不夹第二个核的细节；禁止伪标签把两核糊成词条。
4. **衔接与次序**：段内用「因此 / 所以 / 这样」接住上句对象；换核新段时首句点名上段产物（例：先讲 `kRows`、`kCols` 给出合法范围，新段首句写「范围确定后，坐标检查才有了依据」；递进同一核的展开留在同一段，拆段判据见 `steps/05-sentences.md`「句内骨架」）；若某核由后续小节专讲，本段只留一句明确桥接或整句下沉为其首句，禁止悬空预告。

拆段触发表已收录「词条式冒号 / 多核并列」信号行；改写对照见 `examples/04-paragraph-cases.md`「散文伪标签冒号与多核混段」。

### 章级：总—分—总

- **总起**：无标题引言的构成见 `steps/02-structure.md`「六段块序列」；引言的宾语等于本章 YAML `title` 的对象（承诺链第 2 条，见 `steps/02-structure.md`「纵向承诺链」）；主语取本章对象或执行动作的一方，见 `steps/05-sentences.md`「主语选执行者或话题对象」。
- **分述**：正文 `##` 序列沿一条主线递进展开；每个 `##` 是一个可验证结果的判定见 `steps/02-structure.md`「六段块序列」，每个 `###` 的中心名词与导语宾语按 `steps/02-structure.md`「纵向承诺链」第 4、5 条核对。
- **收束**：本章回顾照应引言提出的任务；首尾照应要求回顾能对上引言的承诺，不引入新概念；「下一章」后的名字等于 `_quarto.yml` 中下一章的 YAML `title`（承诺链第 7 条，见 `steps/02-structure.md`）。回顾的句数、句式与承接正文的要求以 `steps/02-structure.md` 为准。
- 已有源文件的章要补齐自测与回顾。没有源文件的章的处理见 `steps/02-structure.md`。

### 节内：递进式为默认，并列式处理枚举

- 有先后或因果的内容用递进式展开，顺序依据见 `steps/02-structure.md`「六段块序列」，段落顺序与执行顺序一致。
- 无先后关系的要点（边界清单、原则枚举）用并列式，列表选择规则见 `steps/07-layout.md`「列表选择」。
- 同一小节内不混用：一条主线递进到底；并列枚举整体作为一个环节嵌在递进中。

### 段间：过渡句只在话题切换处

- 需要过渡的位置：段落话题或对象发生切换时（上一段讲 A 命令，下一段讲 B 命令；前一小节配置，本节运行）。同一段内句子推进、或下一段直接继续当前对象时，不加过渡。
- 段间衔接落在下一段第一句的主语；主语复用上段的宾语或话题，话题切换时仍先接住上文再引出本段。
- 形式：一句，放在新段段首，先接住上文（点明与上段的关系或结果），再引出本段中心。范例（示例章构建规则节首句）：「可执行目标之外，同一份构建规则还注册了本章唯一的自动化检查」——前半句接住上文的可执行目标，后半句引出新对象。
- 边界：过渡句服务主线判断，不复述标题结构。含「先看…再看…」的导航复述句整句删除，判法见本文件「凑字数禁令」；`##`/`###` 开头的承接句数见 `steps/02-structure.md`「分层上限」。
- 相邻小节的首句同时是上一小节的承接位：写完上一小节结尾后检查下一小节首句是否接住读者，不在小节尾部再补预告句（与凑字数禁令同源）。
- **读者正文禁写「下一节／上一节」**：`content/**` 正文不得用「下一节…」「上一节…」预告或回指小节，衔接靠新节首句接住上文；章末的「下一章」保留。本文件讨论衔接位置时引用的这两个词是规则描述用语，不是允许正文照写的句式（`verifying-content.py` 对读者 qmd 与 agent 文档判失败，紧贴引号或反引号的术语引用豁免）。
- 相邻段落同义合并：相邻两段各自换一种说法讲同一事实时合并为一段，由后段的机制或结论接住前段的对象；合并后其余段落、列表和 Callout 不得再以第三种说法复述该事实。改写对照见 `examples/04-paragraph-cases.md`。
- 相邻两段不得各成独立说明书：第一段讲工具、第二段讲目录而彼此无衔接时，第二段段首要接住第一段的对象（工具基线 → 这些工具在编号目录上如何使用）；只删不接，两段仍然是两个条目。改写对照见 `examples/02-structure-shape.md`。
- 目录树后的正文不复述树内行尾注释：树注释已逐文件交代职责，再列一段「A 组件、B 目录与 C 目录各自带 CMakeLists.txt」是把树翻译成说明书目录。树注释的标记方式（目录 `#/`、文件 `#` 右移 4 列、字母序、个数对齐）见 `steps/03-blocks.md`「情况：目录树」；本条只管树后正文。树后保留的一句读法说明直述机制（「文件名给出位置，行尾注释说明职责」），不写「X 回答 A，Y 回答 B」的问答式并列；换成工具配置、依赖方向或「不参与 / 不依赖」类边界，即使树注释没写过，也删除或下沉，不得靠「新工程信息」留下（改写对照见 `examples/02-structure-shape.md`「目录式堆砌」「树后换对象收束句」）。
- 同一禁令延伸到代码围栏：块后不复述围栏内注释、单段并列对象按对象拆段的写法，见 `steps/03-blocks.md`「内容块前后的闭环」与本文件「段落规则」（对照见 `examples/03-block-after.md`「块后复述注释」「单段混并列对象」）。
- **多代码块小节先判一次只摘一块**：同源围栏是否合并、每个围栏前的导语怎么写、每段最多「一句 + 一个配套块」，见 `steps/03-blocks.md`「内容块前后的闭环」；函数或枚举围栏前固定两句的动词与 `///` 一致判法见 `steps/05-sentences.md`；块后收束与两个最小模块的衔接见 `steps/03-blocks.md`「三级标题最小模块」，本文件不另写一份。改写对照见 `examples/03-excerpt-lead.md`「多代码块一句导语」「递进片段合并」。
- 表格与对照表的承接句、表后结论句见 `steps/03-blocks.md`「短表与宽表」；禁用「X 与 Y 是两个容易混淆的词：」式元标签开场。

### 三层审查

润色按三个层级推进；高层问题不先定，低层改写会白做：

1. **篇章级**：全篇只保留一条成功路径，章节与小节顺序服务这条路径，无跳脱话题；开头交代读者做什么、完成后得到什么。
2. **段落级**：段落与段间条文见本文件「段落规则」与「段间：过渡句只在话题切换处」。
3. **句子级**：逐句过「七个质量维度」与「句子级病类清单」。

### 句序与段落形态

维度之外还有四条形态硬规则，读者正文（`content/**`）命中即改：

- **对象先行**：句子按「对象 → 名称 → 约束 → 出处」排；禁「代码把它写成」式把源码当施事的元叙述开场，也禁「因此记作」「写成 `class`」等以源码为主语的句子。对照见 `examples/01-language-scope.md`「元叙述开场与对象先行」。
- **正常语序**：推荐「主语/对象 + 谓语 + 宾语 +（必要状语）」，本书工程句优先「对象 → 名称 → 约束 → 出处」。改写信号：句首「关于…」抽空主语；「代码把它写成」式元叙述倒装；长定语链把施事压到句末；英文式「被…所…」堆叠；状语（时间/处所）乱插导致主谓隔断。与「对象先行」同向，不另开 kb。
- **连续纯散文上限**：同一小节连续 ≥3 段纯散文（中间无列表、代码块、图或表）即改「一句中心 + 列表/代码/图」；判定信号：删任一段其余仍成立、段间无承接。
- **禁小节导航**：正文「下一节／上一节」的禁令与豁免见本文件「段间：过渡句只在话题切换处」。
- **换算句版式**：换算的写法见 `steps/07-layout.md`「列表选择」。

六个成分和场景表不在本文件复述，见 `steps/05-sentences.md`。

代码块门槛（哪些实现值得出围栏）见 `steps/03-blocks.md`「代码块门槛」。

### 段落与句子

段落长度与中心句条文以本文件「段落规则」为唯一出处；单句 20/40 字与多动作拆句见 `steps/05-sentences.md`「句子规则」。本文件只保留句子级病类判法（见「句子级病类清单」）。

### 定段落：衔接与句段删改口诀

一段一个对象、段间衔接、概念负荷的判定依据见本文件「段落规则」；对每个段落依次检查：

- 删掉后影响当前任务吗？删除判据见本文件「凑字数禁令」。
- 段落是否同时承担两个以上动作？拆分判据见本文件「拆分判据」。
- 同一小节的连续同源代码围栏是否拆并，判定见 `steps/03-blocks.md`（对照见 `examples/03-excerpt-lead.md`「递进片段合并」）。
- 段落是否推进了两个互不依赖的并列对象？是就按「拆核四步（多核混段的拆段方法）」处理，判定见本文件「拆核四步（多核混段的拆段方法）」（对照见 `examples/03-block-after.md`「单段混并列对象」）。
- 段内是否有换说法复述同一机制的句子？是就删辅句或合并，判定见本文件「段内同义堆叠禁令」。
- 分句骨架是否成立？设计说明的角色链不合格情形见 `steps/05-sentences.md`「句内骨架」，都在定句子判为不合格。
- 散文里是否有「话题标签：解释」词条式冒号？是就改完整主谓句或真列表项，判定见本文件「散文伪标签冒号禁令」。
- 收束段是否把列表或围栏注释再讲一遍？次序与块后新信息见 `steps/03-blocks.md`（对照见 `examples/03-block-after.md`「块后复述注释」）。
- 树后或块后补写的新信息主语是否换成另一个对象？删除或下沉见本文件（对照见 `examples/02-structure-shape.md`「树后换对象收束句」）。
- 读者能否指出完成后要观察什么？任务可验证结果的判定见 `steps/02-structure.md`「六段块序列」。
- 正文、代码块和回顾是否重复同一句话？同义反复判定见本文件「凑字数禁令」。
- 新术语是否由当前动作自然引出？标题与论据的术语建立判定见 `steps/03-blocks.md`「小节标题与正文对齐」。

段落衔接、罗列短句成段与接口清单压缩段的判定见本文件；句间关系的写法见 `steps/05-sentences.md`「过简断裂禁令」，对照见 `examples/05-sentence-brevity.md`「罗列短句成段」、`examples/04-paragraph-opening.md`「接口清单压缩段」。

## 情况

### 情况：列表项和表格单元格

列表项、表格单元格不按散文段改。一条一项，不拆成多段，也不补过渡句。

### 情况：换算短句

同一换算关系的短句并列写不算同义堆叠，例如「3 秒等于 3000 毫秒」，保留。
