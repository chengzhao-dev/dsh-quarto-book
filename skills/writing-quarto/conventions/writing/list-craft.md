# 列表与加粗的使用规则

本文件管 `content/**/*.qmd` 与根 `index.qmd` 的列表选择与加粗使用：无序与有序的取舍、列表项结构与字数带、引导词加粗的边界、行列到下标换算条的写法（依据阮一峰[《中文技术文档写作风格指南》](https://github.com/ruanyf/document-style-guide)文本章，强制执行）。
段落形态见`conventions/writing/paragraph-shape/rules.md` 的知识文件，句子级判定见`conventions/writing/sentence-craft/sentence-frame.md` 的知识文件，章、节与段间衔接见`conventions/writing/section-flow/transition.md` 的知识文件。
`.agents/**` 与源代码注释不套列表形态；正反对照见`knowledge/cases/chinese-style/layout-list.md` 的知识文件。
通用降噪 how 见 `writing-quarto` 技能 `references/zh/writing-howto/tasks-structure.md`。

## 列表选择

目录列表后能用段落补一个遗漏的目录吗：不能，并列成员一次列全。列表选择规则：

- **无序列表**：并列概念、范围边界、要点枚举——各项之间没有先后或因果；代码块后的逐条讲解格式见`conventions/writing/paragraph-shape/rules.md` 的知识文件「段落规则」。
- **有序列表**：有先后顺序的步骤或链路——执行顺序本身就是信息（如配置 → 编译 → 测试 → 运行）。
- 列表项结构平行：起首用同类的词（都是名词短语，或都是动词短语），长度相近。
- **列表字数带**：同一列表各项保持视觉齐长，避免扫读节奏断裂。计量：引导词汉字数、冒号后汉字数（行内代码按标识符计）。失衡判定：冒号后最长 ≥ 最短 × 2，或引导词相差 ≥ 4。改写顺序：删长项多余中心 → 拆多中心 → 过短项按简洁边界补全 → 停止。豁免：出错原因/正确做法；有序步骤；着陆页卡片。列表齐长服从句段主规则，假拆禁令见`conventions/writing/paragraph-shape/rules.md` 的知识文件。
- 列表项起首用加粗引导词标记中心语，读者扫读时先看到分类再决定是否细读；关键词取同类词（如「显示状态面板」「读入坐标」），并按对象的发生顺序排列，读者扫读即得顺序与内容。
- 行为或规则枚举项用「**动词短语引导词**：完整句」格式：引导词命名本项的中心动作（如「**显示状态面板**」「**判定流程结果**」），冒号后保留完整中文句，写全动作、对象与结果。引导词是扫读索引，不替代句子信息，不为省字把冒号后压成电报短句（对照见`knowledge/cases/chinese-style/layout-list.md` 的知识文件）。
- 解释并列名称的引导词列表放在首次使用这些名称的代码块或目录树之前：读者先经列表认识每个名称，再看结构展示；禁止把解释压到块后，读者会带着未解释的名称读块。名称本身用读者可核对的具体形态（如「项目动态库」），不用模糊统称（术语依据见标识 `conventions/writing/chinese-quality.md` 的知识文件）。
- 并列成员一次列全：目录、组件等并列对象（含 `build/` 这类构建生成的目录）并入同一个引导词列表，先列全再展示目录树等结构；列表之后不用段落补列遗漏的成员（对照见`knowledge/cases/chinese-style/paragraph-opening.md` 的知识文件「角色总述段」）。
- 三项以上、或每项内含解释的信息优先成列表；只有两项且能写进一句的保留正文；只有一项时不设列表，写进正文（节内无代码块或列表承接时，整节收成一句）。
- **构造后的成员并列成列表**：同一句或同一段用顿号、逗号并列三个及以上数据成员、而且各项状态不同时，改成引导词列表；列表放在数据成员围栏**之前**，引导句不数个数、不把类名连写两次，也不写「成员写在该类里」——只把「构造之后的取值」引出来（如「`Game()` 默认构造之后，状态面板、当前用户、流程结果和操作记录是下面这样：」）。每一项恰好两句：第一句写成员是什么，第二句只写开局取值；第二句可以是「开局是空状态面板」这类状态句。枚举取值列表的位置见`conventions/writing/qmd-element-cases/code-cases.md`「三级标题最小模块」，本文件不重写；枚举成员的含义仍留在源码行尾注释，这里列的是构造之后每个数据成员的状态，不是把枚举成员再解释一遍。依据：C++ Primer 把名字和初值分开讲，阮一峰一句一事。
- **成员围栏前不列类型**：禁止「`board_` 用 `Board`，`current_player_` 用 `Player`」这种把类型再列一遍的句子——类型已经在围栏里。列表前的导语只点名要展开的维度，不把列表项里的取值先写一遍。
- **`private:` 不作正文话题**：围栏里可以保留源码的 ` private:`，因为片段必须和头文件逐字一致；「存放在 `private:` 下」「都在 `private:` 下」一类把访问说明符当话题的句子删掉，换成该 `##` 标题里的对象。
- **列表后直接进围栏**：成员取值列表的每一项先写这个成员是什么，再写开局状态；状态是枚举值时写出含义，不单写 `Player::kFirst` 或 `Result::kInProgress`。列表之后直接进数据成员围栏，围栏后不再放取值列表或同义复述段；成员的先后顺序、关联的结果类型等话题留到使用它们的函数小节再讲，不在成员节预告。围栏前的成员列表与随后成员注释的用词接近、围栏后不复述，见`conventions/writing/sentence-craft/sentence-frame.md` 的知识文件。
- **换算条（行列到下标的换算怎么写）**：
  - **点名**：第一次就写出是哪一种数。`cells_` 的数组下标、行号 `row`、列号 `col` 各用自己的名字。禁止「一个下标」「这个下标」「这次代入」互相指代。
  - **次序**：放在代码围栏和图之间的**同一段**，一句一个动作，后句接住前句的得数。第 0 行写出具体下标；下一句写第 `row` 行的起点；再一句写 `col` 从 0 加在这个起点上；然后一句只给出 `(1, 2)` 的三个数；最后一句只写算式和得数。禁止把跳过整行、列偏移、代入数字和得数写进同一句。
  - **不用列表**：后句用前句得数的乘加不是并列要点。列表仍只用于没有先后的并列，或配置、编译这种各自能做完的步骤。禁止「公式项：一句职责」。
  - **块位**：定义就是围栏里与源码相同的 `return` 行。`###` 导语仍是一句，点名函数和 `cells_` 的数组下标，并点明实现文件。原理段不重复 `static_cast`。图前一句点名得数是哪一个数组下标，不把图里已标的区间再念一遍。正文不另排 `$$` 或行内数学模式。

## 加粗使用

- 加粗只用于列表项或段首的引导词（中心语前置），标记结构，不强调情绪。
- 同一页加粗不成片：一段正文内至多一两处加粗，连续多句加粗等于没有重点。
- 标题不加粗（层级已由 `##`/`###` 表达）；行内代码与加粗不叠加在同一对象上。
