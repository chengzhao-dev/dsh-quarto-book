# 标题纵向承诺链与反例

纵向承诺链、改写反例与命名检查；分层与字数见 `conventions/writing/heading-fit/hierarchy.md`。

## 纵向承诺链

写章第 2 步（定结构）逐条对照，不新开第 10 步。检查顺序固定为下面 8 条；每条的要求都是「下一层必须兑现上一层对象」：

1. part 落地页那一句引言的范围等于该部分全部章的 YAML `title` 集合。根首页卡片不把示例项目收成其中几章。
2. 章引言里「这一章做什么」那一句的宾语等于 YAML `title` 的对象。引言点名的源文件必须是本章摘录实际来自的文件。
3. 每个任务级 `##` 的中心名词是章 title 对象的一部分。有 `class` 的章按「类型、成员变量、最重要的函数、其余重要函数」的次序排任务节，形状见`conventions/writing/chapter-structure/skeleton.md` 的知识文件「有 class 的章的任务节」，没有下一种内容就停在当前一种。
4. 每个 `###` 的中心名词能被父级 `##` 的宾语盖住，或是这一结果里的一步。恰好 2 个 `###` 时，`##` 导语一句点一个；3 个或 4 个时导语只写共同结果，不逐个点名。
5. `###` 那一句导语的宾语等于该 `###` 的对象。其下每个自然段的段首句保持这个对象；换对象就换 `###`，或把句子挪到已经拥有该对象的 `###`。导语点名标题里的对象，不用「这三种类型」代替还没写出的取值名。
6. `##` 下没有 `###` 是允许的，条件是这一节只有一个函数或一个结果。禁止为了「有下级」补出一个孤立 `###`。
7. 「本章回顾」里「下一章」后面的名字等于 `_quarto.yml` 中下一章的 YAML `title`，不写链接。回顾里的能力用本章 title 的对象。最后一章不写「下一章」。任务节不解释下一章才建立的术语。
8. 有 `class` 的章的任务节顺序，见`conventions/writing/chapter-structure/skeleton.md` 的知识文件「有 class 的章的任务节」。任务章的 `###` 顺序与 `src/run-build.sh` 的步骤顺序一致。目录章里「有几个目录」的句子与该节目录树的项数一致，口径见`conventions/writing/section-density/main-line.md` 的知识文件。

## 反例与改写

| 不佳 | 改写 | 原因 |
| --- | --- | --- |
| `工具链验证：从配置到运行` | `配置并运行最小工程` | 冒号后缀解释、动词不前置 |
| `构建定义：CMake 与 CTest` | `编写构建规则` | 冒号 + 专名堆叠 |
| `一键验证：running-build.sh` | `构建并运行` | 文件名进标题 |
| `认识阶段目录` | `查看工程包含的文件` | 未定义统称进标题 |
| `读懂探针源码` | `理解最小程序源码` | 术语黑话进标题；「读懂」改中性「理解」 |
| `看懂一次完整流程` | `流程规则` | 「看懂」是口语领会词，预设读者领悟；title 只留对象名（定稿） |
| `理解程序如何回应流程` | `明确流程约定` | 「回应流程」是读到正文才能懂的抽象说法；标题只用读者字面即懂的词 |
| `走完一次完整流程`（任务级 `##`） | `明确流程行为` | 「走完」承诺读者未执行的操作；改写同时避开与页面 title 共用核心动词（标题与内容匹配，规则见「标题分层」） |
| `查看编号目录` | `查看目录职责` | 未定义统称「编号目录」进 H2；宾语写具体对象，title 收尾后不再重复「示例项目」限定 |
| `对手只返回一次操作` | `选择一次操作` | 行为边界句当任务标题；「返回」是调用方视角的约束，不是本节让读者完成的动作 |
| `直接完成一次` | `在终端完成一次` | 「直接」是空强调；标题写明动作发生的位置 |
| `占格后仍写成新状态`（常见错误 `###`） | `同一格子写入第二次` | 「占格」是压缩黑话；症状句用完整平实说法 |
| `明确流程约定` | `流程规则` | 定语与中心语各自成词时用「的」切开，title 收尾为对象名后直接改写对象词（定稿，规则见「定语「的」的取舍」） |
| `定义状态面板与格子状态` | `数据存储` | title 收尾为对象名；本章重点是状态面板整体的存储，不以两个并列名词充当对象（用户决定） |
| `检查操作并判定终局` | `流程规则` | 「并」串两个动作中心；title 收尾为对象名（用户决定） |
| `构建、测试并运行终端流程` | `构建与运行` | 「并」串三个动作且混入构建与测试；「运行」下放到导语和「执行脚本」，title 只留对象（定稿） |
| `让电脑产生一次操作` | `Ai 操作` | 实现细节视角写的是对手内部动作；title 收尾为对象名「Ai 操作」（定稿） |
| `用一行 JSON 记下局面` | `局面快照` | 「一行 JSON」是实现手段、不宜进 title；title 收尾为对象名「局面快照」（定稿） |
| `得出胜负与平局`（任务级 `##`） | `终局判定` | 把胜负与平局硬拼成一个动宾，读者要多读一层；改写为交付对象「终局判定」，正文改说「操作后判定流程是否结束」（定稿，规则见「标题分层」） |
| `记下这一步用到的类型` | `流程类型` | 字数合规仍是步骤说明：动词「记下」、指示「这一步」、关系「用到的」把真正的对象「类型」挤到末尾；标题只留对象名（定稿） |
| `收进这一次` | `流程成员` | 过程动词「收进」与指示「这一次」是导语内容；改写为对象名（定稿） |
| `确定流程规则` | `流程规则` | 六字动宾把对象挡在动词后，目录里七行同一副骨架；title 收尾为对象名（用户决定） |
| `对应工程目录` | `工程目录` | 「对应」写关系不写交付；title 只留对象名（用户决定） |
| `实现数据存储` | `数据存储` | 「实现」是过程动词，对象自足（用户决定） |
| `完成一次操作` | `一次操作` | 「完成」是过程动词；保留「一次」，与二级「尝试操作」分开（用户决定） |
| `运行构建与运行` | `构建与运行` | 「运行」下放到导语与「执行脚本」（用户决定） |
| `加入电脑操作` | `Ai 操作` | 「加入」是过程动词，对象是「Ai 操作」本身（用户决定） |
| `输出局面快照` | `局面快照` | 「输出」是实现动作，对象是「局面快照」（用户决定） |

## 命名检查

改 title 不改文件名，除非主题边界或页面职责变化；改动后 `quarto render` 检查右侧目录与书内导航显示。页面 title 变化时，part 落地页的卡片标题与一句话描述同步改为新 title 的承诺，一句话仍概括该章交付，不沿用旧措辞。
