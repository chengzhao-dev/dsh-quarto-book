# 篇幅预算

本文件保留本书篇幅 token 预算的计数口径、分层上限与执行方式，作为 `content/**/*.qmd` 的体量标准；数字与 `verifying-content.py` 脚本保持同步。篇幅预算的起因是 示例章连环出现凑字数句、复述导航段和长注释片段：逐条句式规则拦得住具体坏句，拦不住「每一句都合规但整页过量」。

## 计数口径

估算 token = 中日韩字符数 × 1.5 + 其他字符数 ÷ 4。公式对主流分词器（GLM、Claude、GPT）取保守上界，只用于预算比较，不声称等于真实 token 数。

- **计入**：正文、标题、列表、表格、Callout 与链接锚文本。
- **不计入**：YAML frontmatter、链接目标、代码围栏（`{.cpp}`、`{.text}`、bash 等）全文、`{mermaid}` 图表全文、`{python}` 可执行单元全文。逐字代码与图表是机器寻址或视觉对象，读者扫读时整体跳过；token 预算度量的是读者逐句读过的正文当量。
- 代码与图表不计 token 不等于免检：它们仍受分层的行数上限与注释连续行检查约束（见「分层上限」）。
- **任何链接只计读者看见的锚文本，不计目标**（计数口径收紧）：`[锚]` 与 `(目标)` 组成的行内链接、`[锚][ref]` 引用式链接只计锚（锚内可含行内代码）；`<https://…>` 与裸 URL 计 0。GitHub 绝对链接的 URL 是机器寻址字符串，相对链接目标是页面地址，计入都会挤占正文预算；`verifying-content.py` 在计数前把整段链接替换为锚文本，再进入统计。
- 字符数按 Unicode 字符计：汉字、全角标点各算 1 个字符，归入中日韩一侧。
- 节导语口径：标题之后、首个代码块/列表/表格/引用/盒子（div）之前的连续正文；空行只分段，不结束导语。导语内链接只计锚文本。
- 引用块口径：连续 `>` 行合并为一块计数，链接只计锚文本；Callout 盒子（`:::`）不是引用块，按其自身层级计入所属分节。

## 分层上限

| 层级 | 上限 |
| --- | --- |
| 整章（frontmatter 外全部内容，只含计入部分） | 5000 token |
| 无标题引言（首个 `##` 之前） | 400 token |
| 每个 `##` 正文（不含代码和图表） | 400–1200 token；一章只有一个任务级 `##` 时该节 200–1200（下限只约束任务级，固定收尾不设下限）。区间按现有章节的正文当量定，低于下限合并或降级，不补空话 |
| 任务级 `###` 正文（不含代码和图表） | 有代码、表或图时下限 40 token，没有这些块时下限 120 token；上限 640 token |
| 「常见错误」的症状 `###`（不含代码和图表） | 60–240 token，不套任务级 `###` 的 120 下限 |
| 「自测问题」与「本章回顾」 | 不设新的上下限，本章回顾保持短 |
| 任务级 `##` 数量 | 通常不超过 4 个；按独立任务划分的原则见`conventions/writing/chapter-structure/skeleton.md` 的知识文件「六段块序列」 |
| 每个 `##` 下 `###` 数量 | 2 到 7 个；只有 1 个时并入 `##` 正文或补同级 |
| 普通代码块（围栏内内容行） | 20 行 |
| `{mermaid}` 图表块 | 40 行 |
| `{python}` 可执行单元（坐标图等） | 30 行 |
| 单个正文段落（代码块、表格、列表与标题之外的连续文本段） | 70–220 token；下限拦过短段（70 token ≈ 45 汉字当量），上限保持上限，写作舒适带 90–180。豁免下限：章引言段、`##`/`###` 节导语、紧邻代码/列表/表/图/盒子的单句块前导语、本章回顾、自测固定导语、Callout 盒子内段落；豁免类仍受 220 上限约束。低于下限的补法见`conventions/writing/sentence-craft/sentence-limits.md` 的知识文件「导语衔接」 |
| `##` 节导语（标题后、首个代码块/列表/表格/引用/盒子前） | 120 token 且 ≤2 句，不放代码围栏；设 `###` 的任务级 `##` 导语不另设下限，导语点名的句式见`conventions/writing/heading-fit/hierarchy.md` 的知识文件「标题分层」 |
| `###` 节导语（同口径，到首个盒子/代码块/列表前） | 80 token 且 ≤1 句 |
| 单个 `>` 引用块（连续引用行合并计） | 80 token |
| 代码片段内注释 | 写法与限额见`conventions/writing/qmd-element-cases/code-cases.md` 的知识文件「代码块 filename 标注」 |
| 一章 Callout | 不设下限；超过 8 个失败。写作时常例是 1 到 3 个 |

`{python}` 可执行单元应只含助手调用，绘图逻辑在共享助手库（见`conventions/rendering/coords-diagram.md` 的知识文件）；超出 30 行说明把绘图逻辑内联进了正文，属于结构违规。

数字依据：没有规定章节字数的权威国标（GB/T 7713《科技报告编写规则》只管结构格式）；技术写作社区实践是单节对应 3-5 分钟阅读（约 1500-3000 字）、单个功能模块 800-1200 字，超限优先拆分。按 CJK×1.5 换算，整章 5000 token 约合 3300 汉字的正文当量，是「一节一件事、一章四节左右」的自然边界。

## 执行方式

- `verifying-content.py` 第 3 查按上表逐文件、逐节、逐代码块、逐正文段落核对，超限即整体失败；限额调整只改该脚本的常量与本表，两处必须同步。
- 根目录 `index.qmd` 与 `content/<game>/index.qmd`（YAML 含 `body-classes: index-page`）是着陆页：短引言与卡片网格不是章节引言，只核对整章总量与代码块限额；着陆页不套用标题与骨架限制，见`conventions/writing/chapter-structure/skeleton.md` 的知识文件「六段块序列」。
- 任务级 `##` 数量、固定收尾不计入、`###` 的使用条件与首章「常见错误」豁免的结构判断，见`conventions/writing/chapter-structure/skeleton.md` 的知识文件「六段块序列」；数量口径以上表为准。
- 结构性规则（引言构成、`###` 数量）同时受`conventions/writing/chapter-structure/skeleton.md` 的知识文件「六段块序列」约束；本表提供量化兜底。
- 接近上限不是目标：预算是上限，内容仍按凑字数禁令与密度规则精简（见`conventions/writing/paragraph-shape/rules.md` 的知识文件「凑字数禁令」）。
