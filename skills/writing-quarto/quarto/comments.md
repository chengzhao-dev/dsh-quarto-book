# 注释：qmd、YAML、SCSS 与 CSS

> 速查：qmd 不写声明注释 · YAML 的 `#` 只写为什么 · SCSS 区域标记不可删 · 纯 CSS 只用 `/* */` · 不写 `///` 与 `@param`

本文件只管 Quarto 书里各类文件的注释写法。C++、CMake、shell 与 Python 的注释归项目自己的 C++ 流程，本技能不复述；正文与代码围栏的关系见 `steps/03-blocks.md`「内容块前后的闭环」。

## qmd 正文

- `.qmd` 不设文件头声明注释，也不写函数、参数或返回值注释。章节的任务、边界和读者对象由导语与二级标题承担，注释不重复。
- 正文里不保留被注释掉的旧段落、旧链接或旧围栏。要留历史就交给 Git，不在源文件里堆注释。
- 代码围栏逐字摘自源文件，围栏里的注释属于源文件；正文不解释这些注释，只补注释没写到的工程关系。
- 源文件的 `@file`、`@brief` 文件头不进读者正文。

## YAML

- `#` 只写「为什么这样取值」，不把键名翻译成中文，也不复述默认值。
- 能由 `_quarto.yml` 的键本身说清的，不写注释；同一取值只在一处解释，其他文件引用该处。
- front matter 里不写分隔线式注释（`# --- 标题 ---`）；标题就是 YAML 的 `title:`。
- 注释紧贴被说明的键，放在上一行；不放在行尾挤占宽度。

## SCSS

- Quarto 的三段区域标记必须原样保留，不能删除、改写或合并：

  ```scss
  /*-- scss:defaults --*/
  /*-- scss:rules --*/
  /*-- scss:mixins --*/
  ```

  区域标记是 Quarto 注入变量的边界，删掉后变量会落到错误的作用域。
- 变量分组用 `//` 单行注释；跨行说明用 `/* */`。
- 不写「这段设置颜色」式复述；注释只写取值理由或与另一处令牌的同步关系。

## CSS

- 纯 CSS 只接受 `/* */`；`//` 不是合法 CSS 注释，会被当成选择器或声明而报错。
- 不在 CSS 里写 `///` 文档注释、`@param`、`@return` 或 Doxygen 标签；这些是源码声明注释的写法，主题资产不用。
- 注释只解释「这条规则为什么存在」或「和哪个令牌联动」，不逐条翻译属性。
- 被禁用的规则用注释说明原因后直接删掉，不保留大段注释掉的旧样式。

## 编码与行尾

所有文本文件按 `quarto/encoding.md` 保存为 UTF-8 无 BOM、LF；`.bat` 与 `.cmd` 例外，用 CRLF。
