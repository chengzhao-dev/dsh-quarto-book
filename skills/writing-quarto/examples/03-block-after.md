# 中文案例：块后正文对照

代码块后正文分工的正反对照。

## 块后复述注释

代码围栏内的 `//` / `#` 注释已写明的意图，块后正文不得同义再讲一遍；块后只写注释没覆盖的新工程信息。以 示例章产物目录节为对照：

````text
不佳（块内注释写产物目录，块后换个说法再讲一遍）：
```{.cmake filename="CMakeLists.txt"}
# 可执行文件归入 build/bin，动态库与静态库归入 build/lib。
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/bin")
set(CMAKE_LIBRARY_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/lib")
set(CMAKE_ARCHIVE_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/lib")
```

可执行文件落 `build/bin/`，动态库落 `build/lib/`。源码树没有 `lib/` 目录，它是构建产物目录。

改写（删除翻译句，块后只留注释没覆盖的新信息）：
```{.cmake filename="CMakeLists.txt"}
（同一代码块，注释不动）
```

源码树不出现 lib/ 目录，它是配置时生成的构建产物目录。
````

判定信号：删掉块后第一句，代码注释仍完整回答「产物去哪」；块后正文只是把注释里的路径换成近义说法重写。块后允许的是新工程信息：谁读取这些产物、如何验证产物位置、与下一块的关系。

块后逐项复述成员清单是同一禁令的常见变体。以 示例章检查坐标后读写节改稿前为对照：

````text
不佳（类声明摘录后，块后把三个成员的行尾注释连讲一遍）：
`GetCellState` 读取格子状态，`PlacePiece` 放置元素，`IsFull` 检查状态面板是否已满。……

改写（成员含义已在行尾注释，块后展开流程需要并逐项映射到入口）：
一次流程需要状态面板做的事很有限：从空状态面板开始，之后每次操作写入一个数据项，画状态面板时逐格读出每个格子的状态，判定终局要检查三连和下满，用户输入的行列也要先检查。

空状态面板由 `Board()` 默认构造出来，其余的需要由四个入口分别接住：操作写入交给 `PlacePiece`，格子读取交给 `GetCellState`，下满判定交给 `IsFull`，行列检查交给 `IsInRange`。外界碰不到数组，也算不出下标。下一章的 `Game` 经它们访问状态面板，终端程序经 `Game` 对弈。

读取和写入都先检查坐标，两种失败分开处理：出界坐标说明调用方算错了，读取直接抛出 `std::out_of_range`，没有可返回的格子。格子被占用在流程里随时会发生，写入返回 `false`，状态面板保持不变，调用方再选别的格子就行。完整的 `@param`、`@returns`、`@throws` 注释写在 `state.h` 里。
````

块后把函数契约拆成条款列表，是同一禁令的另一种写法。以 井字棋 落子校验节改稿前为对照：

````text
不佳（头文件注释已写清三个拒绝条件，块后仍逐条复述并解释返回值）：
`PlaceCell` 返回 `true` 表示放置成功，返回 `false` 表示拒绝。

- **放置被拒**：返回 `false`，棋盘保持原样。坐标越界或格子已被占用时换一个坐标；传入的类型是空格子时换一个非空类型。
- **放置成功**：返回 `true`，新棋子当场能从 `GetCellType` 读回来。

改写（注释覆盖契约，块后只留读者要做的判断）：
`PlaceCell` 用返回值报告结果，三种拒绝都不改棋盘；调用方检查返回值就能决定下一步，不必比较落子前后的棋盘。
````

判定信号：块后列表项与 `@param`、`@return` 一一对应，删掉列表注释仍完整；返回值语义被正文重复解释两遍以上。允许保留的是注释没写的调用方策略：谁该重试、谁该结束、界面要显示什么。

## 块后交代注释布局

块后正文不交代「类说明没有逐个列出成员」「每个成员的用法写在行尾注释里」这类注释安排：它讲作者怎么组织注释，不讲程序做什么。读者需要的事实直接陈述。以 井字棋 棋盘类型节改稿前为对照：

````text
不佳（块后说明注释怎么分工，没有程序信息）：
类说明没有逐个列出成员的用途，只说清这个类管什么、棋盘为什么可以随便拷贝。每个成员的用法写在各成员自己的注释里，两处不重复。

改写（整句删掉，前后段落已经交代了棋盘做什么）：
（无块后段落）
````

判定信号：句子主语是「类说明」「注释」「行尾注释」而不是程序里的对象；删掉后读者对代码的理解不变。

## 块后悬空指代

块后第一次提到代码块里的常量怎么写：点名标识符，不用「这 N 个 X」。块后段落首次提及围栏里的实体时点名标识符；先行词只出现在代码围栏里、不在任何句中时，「这 N 个 X」「它们」式省称没有可依的先行词，计数指代还容易盖错范围。条文见 `steps/03-blocks.md`「内容块前后的闭环」。以 示例章定义坐标范围节改稿前为对照：

```text
不佳（「这三个常量」开场，先行词只在上方围栏里；三个常量里只有 kRows、kCols 约束行列取值，kCellCount 给的是总数）：
行列的取值范围由这三个常量给出：`row` 和 `col` 都是 0 到 2，用户输入的数字直接成为 `Position` 的 `row` 和 `col`。后续检查坐标、换算下标和写出数组长度都引用它们，调整状态面板尺寸只需改这几个数字。下面的图标出可用的 `(row, col)`。

改写（首次提及逐一点名，先讲位置为什么需要行列成对；下游引用独立成段，桥接句单独收尾）：
数据项的位置是行和列。行从 0 数到 `kRows - 1`。列从 0 数到 `kCols - 1`。这块状态面板上都是 0 到 2。

`kCellCount` 由 `kRows` 和 `kCols` 相乘得出，状态面板尺寸因此在代码里只有一处出处。坐标检查、下标换算和数组长度用的都是这三个常量。想调整状态面板大小，改的只是行数和列数两个数字，第三个常量随之更新，用到尺寸的代码不必跟着改。
```

判定信号：块后第一句的主语是「这 N 个 X／它们／这几个 X」，而围栏是先行词的唯一出处；计数指代盖错范围或把派生量与约束量并列；常量、字段、记法、输入的关系链拆散在多句里，没有一句贯穿。

## 块后并列事实段拆引导词列表

以 首章查看终局输出节改稿前为对照。块后一段串起三个以上并列区域的事实（版式、显示规则、结果行），句句完整却仍是多中心段，各项对应输出的哪一部分全靠读者自补；三项以上优先成列表（规则见 `steps/07-layout.md`「列表选择」）：

```text
不佳（块后一段四句各讲一个区域，顺序与对应关系全靠读者自补）：
行列号印在状态面板上，和用户输入的数字同一套：列号 `0`、`1`、`2` 排在状态面板上方，分别对准三个数据项的中心，行号写在左边框的左侧。用户按状态面板上印的数字输入行列，无需换算。没有字母的格子是尚未操作的数据项，已操作的数据项显示 X 或 O。末行的 `流程结果：甲方获胜` 报告流程结果，平局与 乙方获胜也用这一行显示。

改写（一句引言说出阅读动作，引导词列表按输出阅读顺序排列）：
从上往下读这段画面，依次会看到三处信息：

- **行列标记**：列号排在状态面板上方，行号写在左边框左侧，和用户输入的数字同一套。
- **数据项**：上图中没有字母的格子是尚未操作的数据项，操作后格子里显示 X 或 O。
- **结果提示**：末行的 `流程结果：甲方获胜` 报告获胜方，平局与 乙方获胜也用这一行显示。
```

判定信号：块后一段出现三个以上句号句、各句对象可与并列区域一一对应、删任一句其余仍成立 → 拆引导词列表并按阅读顺序排列；引导词取输出中的区域名。两项且能写进一句的保留正文。

## 单段混并列对象

同一段只推进一个对象；对象切换必须新起段，必要时用一句关系衔接。以 示例章运行时库查找与测试依赖为对照：

```text
不佳（一段先讲 RPATH、再讲 GoogleTest 拉取，两个互不依赖的对象挤一段）：
$ORIGIN 表示可执行文件所在目录，查找位置随文件移动。GoogleTest 由 FetchContent 在首次配置时拉取，版本固定为 v1.17.0。

改写（对象切换新起段，新段段首点明关系）：
$ORIGIN 表示可执行文件所在目录，查找位置随文件移动。

测试依赖是另一处来源：GoogleTest 由 FetchContent 在首次配置时拉取，版本固定为 v1.17.0。
```

判定信号：段内出现两个互不依赖的主语（库查找与测试依赖），删掉任一句另一主语仍成立；切换处没有过渡句就硬切。配套列表只服务本段对象，不得跨对象拼装列表项。类型定义和后一步使用它的函数是两个对象，分块分段；只有紧邻常量与其直接使用行才放在同一个围栏（见 `examples/03-excerpt-lead.md` 的「递进片段合并」）。

## 指代与验收

已知对象名称时直接复用对象名（`这个程序` → `Hello, World! 示例程序`）。验收句指向可观察结果：`看到 Hello, World! 后，就完成了本章的实践目标`，不写 `本章就完成了`。

悬空指代与讲义口：

```text
不佳：划定了这条路线的边界。……与这条流程直接相关的只有两个文件……，下面分别精读。
改写：先看清工程确认了工具、项目内容与分层实现。……src/main.cpp 与 CMakeLists.txt 是配置与运行的两个关键文件。
```

```text
不佳：本章配置和运行的对象就是引言中的最小工程目录……代码块标题使用短文件名……避免标题栏被深层路径挤满：
改写：最小工程目录如下，树内注释标出各文件职责。src/main.cpp 与 CMakeLists.txt 是配置与运行的两个关键文件。
```
