# 中文案例：摘录导语对照

摘录导语与递进围栏形态的正反对照。

## 摘录链接密度

章引言的源文件链接一章挂几次：挂一次。正文写 state.h 这类源文件名，链接怎么挂：章引言挂一次，正文复提用裸文件名。以 示例章改稿前为对照：摘录块每节重新挂一次同文件链接，读者在正文里反复撞见同一串 URL，阅读断点全落在链接上。链接分三层：章引言是全章介绍位，首次点名源文件并挂链接（示例章引言）；摘录围栏的短 filename 自明文件；正文复提用裸文件名。

```text
不佳（同节两个摘录导语各挂一条同文件链接）：
先在 [state.h](…) 里声明状态面板的尺寸常量……
每个数据项保存 [state.h](…) 中 `CellState` 的三种取值之一。

改写（每章每条仓库路径只在章引言保留一条，供片段校验解析源路径；后续导语与正文用行内代码）：
先在 [state.h](…) 里声明状态面板的尺寸常量……
每个数据项保存 `CellState` 的三种取值之一。
```

```text
不佳（章引言不挂链，正文又逐节重挂同文件链接）：规则在 state.h 和 state.cpp。……每个数据项保存 [state.h](…) 中 `CellState` 的三种取值之一。
改写：规则写在 [state.h](https://github.com/your-org/your-book/blob/main/src/include/state.h) 和 [state.cpp](https://github.com/your-org/your-book/blob/main/src/state.cpp) 里。……每个数据项保存 `CellState` 的三种取值之一。
```

判定信号：同一章内同一 URL 的 blob 链接 ≥2（`verifying-content.py` 判失败「同章重复文件链接」）；或摘录导语为「告诉读者文件在哪」挂链，而非预告块内内容；或正文复提源文件仍挂着链接。

## 摘录导语只报出处

导语点名读者要在块内观察的代码标识符，再给出处；只报出处的句子让读者把「行列坐标」这类中文概念对不上围栏里的名字。条文见 `steps/03-blocks.md`「内容块前后的闭环」。以 示例章定义坐标范围节改稿前为对照：

```text
不佳（导语只报出处，句中没有任何块内标识符）：
状态面板的尺寸常量和定位格子的行列坐标都定义在 state.h 里：
（围栏：kRows / kCols / kCellCount / Position）

改写（导语点名块内对象，再给出处）：
状态面板多大是示例项目的规则，尺寸常量 `kRows`、`kCols` 和 `kCellCount` 与格子的行列坐标 `Position` 都定义在 state.h 里：
```

判定信号：导语句里没有一个块内将出现的标识符；「行列坐标」这类中文概念在块内对不上任何标识符；删掉围栏后导语仍完整成立——出处句不依赖块内容。

同节的另一处省字（并列量名省掉被计量的对象，条文见「简洁边界」）：

```text
不佳（「行数」「列数」写出了数的是什么，「总数」没写数的是什么）：
状态面板尺寸由行数 `kRows`、列数 `kCols` 和总数 `kCellCount` 确定：
（围栏注释写明这是数据项总数，引入短语却是光秃的「总数」）

改写（量名在引入短语里带全对象，与围栏注释同一个说法）：
数据项总数 `kCellCount` 等于 `kRows` 乘 `kCols`。
```

## 逐条释义代替动机

块后把成员逐个介绍一遍怎么改：删掉逐条释义，换成边界设计加动机。讲解性正文（摘录导语与块后项目解释）要给出设计动机，不是把成员清单散文化重写；`X` 做 A、`Y` 做 B 式的连续释义只回答「是什么」，删掉后读者照样不知道为什么这样设计。条文见 `steps/03-blocks.md`「内容块前后的闭环」。以 示例章检查坐标后读写节改稿前为对照：

```text
不佳（四个成员逐条释义，句子骨架只是行尾注释的排列）：
`Board` 对外的入口都集中在 `public:` 下：`IsInRange` 检查坐标，`GetCellState` 读取格子，`PlacePiece` 放置元素，`IsFull` 判断状态面板是否下满。

改写（导语只留边界设计与四个入口名，各入口接住的流程事务由块后映射）：
`Board` 把存储和换算收在 `private:` 下，`public:` 下只留下四个入口：`IsInRange`、`GetCellState`、`PlacePiece` 和 `IsFull`。
```

判定信号：连续两个以上「`标识符`＋动词短语」释义，每个短句都能在围栏或行尾注释里直接读到；全段删掉后读者不知道这些入口为什么长这样。为绕开释义把用途压成并称（「一读一写」）、或省掉从句主语（「报告是否下满」说不出什么满了）同样违规——名字与动作的对应要读者自补，补错无检查可拦。改写不再逐条释义：导语留边界设计与入口名，各入口接住哪件流程事务由块后按需要展开映射（见 `block-after.md` 的「块后复述注释」）。

## 多代码块一句导语

同一小节内出现多个同源围栏时，先看是否是紧邻常量与其直接使用行：只有这时才放在同一个围栏；类型定义和后一步使用它的函数是两步，分成两块，对照见「递进片段合并」。其余多围栏一律适用本条：每个块前一句完整导语（对象 + 谁调用或做什么）→ 围栏；禁止块前半句，块后按「三级标题最小模块」收束。

````text
不佳（同一常量拆成块前半句 + 块后半句）：
状态面板固定为 3 行 3 列，尺寸来自公共头里的一对常量：

```{.cpp filename="state.h"}
…
```

终端程序打印状态面板、测试遍历数据项，都用这对常量圈定范围。调整状态面板规模只改这一处。

改写（块前一句含使用方，块后不再补半句）：
状态面板固定为 3 行 3 列，终端程序打印状态面板和测试遍历数据项都读 state.h 里这对常量，调整规模只改这一处：

```{.cpp filename="state.h"}
…
```
````

判定信号：块后第一段删掉后，块前导语仍缺「谁调用」；或块后只是把块前半句补全。合并后一句须满足简洁边界（见 `steps/05-sentences.md`「简洁边界」），不得电报省略。

## 递进片段合并

同一小节的连续同源片段不再整链合并：只有常量紧接着被下一行使用时才放在同一个围栏；类型定义和后一步使用它的函数是两步，即使函数用到该类型也分成两块，每块各留一句完整导语，中段导语不点名后块才出现的符号。以 示例章状态面板尺寸与位置节改稿前为对照：

````text
不佳（常量、坐标类型与判定函数拆成三个连续同源围栏，各配半句导语；首句已点名 IsInRange，中间块里看不到它）：
状态面板固定为 3 行 3 列；终端程序打印状态面板与测试遍历数据项都读公共头这对常量，调整规模只改这一处：

```{.cpp filename="state.h"}
inline constexpr int kRows = 3;
inline constexpr int kCols = 3;
```

Position 携带从 0 起算的行列坐标，越界由 IsInRange 判为非法：

```{.cpp filename="state.h"}
struct Position {
  int row;
  int col;
};
```

提交动作前的坐标检查都经过同一个入口：

```{.cpp filename="state.h"}
constexpr bool IsInRange(Position position) {
  return position.row >= 0 && position.row < kRows && position.col >= 0 &&
         position.col < kCols;
}
```

改写（三块各配一句完整导语，中段不再引用后块才出现的符号；「并为一个围栏」的旧改法已废除，合并只保留给紧邻常量与其直接使用行）：
状态面板固定为 3 行 3 列，`kCellCount` 由 `kRows` 乘 `kCols` 得出，三个常量都定义在 state.h 里：

```{.cpp filename="state.h"}
（kRows/kCols/kCellCount 按源序摘录为一个围栏）
```

数据项的位置是行和列。行写入 `Position` 的 `row`。列写入 `col`：

```{.cpp filename="state.h"}
（Position 结构体）
```

提交动作前的坐标检查都经过同一个入口，`IsInRange` 比对行列与常量给出的范围：

```{.cpp filename="state.h"}
（IsInRange 实现）
```
````

判定信号：导语点名了后块才出现的符号，或同一常量的讲解被拆成块前半句加块后半句。类型定义与其使用函数分成两块不是违规；禁的是整份头文件或整条调用链贴进同一个围栏。拆块豁免清单见 `steps/03-blocks.md`「内容块前后的闭环」。
