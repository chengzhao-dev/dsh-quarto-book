# 中文案例：过简与压缩句对照

过简、压缩与罗列句段形态的正反对照。

## 压缩黑话与过短句

读者正文写可观察对象与完整主谓句，不写压缩隐喻和缺成分的省略句；禁用词见 `steps/06-wording.md`，正向语气标准见 `steps/06-wording.md`。判定口诀：读者能从句子里指出磁盘上的文件、屏幕上的输出或可执行的动作，这句才合格。

```text
不佳（压缩隐喻当主语，读者对不上现实对象）：
本章固定状态面板尺寸、位置与状态外壳这三组定义。
CLI 打印与测试遍历数据项都消费这三个定义。

改写（写具体对象与完整动作）：
本章固定状态面板尺寸、格子坐标与状态码这三组公共定义。
终端程序打印状态面板、测试遍历数据项，都读这三个定义。
```

```text
不佳（无先行词的「闭环」与「地基」）：
AI 才有稳定的地基。本章设计终端双人闭环与分层验收。

改写（写可核对的前置条件与流程）：
规则接口稳定后，AI 才有可以调用的入口。
本章设计终端双人流程的完整流程与分层验收。
```

```text
不佳（「执行纪律」「逐层落地」这类不可核对的抽象词）：
下一章给出目录门槛与执行纪律。各章通过验收后逐层落地。

改写（写具体约束与具体动作）：
下一章给出目录门槛与验收顺序。
各章实现通过验收后再进入下一章。
```

```text
不佳（编写者视角的元表述当主语，新人还原不出谁对谁做什么）：
摘录里的标注服务于调用方：[[nodiscard]] 表示忽略返回值就是逻辑错误。

改写（点名属性名与可观察后果）：
除构造函数外，每个函数都标注了 [[nodiscard]]：忽略返回值时编译器会给出警告。
```

判定信号：把隐喻词删掉后读者说不出这句话约束什么、产出什么，或主语是缩写、谓语缺对象（「CLI 打印」「CLI 报错」）。编写者之间的沟通文档（.agents/**）不受本条限制，但不得把这类写法教成读者的正例。

## 过简断裂段

以 示例章「查看流程接口」节导语改稿前为对照。与「罗列短句成段」的分工：那条打句号清单，本条打逗号切断与过简两句各丢一个事实——每截单看都合法，段却不成篇，读者要自己补「因为／所以／其中」（规则见 `steps/05-sentences.md`「过简断裂禁令」与「概念负荷」）：

```text
不佳（四截并列：对象 → 文件位置 → 入口个数 → 私有存储，截截换新主语、新事实）：
一次流程落在 `Game` 上，定义在 state.h 里。`public:` 下留五个入口，数据存储收在对象内部：

改写（主概念只留类 Game；文件与「对外入口／内部状态面板」作次要展开，去掉「五个」统计）：
一次流程由 `Game` 编排。它把状态面板和流程进度收在对象内部，对外只露出查询与操作入口；声明在 state.h。
```

```text
不佳（ai.h 不做的事与 `Ai::Choose` 的行为两截并列，无回指）：
ai.h 不打印状态面板，也不读取键盘。`Ai::Choose` 读当前流程，返回当前用户的一次合法 `Move`。

改写（定稿：正文只写声明操作的公共接口，否定边界让给常见错误节）：
`ai.h` 声明操作的公共接口：`Ai::Choose` 读当前流程，返回当前用户的一次合法 `Move`。
```

判定信号：逗号、句号后的分句引入新主语或新的行内代码标识，且无回指词、无承接词；删掉该分句后上下文照样成立，说明它只是被并列甩出的另一截。改写时收敛主概念，用给定信息衔接次要展开；时序句「进入目录，执行入口」合法（后一分句接住前一分句的动作）。

ai.h 那组的改写只解决过简断裂；定稿进一步把「不打印、不读取」的否定边界让给常见错误节，正文只写「`ai.h` 声明操作的公共接口：`Ai::Choose` 读当前流程，返回当前用户的一次合法 `Move`。」（否定式预告见 `steps/05-sentences.md`「句子规则」）。

## 罗列短句成段

以 首章「观察一次流程」改稿前为对照。三个短句各自成立、句间无衔接，读起来像清单；分号还把显示状态面板与拒绝非法输入两件事串进一句（规则见 `steps/04-paragraphs.md`「罗列短句成段禁令」）：

```text
不佳（三个独立短句堆成一段，句间无衔接；分号串两个中心）：
两名用户轮流在 3×3 状态面板上操作。程序显示状态面板并提示下一位用户；输入越界、占用或格式错误时说明原因并保持状态面板不变。

改写（一个中心主题，衔接词组织成连贯句，分号改写）：
两名用户轮流在 3×3 状态面板上操作：程序每一轮都先显示状态面板，再提示接下来轮到谁。行列越界、格子已被占用或格式错误时，程序会说明原因并保持状态面板不变，要求重新输入。
```

判定信号：段内句子逐句可删、互不引用；句间没有承接、因果或时序词；删掉分号后的任一分句中心仍成立。真正并列、需要扫读的项改用列表，不做伪连贯。

## 过简实现围栏

值得出围栏的是类型布局、多步或非显然控制流、与图核对的公式实现；单次比较或直接 `return` 的平凡实现不出围栏（门槛见 `steps/03-blocks.md`）。以 示例章检查坐标后读写节改稿前为对照：

```text
不佳（为证明「源码有此函数」贴出一次比较的平凡实现）：
（围栏：IsInRange 的两行 return 比较）
`Board` 提供 IsInRange 检查坐标是否落在状态面板内。

改写（删实现围栏，改为入口列表 + 失败策略列表）：
`Board` 的 `public:` 下只留四个入口：`IsInRange`、`GetCellState`、`PlacePiece` 和 `IsFull`。
读取和写入都先检查坐标，两种失败分开处理：出界坐标说明调用方算错了，读取直接抛出 `std::out_of_range`；格子被占用时写入返回 `false`，状态面板保持不变。
```

判定信号：围栏内是单次比较、单条 `return` 或一行委托；围栏只为证明函数存在；删掉围栏后正文信息不减少。
