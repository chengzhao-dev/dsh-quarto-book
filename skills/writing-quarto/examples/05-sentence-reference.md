# 中文案例：指称与并列句对照

指称、数量词与并列搭配的正反对照。

## 定结构与定句子：代词不能代替未写出的对象

条文见 `steps/05-sentences.md`「代词不能代替未写出的对象」；题干禁令在定结构改（对照见 `steps/02-structure.md`「六段块序列」），节首前指在定句子改。两个对照都拿整篇 qmd 验：题干合上书单独可读，节首对象名同句可核。

**定结构（示例章第 5 题，题干代词没有说出对象）：**

```text
不佳（「这个个数」没说出是数据项的个数，「哪个常量」没说出候选）：
这个个数写在哪个常量里？

改写（题干写出对象与候选，用「还是」问）：
数据项的个数写在常量 `kRows`、`kCols` 还是 `kCellCount` 里？
```

**定句子（示例章「记下流程数据」节首，「这些」把后文两个三级标题才展开的内容提前捆成一包）：**

```text
不佳（「带什么」缺宾语，「这些数据」要等后面的 ### 才对得上）：
先记下这一步是谁下的、带什么，以及这一步写下没有、整局进行到哪。再把这些数据收进这一次。

改写（同句列出四项对象，不用代词往下指）：
操作前先记下下子的用户、操作的格子、状态面板有没有写入、流程有没有结束。这一节先列出流程类型，再写出流程成员。
```

**定句子（示例章「坐标与格子状态」节导语，链接文字已是章节名，导语又用「这一节」起头并加「的画面」）：**

```text
不佳（导语第二句用「这一节」代替已写出的对象，链接后还挂「的画面」）：
在流程规则的画面里……这一节先写出行列坐标。

改写（只用衔接词接住上一句已写出的名词，不加「的画面」）：
在流程规则里，用户用行列数字选中一个数据项。先写出行列坐标，再区分格子状态。
```

判定信号：题干里出现「这个／哪个／哪些」且题面单独拿出来答不了；节首句以「这些／这个／这一步」作话题而同句列不出对象名；代词的所指要等后面的 `###` 或代码围栏才对得上。

## 定句子：数量词对着下一块点名

条文见 `steps/05-sentences.md`「一次对话」。三个对照都来自数量词与紧挨名单对不上的旧稿：成员与类型的接线句、`kPlaced` 的两种结局、`StateTest` 的场景数。

**成员与类型（示例章「流程成员」节首）：**

```text
不佳（「这些类型由四个数据成员使用」：数量词算的是成员，主语却是类型，下一块列的也只是成员声明）：
这些类型由 `Game` 的四个数据成员使用，都声明在 `state.h` 的 `private:` 下，初始状态写在声明处：

改写（数量词对准成员，类型跟着各成员点名，`PlaceResult` 明确不是成员）：
四个数据成员都在 `state.h` 的 `private:` 下，`board_` 用 `Board`，`current_owner_` 用 `Player`，`outcome_` 用 `Result`，`move_log_` 按顺序保存 `Move`：
```

**`kPlaced`（示例章「尝试操作」块后）：**

```text
不佳（「两种结局」之后按动作续写，两个返回值各自的含义要读者自己补）：
调用方从返回值就能分辨两种结局：按 `kPlaced` 继续下一手，按 `kRejected` 让同一个用户重试。

改写（两个返回值各自说清含义与后果）：
调用方从返回值就能分辨两种结局：`kPlaced` 只表示已经写入，流程仍是进行中才轮到另一名用户；`kRejected` 表示没有写入，仍是同一名用户重试。
```

**`StateTest`（示例章「核对结果」）：**

```text
不佳（「覆盖四类场景」，下一块列四类，源码里还有占用、出界与历史顺序的测试）：
其中 `StateTest` 覆盖四类场景：
- 拒绝不是当前用户的操作。
- 按行、按列和两条对角线获胜。
- 状态面板下满时记平局。
- 获胜后再操作被拒绝。

改写（不写数量词，列出实际有的场景）：
`StateTest` 覆盖这些场景：
- 拒绝不是当前用户的操作。
- 按行、按列和两条对角线获胜，含最后一子同时三连。
- 状态面板下满且没有三连时记平局。
- 流程结束后、数据项被占用或坐标出界时操作被拒绝。
- 历史按操作顺序保存。
```

判定信号：句中数量词或「这些」的所指在下一块数不出来；数量词算的对象和下一块列的对象不是同一类；序数给已经出现过的类型、成员、入口或步骤重新编号。

## 主语跳变与并列搭配不当

并列成分里顿号套顿号怎么改：降层级，一级并列只用顿号。句子级语法判为不合格的总纲见 `steps/06-wording.md`；本案例收并列施事失配、受事与施事混排、顿号层级嵌套三类。以 示例章本章回顾、示例章章引言与 示例章测试场景句改稿前为对照：

```text
不佳（并列三项共用「说明」，后两项主语从「数据项」跳到省略的施事）：
下一章实现数据存储，说明数据项如何保存、换算下标，以及拒绝无效访问。

改写（回顾的预告只留一件事，三个细节由下一章的节标题承载；并列时保持同构的原则见第三组）：
下一章实现数据存储。
```

```text
不佳（冒号前施事是「状态面板」，并列里「定位格子」的却是行列坐标，「保存状态」也省掉了谁的状态）：
这一章只处理状态面板：它如何定位格子、保存状态、换算数组下标，以及拒绝无效访问。

改写（受事主题句，四项统一由小节正文交代）：
这一章只处理状态面板：数据项如何定位、状态如何保存、下标如何换算，以及无效访问如何拒绝。
```

```text
不佳（外层四类场景用顿号并列，内层「按行、按列」又是一层顿号，大小并列混在一层）：
覆盖四类场景：拒绝不是当前用户的操作、按行、按列和两条对角线获胜、状态面板下满记平局、以及获胜后再操作被拒绝。

改写（外层逗号、内层顿号；条件补「时」让假设显形）：
覆盖四类场景：拒绝不是当前用户的操作，按行、按列和两条对角线获胜，状态面板下满时记平局，以及获胜后再操作被拒绝。
```

判定信号：并列各项还原主语后施事不同一；后续分句主语换人且无过渡；「主＋是＋宾」两侧概念不对当（目录是程序、章保存格子）；顿号套顿号分不清大小并列（GB/T 15834—2011：大并列用逗号、小并列用顿号、「以及」前用逗号）；承前省略省到指代不明（《语法修辞讲话》：省略以仍能明确表意为界，跨句换施事即补名词）。

## 处所状语配错谓语

以 示例章章首改稿前为对照。四句章首把职责与位置并列甩开；并句时若把「在头文件和源文件里」留在「记住」上，状语就配错了谓语——记住的是元素，不是头文件。三档并法见 `steps/05-sentences.md`「同档并句」：

```text
不佳（四句章首：职责、承接、机制、位置被句号甩成并列）：
`Board` 记住状态面板上已经落下的元素。[工程目录](…)已经把这份头文件放进项目动态库。它保存九个数据项，先检查坐标再写入。接口与实现在头文件 state.h 和源文件 state.cpp 里。

否决（并句不改状语错配：「在头文件和源文件里」修饰「记住」）：
`Board` 在头文件和源文件里记住已经落下的元素。

改写（同档并句：职责一句、机制一句、位置一句）：
`Board` 记住状态面板上已经落下的元素。保存九个数据项，写入前检查坐标。把声明放在项目动态库的头文件 `state.h`，把实现放在源文件 `state.cpp`。
```

判定信号：处所状语「在……头文件或源文件……里」后 12 字内出现「记住」「保存」或「选出」，判为状语配错谓语；同对象相邻两句被句号切开且异档混排同判。改写时位置句的谓语用「放进」，职责留前一句。
