# 中文案例：句式与分句骨架

句式成分、分句骨架与拉链句的正反对照。

## 六个成分与场景句式

- 不佳（连谓，两个动作写在一句）：先手操作并切换后手。改写：先手在这一格落下元素。后手接着下。
- 不佳（兼语）：规则让状态面板记下这一格。改写：状态面板记下这一格。
- 把字句只用于处置已知对象并写出结果：先手把这一格落成 X。
- 存现句只用于处所里有什么：状态面板上有九个格子。
- 是字句只用于判断类别：这一格是空位。
- 零形回指只用于话题未换的下一句：先手在这一格落下 X。接着轮到后手。

## 句内骨架：先依据后选择

以 示例章「用数组存放九个数据项」的块后段为对照。旧改写只去掉词条式冒号和同义堆叠，分句骨架仍不合格：第一句先给代码决定，第二句才补依据；「是示例项目规则的一部分」只贴类别；「正好装下」把上一句再说一遍；「由 `ToFlatIndex` 完成」提前交接下一小节专讲的对象（规则见 `steps/05-sentences.md`「句内骨架」）：

```text
不佳（先决定后补依据，类别句不改下一步，复述句与交接句多余）：
`cells_` 的长度取常量 `kCellCount`。状态面板一共九个格子，这个数量是示例项目规则的一部分，从开局到终局不变，编译期就能确定。

长度写进类型后，`std::array` 正好装下全部九个数据项。读写某个格子时，还要把行列坐标换成数组下标；换算由紧接着的 `ToFlatIndex` 完成。

改写（事实和约束一句，因此的选择一句；删类别句、复述句与交接句，两段并一段）：
状态面板一共九个格子，数量从开局到终局不变。这个数量编译期就能确定，所以 `cells_` 用 `std::array` 存放，长度取常量 `kCellCount`。
```

判定信号：设计说明句里选择先于依据，读者要把因果倒过来才能读；「是规则的一部分」这类只贴类别、不改变下一步的分句；删掉关系词后读者仍要自己补因果；「正好装下」在同段复述同一核；后续小节专讲的对象在本段末尾写成「由 X 完成」。

## 拉链句

一句话把两组对象两两配对，删掉任一配对、剩下的仍能单独成立，原句就是拉链句：读者要按顺序把左组一一配到右组，且两个配对共用同一个判据（判定与三条改写见 `steps/05-sentences.md`「拉链句」；步骤链、同物两处与回顾不按拉链判）。以 示例章章首改稿前与 示例章改稿前为对照：

```text
不佳（一句两组配对：「数据项在哪、上面是什么」分别交给两个类型；还提前点了后文才定义的类型名，并用「写进代码时」元叙述）：
在[确定流程规则](01-rules.qmd)的画面里，用户用行列数字选中数据项，落下的元素显示为 X 或 O。写进代码时先把两类信息分开，数据项在哪、上面是什么，分别交给 `Position` 和 `CellState`。

改写（两条改写都触发时先「推迟」：章首只留顺序的两句白话，不点类型名；类型名留在各自小节的块前导语）：
在[流程规则](01-rules.qmd)里，用户用行列数字选中一个数据项。接着再记这个格子上显示的元素。
```

```text
不佳（「各说一层」把 PlaceResult 与 Result 的分工配进一句，删掉任一配对另一照常成立）：
操作结果和流程结果各说一层：`PlaceResult` 回答这一次操作写进状态面板没有，`Result` 回答整局流程进行到了哪一步。

改写（两个类型已在前文各配导语和围栏，分工不再复述，直接进入下一块）：
（整段删除。下一块改为一句桥接：这些类型由 `Game` 的四个数据成员使用，都声明在 `state.h` 的 `private:` 下。）
```

判定信号：一句里两组对象两两配对、删任一配对仍成立；「分别交给」「各说一层」「分别是」出现在同一句里连接两组对象。改写顺序：推迟（只留顺序白话，类型名下放）→ 拆句（后句用「因此 / 所以 / 接着」接前句对象）→ 一项一行（三项以上进列表）。`verifying-content.py` 对读者正文的「分别交给」「各说一层」硬拦。

## 分号与句长

```text
不佳：先执行 A；再执行 B；完成后检查 C，不通过时回到上一步。
改写：执行 A，再执行 B。完成后检查 C。不通过时回到上一步。
```

「两个并列主谓分句可用分号并列」的旧豁免已废除：凡是删掉任一分句中心仍成立的分号句，都按多中心句或拉链句改写（对照见「拉链句」与 `examples/04-paragraph-opening.md` 的「导语多中心与分号挂外链」）；指令链与「冒号后堆叠分号解释」仍按上文与对应案例改写（`verifying-content.py` 的分号检查不再豁免行内代码主语）。

## 长句与连接关系

连接词必须表达真实因果、时序、转折或条件。一个句子出现三个以上动作、多个「并且」或多个括号时拆分，并保留明确主语：

```text
不佳：完成 A 后通过 B 使用 C，并根据 D 判断 E，最后处理 F。
改写：完成 A。接着使用 B 执行 C。根据 D 检查结果，满足条件后处理 F。
```

需要一句话交代多个条件与同一结果的对应关系时保留长句，拆开反而让读者在短句间拼接。

## 破折号夹心句

正文用破折号夹住解释时，读者要在一句话里跳进跳出两次。正文停用破折号，解释用冒号引出或拆成两句，规则见 `steps/01-task.md`：

```text
不佳：src/main.cpp：被编译和运行的程序——输出一行稳定文本并返回 0；
改写：src/main.cpp：被编译和运行的程序，输出一行稳定文本并返回 0；

不佳：脚本每次都重新执行配置，而不是判断 build/ 已存在就跳过——配置是幂等的。
改写：脚本每次都重新执行配置，而不是判断 build/ 已存在就跳过。配置是幂等的。
```

## 结构助词「的」

两条判定见 `steps/05-sentences.md`「结构助词「的」」；正反对照只收这一组。两个名词粘合后仍是一个叫法时去掉「的」；术语表已定名的按定名走：

```text
不佳（「状态面板的格子的总数」两个「的」，内层先粘合成「数据项」）：
/// 状态面板的格子的总数。
改写：
/// 数据项总数。

不佳（定语和中心语都是名词，粘合后仍是一个叫法）：
/// 状态面板的行数。
改写：
/// 状态面板行数。

保留（术语表已定名的，类型概述跟术语走）：
/// 数据项坐标。

保留（定语是动词短语）：
已经写入的状态面板
```

「的的」字面仍由 verifying-content.py 拦截，不新增 `A的B的C` 这类正则。

## 定句子：两次说话拆成一次对话

条文见 `steps/05-sentences.md`「一次对话」。总述叠了几件内容：有没有写进状态面板、整局走到哪、它们是两个问题、用两个枚举分开答，下一句又改口「接着看」「第一个枚举」。改写发生在定句子：每件内容一次对话，紧挨自己的围栏。

**定句子（示例章两个枚举的总述）：**

```text
不佳（几件内容叠进一次说话，读者要拿开头的问题去猜「第一个」是哪个；「走向」又与开头的「进行到了哪一步」对不上）：
至于操作有没有写进状态面板、整局进行到了哪一步，是两个不同的问题，`Game` 用两个枚举分开回答。接着看操作可能写入状态面板、也可能被拒绝的处理结果，用第一个枚举 `PlaceResult` 表示：

第二个枚举回答流程整体的走向，用 `Result` 表示：

改写（每件内容一次对话，说法从开头保持到围栏，中间不编号）：
这次操作有没有写进状态面板，用 `PlaceResult` 表示：

整局进行到了哪一步，用 `Result` 表示：
```

序数指真实位置不在这条禁令内：示例章「第一个格子」说的是行列序，不是给并列过的两件事重新编号。

判定信号：一次说话里叠了几件内容，每件读者本应能单独复述；下一句用「接着看」「第 N 个枚举」给并列过的事重新编号；导语的说法到围栏前已经换了词。

## 假对比、起跑式铺垫与意义拔高

以一段常量位置说明改稿前为对照（规则见 `steps/05-sentences.md`「情况：假对比、起跑式铺垫与意义拔高」）：

```text
不佳（起跑式铺垫、假对比、句尾拔高各一处）：
在开始之前，我们先来看常量放在哪里。把长度写进头文件，这不仅是一次位置调整，更是对边界的重新划分。改完之后，数组长度在编译期就固定下来，看似只挪了一行，却为后面的扩展打下了基础。

改写（删铺垫与拔高，两层事实各写一句，不补依据）：
数组长度取常量 `kCellCount`，常量在头文件里给出值，编译期就确定长度。
```

判定信号：「在开始之前」「首先我们来看」后面接的不是新内容；「不仅是 X，更是 Y」的 Y 没有 X 之外的信息；句尾「看似……却……」「为……打下基础」把操作说成意义。改写只删不补：没有新增数字、命令或性能结论。
