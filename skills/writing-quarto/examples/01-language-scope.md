# 中文案例：工程旁白的语言边界

工程旁白的语言边界与零基础读写路径的正反对照。

对照三：类型形式决策复述（首章与 示例章导语）。

```text
不佳：取值封闭的集合用 enum class，数据组合用 struct 聚合，常量与枚举子以 k 开头，全部定义在 example 命名空间内。
```

对照四：命名教学（首章命名节）。

```text

```

## 零基础可懂的读写路径与层名定义

讲「谁改状态面板、谁读结果」时不用架构隐喻句（「经规则接口读写」「状态不反向依赖调用者」），按三步模板写：先说屏幕上或调用处发生什么，再点名类型与函数，最后一句边界。正例模板（示例章定稿）：

```text
正确（先动作 → 再点名成员 → 后边界）：
终端程序把「行 列」变成一次操作动作后，只能调用 Game 的三个成员去改状态面板或查结果，
不能直接改私有数组 cells_。测试也调用同一组成员。
Game::Place 负责写入数据项；Game::GetCellState 负责读某个数据项的状态；
Game::GetResult 负责报告流程结果。
```

```text
不佳（隐喻句，读者还原不出画面）：
状态面板状态经规则接口读写，状态不反向依赖调用者，动作只从外部进入。
改写（写成上模板的成员清单）：
终端程序与测试都只调用 Game 的三个成员读写状态；
Game 不调用终端程序，也不读键盘。
```

架构层名（终端适配层、规则核心、规则接口）可保留，但首次出现必须用一句可观察行为定义；Mermaid 图节点用日常说法（如「终端程序」「规则库里的 Game」），图后列表再对上术语：

```text
正确（层名首次出现给可观察定义）：
规则接口是 Game 暴露的三个成员函数，终端适配层负责把键盘输入翻译成 Move。
```

## 流程交流不绑定媒介与行为刚性表述

以 首章观察一次流程节改稿前为对照。把交流绑定到具体媒介、把行为写成刚性属性，都会在后续编号目录更换界面或引入协议时与前面冲突（禁用与替换见`steps/06-wording.md`）：

```text
不佳（媒介绝对化，「只发生在」把流程交流写死在终端）：
一次流程的交流只发生在终端上：用户输入行列，程序打印状态面板和结果。

改写（写交流的形态，不绑定媒介）：
一次流程通过文本交流完成：用户输入行列，程序打印状态面板和结果。
```

```text
不佳（「固定」落在程序行为上，读作硬编码）：
流程中的每一步回应和结束判定都是固定的：

改写（行为列举导语直接点名列表内容，与章 title 对齐）：
两名用户轮流在 3×3 状态面板上操作，每一次输入，程序都按下面四项行为回应：
```

```text
不佳（「固定」落在章叙述上，读作把约定硬加给读者）：
这一章只固定一次完整流程要做什么：用户怎么操作、输入不合法时怎么处理、流程什么时候结束。具体实现不在这一章展开。

改写（章确定约定用「确定」；收尾否定句删除，「只」已表边界）：
这一章只确定一次完整流程要做什么：用户怎么操作、输入不合法时怎么处理、流程什么时候结束。
```

判定信号：媒介名词（终端、协议、界面）出现在「只」「都」「总」等全称限定里修饰流程交流本身；或出现「固定」式表述——章叙述、程序行为与不变量一律停用「固定」，分别改写为「确定」、点名行为清单的列举导语与直陈事实（「编译期就是 9 格」「长度不变的 `std::array`」）。「只发生在」仍可用于局部实现事实（换算只发生在 `Board` 内部、写入只发生在 `Place`）。抽象指称的铺垫要求见 `wording-cases.md` 的「无铺垫的规则指称」。

## 元叙述开场与对象先行

正文句序是「对象 → 名称 → 约束 → 出处」，不用「是规则，代码把它写成」这类把源码当施事的元叙述开场（用户决定）：读者先要知道讲的是哪个对象，才轮到它叫什么、受什么约束、源码在哪。

```text
不佳（元叙述开场：「代码把它写成」把源码当施事，对象落在从句里）：
状态面板多大是示例项目的规则，代码把它写成常量 `kRows`、`kCols` 和 `kCellCount`，都定义在 state.h 里：

改写（对象先行：先点名状态面板尺寸，再给名称与出处）：
状态面板尺寸由 `kRows`、`kCols` 和 `kCellCount` 三个常量固定，都定义在 state.h 里：
```

```text
不佳（判据从属句开场，读者读到句尾才知道主语是数组）：
九个数据项一排编号，这是 `std::array` 的固定长度，代码用 `kCellCount` 写死：

改写（对象先行）：
九个数据项的状态放在一个 `std::array` 里，长度由 `kCellCount` 固定：
```

判定信号：句首是「是…的规则／约定／做法」类判断句，或出现「代码把它写成／因此记作／写成 `class`」等以源码为施事的元叙述；对象名词落在从句或句尾。
