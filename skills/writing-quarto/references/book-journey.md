# 整本书的写作次序

单章润色看一章；整书重构先看这本书要带读者完成什么，再决定章节次序。本文件只定整书层的判断，单章规则仍在 `steps/`。

## 先定一条主线

把目录写成一句可验收的话：读者从什么基础出发，按顺序做完哪些事，最后能独立交付什么。主线要落到一个可运行、可检查的产物；章节是这条主线上的阶段，不是互不相干的 API 清单。

写目录前先删掉三类章：同一对象拆成多章、只罗列类型而没有阶段结果、前后章可以任意交换。保留下来的章，每一章只回答一个关键问题，并在开头接住上一章的结果、结尾交出下一章需要的输入。

## 三遍走

1. **骨架遍**：先排章节次序与每章关键，确认读者按顺序能完成主线；此时不写句子，不补代码。
2. **章节遍**：每章按 `steps/01-task.md` 到 `steps/09-check.md` 走九步，只改这一章；章与章的接口在章首、章末对齐。
3. **全书遍**：从头回读，检查术语、项目名、图注、链接与前后承诺；只改跨章不一致，不在这一遍重写单章。

骨架遍改次序，章节遍改正文，全书遍改一致性；三遍不混做。

## 章的视角

先定这一章站在哪里看，再定标题与段落：

- **总览章**写整体形状：交代对象在全局里的位置、彼此关系与阅读路线，可以点名后章对象，但不展开它的数据与函数。
- **对象章**只写本章对象：数据成员、构造后的状态、公开接口与实现选择。后章才展开的类型名、个数标题、块后归属段不写；「留在某类型」「由某类得出」「不放进本章」这类归属句整句删除。
- 对象章内的互斥结果写成无序列表，每项「情形：结果」，列表后停止；标题点名这一节的实体，不数条目（`八条线` 拆成 `线坐标表`、`成线判断`）。
- 总览章与对象章的分界见项目章节表；本书 `01-rules.qmd`、`02-mapping-layout.qmd`、`viewing-program.qmd` 与两份 index 是总览，`03` 起各章是对象章。
- 整书遍同时统一陈述范围：部分页使用项目名与「这一部分」，不把单个样例抬成全书；只有书首页概括全书。页首导语不复述目录与章节卡片，卡片入口只写章节标题与一句交付结果。

## 以井字棋书为例

| 阶段 | 章节 | 交给下一章的结果 |
| --- | --- | --- |
| 规则 | 对局规则 | 一局怎样算结束 |
| 结构 | 工程结构、程序结构 | 文件与类的整体形状 |
| 数据 | 棋盘、对局 | 格子、坐标、落子后的状态 |
| 决策 | 电脑落子 | 电脑怎样选一格 |
| 交互 | 终端程序、程序入口 | 人怎样下一局 |
| 质量 | 调试、测试、构建与运行 | 改动后怎样确认没坏 |
| 收束 | 局面快照 | 一局怎样保存与还原 |

这张表只是示例。项目有自己的章节表时，以 `.agents/skills/quarto-book-project/writing/chapter-map.md` 为准；没有就按上面的阶段顺序推，不猜项目事实。

## 插件层怎么配合

- 整书规划先读本文件与项目章节表，再逐章加载 `steps/`；不要一次读完九步。
- 单章判不准时才开 `examples/`；排图、查渲染或全仓重构才开 `quarto/`。
- 全仓检查用 `scripts/`，渲染验收用 `quarto_render_check`；两件事都放在最后一遍，不在骨架遍执行。
- 文件体量受 `references/token-budget.md` 约束；新增整书规则只写进本文件，不复制到各步。
