# 规则卡

研究结论的压缩版。每张卡一行规则、一个正例、一个反例和所属步骤；写正文时按需打开一张，不要整份读完。
卡号写进步骤文件末尾，便于在技能内互相指认；来源不随包分发。

## 句子

**C01 段首给结论。** 第一句写这段要读者记住的事，背景放后面。
- 正：`棋盘用固定大小的二维数组保存，行和列都是 0 到 2。`
- 反：`在开始介绍棋盘之前，我们先来了解一下背景。`
- 步骤：`steps/04-paragraphs.md`

**C02 一段只推进一个动作。** 说明、举证、划界、收口四选一；出现第二个动作就分段。
- 正：一段说清 `PlaceCell` 的职责，下一段再说它拒绝哪些输入。
- 反：一段里既讲职责、又讲实现细节、又讲历史原因。
- 步骤：`steps/04-paragraphs.md`

**C03 句子有预算。** 中文单句不超过 40 字，英文不超过 25 词；超了先拆。
- 正：`落子前先检查坐标是否越界。越界时返回 false，不修改棋盘。`
- 反：`落子前先检查坐标是否越界并在越界时返回 false 且不修改棋盘以及不记录日志。`
- 步骤：`steps/05-sentences.md`

**C04 术语首次出现给中英。** 中文在前，英文括注一次，之后只用中文。
- 正：`棋盘格子（cell）只有三种状态。`
- 反：`cell 有三种状态，后面我们有时也叫它格子。`
- 步骤：`steps/06-wording.md`

**C05 删复述句。** 代码已经说明的，不要再写一遍。
- 正：`PlaceCell 被拒绝有两种原因：越界，或格子已被占用。`
- 反：`上面的代码中，if 判断 position.row 是否越界，如果越界就 return false。`
- 步骤：`steps/08-reread.md`

**C06 删元叙述。** 不写「本节将」「下面我们来看」「值得注意的是」。
- 正：`判断胜负要扫描四条线。`
- 反：`下面我们来看一下如何判断胜负。`
- 步骤：`steps/08-reread.md`

**C07 示例先于术语。** 先给能跑的最小例子，再解释机制。
- 正：先给 `Board b; b.PlaceCell({0,0}, CellType::kX);` 与输出，再讲存储布局。
- 反：先讲「采用行优先的连续存储」，再给例子。
- 步骤：`steps/03-blocks.md`

**C08 反例紧随正例。** 错误写法放在正例之后一段，不埋进注里。
- 正：正例后一段写「如果漏掉越界检查，会……」，附代码。
- 反：把反例塞进 `::: {.callout-note}` 的折叠块。
- 步骤：`steps/04-paragraphs.md`

## 结构

**C09 标题用名词短语。** 不用问句，不用「关于……」。
- 正：`胜负判定`
- 反：`我们如何判断胜负？`
- 步骤：`steps/02-structure.md`

**C10 章节按五步走。** 现象 → 最小例子 → 机制 → 边界 → 自测。
- 正：`03-board.qmd` 依次讲空棋盘、落子、越界、判胜、自测。
- 反：先给完整类声明，再逐行解释。
- 步骤：`steps/02-structure.md`

**C11 表格只放同构信息。** 叙述内容仍写自然段。
- 正：三种格子类型一行一个，列固定。
- 反：把一段因果解释塞进表格的「说明」列。
- 步骤：`steps/03-blocks.md`

**C12 一节一个关键。** 一章只解决一个问题，多出来的挪到下一章。
- 正：03 章只讲棋盘；游戏流程留给 04 章。
- 反：03 章顺手把 `Game` 的状态机也讲了。
- 步骤：`steps/02-structure.md`

**C13 章首导语 60–146 字。** 一段说清这章解决什么、读者读完能做什么。
- 正：`这一章把棋盘写成类……读完后你能判断任意坐标是否合法。`
- 反：三段历史回顾加一张架构图。
- 步骤：`steps/01-task.md`

## 代码块与图

**C14 代码块前一句导语，后一段解说。** 导语说这块代码要证明什么，解说只讲没写在代码里的。
- 正：`下面这段是判胜的核心循环：` + 代码 + `两层 any_of 在第一次命中时短路。`
- 反：导语写「代码如下」，解说把代码逐行翻译。
- 步骤：`steps/03-blocks.md`

**C15 围栏属性只写必要项。** 需要文件名才写 `filename`，需要行号才写 `start-from`。
- 正：` ```{.cpp filename="board.h"} `
- 反：每个代码块都堆 `filename`、`code-link`、`start-from`。
- 步骤：`steps/03-blocks.md`

**C16 图示有替代文本。** 图必须有 `alt` 或 `aria-label`，说明图在讲什么，不写「示意图」。
- 正：`aria-label="三行三列的棋盘，行列都从 0 编号"`
- 反：`alt="图 1"`
- 步骤：`steps/07-layout.md`

**C17 交叉引用写对象。** 引用图、表写 `@fig-...`、`@tbl-...`；引用别的章写章节标题链接；不写「见上文」「如下图所示」。
- 正：`判胜规则见 @fig-board-lines。`
- 反：`判胜规则见上面的图。`
- 步骤：`steps/07-layout.md`；标签语法见 `quarto/crossrefs.md`。

## 用词与排版

**C18 称呼读者用「你」。** 不写「我们」「大家」「读者」。
- 正：`你可以先用空棋盘试一次落子。`
- 反：`我们接下来让大家试着落子。`
- 步骤：`steps/06-wording.md`

**C19 中英混排加空格。** 中文与英文、数字之间留一个空格；全角标点只用于中文语境。
- 正：`C++23 的 std::array 固定长度。`
- 反：`C++23的std::array固定长度。`
- 步骤：`steps/07-layout.md`

**C20 数字与单位写全。** 行列编号写「第 0 行」，范围写「0 到 2」，不写「0~2」。
- 正：`行和列的取值都是 0 到 2。`
- 反：`行列取值 0~2。`
- 步骤：`steps/07-layout.md`

**C21 链接文字要自述。** 链接文字说明目标是什么，不写「这里」「点击」。
- 正：`参见 [Google C++ 风格指南](https://google.github.io/styleguide/cppguide.html)。`
- 反：`参见[这里](https://google.github.io/styleguide/cppguide.html)。`
- 步骤：`steps/09-check.md`

**C22 列表只列同构项。** 列表项长度相近；出现完整句子就改自然段。
- 正：三条各一行的「越界、占用、终局」检查项。
- 反：列表第一项一句话，第二项三行解释。
- 步骤：`steps/07-layout.md`

## 节奏与收尾

**C23 长文分小节。** 一节 60–90 行，超过就拆；拆出来的小节标题写名词短语。
- 正：`棋盘存储`、`落子`、`判胜` 三个小节。
- 反：一个 300 行的「实现」小节。
- 步骤：`steps/02-structure.md`

**C24 排障写成可跟做步骤。** 失败现象、检查项、修法各一行，命令可直接复制。
- 正：`报错 EADDRINUSE：先运行 lsof -i :3000，再结束占用进程。`
- 反：`如果端口被占用，可能需要检查一下相关进程。`
- 步骤：`steps/09-check.md`

**C25 每章末尾给三句回顾。** 只回顾结论，不引入新概念。
- 正：`棋盘用二维数组保存；落子前检查越界与占用；判胜扫描四条线。`
- 反：回顾里补一个前面没讲过的 `std::optional` 用法。
- 步骤：`steps/08-reread.md`

**C26 自测问题不引入新概念。** 问题只用本章讲过的内容，答案放折叠块。
- 正：`如果省略越界检查，传入 {-1, 0} 会发生什么？`
- 反：`请用 std::variant 重写棋盘。`
- 步骤：`steps/08-reread.md`

**C27 术语表只收本书自造词。** 通用 C++ 术语不收；收「棋盘格子」「落子」这类本书固定叫法。
- 正：`棋盘格子：棋盘上的一个位置，取值见 CellType。`
- 反：把 `std::array` 也收进术语表。
- 步骤：`steps/06-wording.md`

**C28 代码注释不复述正文。** 正文讲契约，注释讲代码里看不出的取舍；同一句不写两遍。
- 正：注释写「不用编号求和，和相等不代表同色」，正文讲判胜算法。
- 反：注释把正文的判胜步骤抄一遍。
- 步骤：`steps/03-blocks.md`

**C29 渲染后朗读一遍。** 出声读，卡住的地方就是句子太长或指代不清。
- 正：读不顺的句子拆成两句。
- 反：只看渲染截图就交付。
- 步骤：`steps/09-check.md`

**C30 改完就校验。** 每改完一节跑一次 `verifying-content.py`，不攒到最后。
- 正：`python scripts/verifying-content.py --root . --strict`
- 反：整章改完再跑，报错定位到整章。
- 步骤：`steps/09-check.md`
